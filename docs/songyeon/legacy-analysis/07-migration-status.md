## 6. 보고용 요약

> 기존 Python 기반 송연 MES를 다시 분석해 API 290개, DB 테이블 60개, 화면 43개와 업무 규칙을 문서로 정리했습니다. 참조 프로젝트 s-erp-main의 구조를 확인한 결과, 화면 폴더 구조와 백엔드 계층·명명 규칙은 따르되 s-erp가 구버전 스택(Spring Boot 2.7)이어서 코드를 그대로 가져오지는 않고, 인증은 현재의 세션 방식을 유지하는 것이 적합하다고 판단했습니다.
>
> 현재 React로 로그인·대시보드와 영업 6개 화면(제품등록·단가관리·견적·수주등록·출하등록·생산가능확인)을 기존과 같은 모양으로 옮겼고, Spring Boot에 인증과 이 6개 화면의 서버 기능(Controller·Service·DAO·DTO·MyBatis XML)을 만들었습니다. 테스트 50개(서버 26, 브라우저 24)를 통과했습니다. PostgreSQL `songyeon` DB의 금액·수량 컬럼을 기존과 같은 정밀도로 바꾸고 이 PC의 기존 자료를 옮겼으며, 서버 SQL이 모두 도는 것을 확인했습니다. 화면과는 아직 연결하지 않았습니다. 다음 단계는 운영 자료를 옮기고 로그인 계정도 PostgreSQL에서 읽게 한 뒤 화면과 서버를 잇는 것입니다.
