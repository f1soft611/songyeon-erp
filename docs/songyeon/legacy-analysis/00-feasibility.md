# 00. 전환 가능성 검토 — 기존 구조를 Spring Boot·React로 옮길 수 있는가

작성일: 2026-09-18 · 현재 단계: **전환 가능 여부 확인**

## 1. 결론

**전환 가능하다. 전환을 막는 기술 요소는 발견되지 않았다.**

- 기존 시스템의 서버 쪽은 Flask 고유 기능에 거의 의존하지 않는다. 대부분 "HTTP 요청 → SQL 실행 → JSON 응답"과 순수 계산 함수라 Java로 1:1 옮길 수 있다.
- 로그인(기존 비밀번호 해시 호환, 기존 DB 읽기, 세션)은 **실제로 옮겨서 동작을 확인했다**.
- 화면은 "옮긴다"기보다 **React로 다시 만드는 작업**이다. 기존 JS가 DOM을 직접 조작하는 방식이라 코드를 재사용할 수는 없지만, 화면 구성과 동작은 모두 React로 재현할 수 있다. 레이아웃·메뉴·권한 필터·제품등록 입력 화면은 이미 재현했다.
- 비용이 큰 부분은 기술적 불가능이 아니라 **분량**이다. 라벨 양식 편집기·인쇄물·재고·출하 트랜잭션이 여기에 해당한다.
- 실물 장비(프린터, 온도 센서)와 운영 비밀키(Fernet)가 필요한 부분은 아직 확인하지 못했다(5장).

## 2. 실제로 옮겨서 확인한 것 (2026-09-17, PoC)

| 확인 항목 | 방법 | 결과 |
|---|---|---|
| 기존 비밀번호 해시(Werkzeug scrypt·pbkdf2)를 Java에서 검증 | Python으로 만든 해시 벡터(영문·한글)를 Java에서 검증 | ✅ 통과. 기존 계정을 비밀번호 재설정 없이 그대로 쓸 수 있음 |
| 기존 SQLite DB를 Java에서 읽기 | sqlite-jdbc, 읽기 전용 연결 | ✅ `employees` 조회, 원본 파일 변경 없음 확인 |
| 로그인·세션·로그아웃 | Spring Security 세션 + CSRF | ✅ JUnit 12개, 브라우저 테스트로 실제 로그인 확인 |
| 기존 권한 키로 메뉴 표시 | 레거시 권한 키·별칭 규칙을 React로 옮김 | ✅ 관리자·일반 계정 메뉴 차이 테스트 |
| 기존 화면 틀(사이드바·분류 11개·탭·달력·야간모드) | React로 재작성 | ✅ 기존 화면과 배치 비교 |
| 업무 화면 1개(제품등록 입력·BOM 행 편집) | React로 재작성 | ✅ 화면 동작 확인. 저장·계산은 미연결 |
| 참조 프로젝트(s-erp-main) 구조 적용 | 프런트 폴더 규칙을 s-erp에 맞춤 | ✅ 빌드·테스트 통과 |

## 3. 영역별 판정

판정: **가능** = 표준 방법으로 바로 대응 · **가능(주의)** = 대응 방법은 있으나 규칙을 정확히 맞춰야 함 · **가능(실물 확인)** = 장비·키로 확인 필요

### 서버

| 영역 | 기존 | Spring 대응 | 판정 | 근거·주의 |
|---|---|---|---|---|
| API 290개 | Flask 라우트 | Spring MVC Controller | 가능 | 경로·메서드·JSON 구조를 그대로 옮길 수 있음 ([목록](reference/api-inventory.md)) |
| 업무 로직 | Python 함수(단가·BOM·재고·연차 등) | Java 서비스 | 가능 | 외부 라이브러리에 의존하지 않는 계산 로직이라 1:1 이식 가능 ([03 문서](03-business-rules.md)) |
| DB 접근 | 직접 SQL(sqlite3) | MyBatis + PostgreSQL | 가능 | SQL 구조는 그대로 옮기고 SQLite 전용 문법만 바꾼다 |
| SQLite 전용 문법 | `rowid` 28, `last_insert_rowid` 13, `INSERT OR IGNORE/REPLACE` 11, `date()` 19, `GROUP_CONCAT` 4, `PRAGMA` 52(대부분 schema.py) 등 | PostgreSQL 문법 `RETURNING`, `ON CONFLICT`, `string_agg`, `to_char` 등으로 교체 | 가능 | **PostgreSQL 전환 확정**이라 SQL을 옮길 때 함께 바꾼다. 모두 대응 문법이 있음 |
| 트랜잭션 | 커밋 없이 닫아서 롤백 | `@Transactional` + 예외 | 가능(주의) | Spring은 오류 응답을 return하면 커밋되므로 **예외로 처리**해야 같은 동작 |
| 인증 | Werkzeug 해시, 서명 쿠키 | Spring Security | **확인 완료** | 해시 호환 검증됨. Flask 세션 쿠키 자체는 호환 안 됨 → 전환 시 재로그인(문제 없음) |
| 권한 | 경로별 권한표(`permissions.py`) | Spring Security + 서비스 검사 | 가능 | 표를 그대로 옮기면 됨 ([02 문서](02-legacy-architecture.md#4-권한-모델)) |
| 외부 API 키 암호화 | Fernet(cryptography) | Java로 복호화(AES-128-CBC + HMAC-SHA256 표준 형식, 라이브러리 존재) | 가능(실물 확인) | **운영 `secret.key`가 있어야** 기존 API 키·주민번호를 옮길 수 있음 |
| 금액 반올림 | Python `round`(짝수 쪽 반올림) | `BigDecimal` + `HALF_EVEN` | 가능(주의) | 방식을 명시하지 않으면 1원 차이 발생 가능 |
| 수량 문자열(`100kg`) | 정규식으로 첫 숫자 추출 | 같은 규칙 이식 | 가능 | |
| 서버 엑셀 | openpyxl | Apache POI | 가능 | 거래처·레시피·재고 엑셀 |
| 파일 업로드·다운로드 | 로컬 폴더(`uploads`, `chat_files`) | multipart + 파일 저장 | 가능 | 파일 폴더도 함께 이관해야 함 |
| 예약 단가 반영 | 요청마다 실행 | `@Scheduled` | 가능 | 오히려 구조가 나아짐 |
| 기동 시 스키마 보정 | schema.py가 매번 실행 | Flyway 마이그레이션 | 가능 | |
| 외부 연동 | Anthropic·Gemini·RadioNode HTTP 호출 | Java HttpClient | 가능(실물 확인) | 키·장비로 확인 필요 |
| 세금계산서 | **기존에도 미구현(501)** | — | 해당 없음 | 전환 대상이 아니라 신규 개발 |

### 화면

|---|---|---|---|---|

| 항목 | 판정 | 근거 |
|---|---|---|
| 프런트 폴더·이름 규칙 | 적용 완료 | |
| 백엔드 계층·이름 규칙, 응답 형식, MyBatis | 가능 | 구조만 적용. s-erp는 Spring Boot 2.7 / Java 8 문법이라 **코드 복사는 불가** ([09 문서](09-s-erp-reference.md)) |

## 4. 비용이 큰 부분 (불가능이 아니라 분량)

| 순위 | 대상 | 이유 |
|---:|---|---|
| 1 | 라벨(등록·양식 편집기·출력) | 약 2,400줄, mm 인쇄, 버전 관리, 격자 편집기 |
| 2 | 생산·출하·재고 트랜잭션 | 원재료 차감·자동 입고·로트 배분·원장이 한 번에 맞물림. 기존 결함을 그대로 옮길지 결정 필요 |
| 3 | 기초정보(탭 10개), 입고, 재고조정, 수불대장 | 편집 표·엑셀 업로드·계산이 많음 |
| 4 | 인쇄물 6종 | 기존 출력물과 똑같이 맞추는 작업 |
| 5 | 데이터 이관 | 이름 문자열로 연결된 자료 정리, 수량 문자열 변환, 파일 폴더, 암호화 자료 |

## 5. 아직 확인하지 않은 것

| 항목 | 확인하려면 |
|---|---|
| 운영 DB·운영 계정으로 로그인 | 테스트는 임시 DB로 함. 운영 DB 사본으로 1회 확인 |
| Fernet 암호문(API 키·주민번호) Java 복호화 | 운영 `secret.key`로 사본 1건 복호화 |
| 인쇄물·라벨 출력 | 실제 프린터·라벨 용지 |
| 온도 센서, AI | 실제 키·장비 |
| 대량 데이터 성능 | 운영 규모 사본으로 수불대장·매출 집계 조회 |
| 기존 테스트 49개 기대값 | 업무 기능을 옮길 때 Java 테스트로 재현 |

## 6. 가능성 확인을 마무리하려면 (추가 PoC 제안)

지금까지의 PoC는 로그인·화면 틀까지다. **업무 로직 쪽**을 작은 단위로 한 번씩 실제로 옮겨 보면 검토가 끝난다. 각각 독립적으로 할 수 있다.

| # | PoC | 확인되는 것 | 규모 |
|---|---|---|---|
| 1 | 제품+BOM 조회·등록 API + 제품등록 화면 연결 | SQL·계산(BOM 비율, 원가) 이식, 응답 형식, s-erp 백엔드 계층 적용 | 작음~중간 |
| 2 | 출하확정 1건(재고 원장·로트·박스 차감) | 여러 테이블을 묶는 트랜잭션 이식, 기존 결과와 대조 | 중간 |
| 3 | 거래명세표 또는 라벨 1종 인쇄 | mm 인쇄를 React에서 재현, 실제 프린터 출력 | 작음 |
| 4 | Fernet 복호화 | 암호화 자료 이관 가능 여부 | 작음 |

이 네 가지가 통과하면 나머지는 같은 방식의 반복이라 "가능 여부"보다 "일정" 문제가 된다. 전환을 진행하기로 하면 [05. 목표 구조](05-target-architecture.md)와 [07. 로드맵](07-migration-status.md)을 기준으로 삼는다.
