# F1-Grid 도입 검토

> **요약** — s-erp 공용 그리드(F1-Grid)를 조회 화면 2개(생산현황·원재료BOM)와 **편집 화면 1개(수주등록)** 에 시범 적용했다.
> **저장·수정·삭제는 모두 정상 동작한다.** 다만 편집 화면은 표가 목록을 **따로 들고 있는 구조**와 **브라우저 기본 자동완성** 때문에 화면마다 손이 더 간다.
> **편집이 많은 화면에는 이점이 크고, 단순 조회 화면에는 이점이 작다.**

## 1. 시범 적용 결과

| 항목 | 결과 |
|---|---|
| 적용 화면 | 생산현황(PD0003) · 원재료BOM(CM0001 8번 탭) · **수주등록(SA0004 — 편집 화면)** |
| F1-Grid 소스 | **S_ERP(`D:\workspace\S_ERP`) 판 41개 파일 복사, 원본은 고치지 않음** (2026-09-29 판올림 — 처음 복사한 s-erp-main 판은 12개 파일이 더 오래된 것이었다) |
| 추가 라이브러리 | MUI, emotion, dayjs, exceljs (s-erp 와 같은 버전) |
| 표시 | 밝은 화면 · 야간모드 정상. 글자 13px · 행 32px · 머리글 38px · 줄무늬·머리글·테두리 색까지 s-erp 와 같은 값으로 확인(2026-09-29 양쪽 앱을 띄워 실측) |
| 줄 색 | 기존 화면의 줄 색 중 **저장 전 빨강만** 남겼다. 저장된 줄의 파란 바탕은 표에서 고른 줄처럼 보여서 뺐다 |
| 글꼴·크기 | S_ERP 화면을 실제로 띄워 재서 맞췄다(2026-09-29): 글자 13px · 굵기 700 · 행 32px · 머리글 38px · **한글 Noto Sans KR · 영문 Segoe UI**. MUI 테마에만 글꼴을 적으면 F1-Grid 는 바깥 CSS 를 물려받아 적용되지 않아, `[role="grid"]` 규칙으로 표 안에만 준다(다른 화면 글꼴은 그대로) |
| 글꼴 지정을 베끼지 않은 이유 | s-erp 테마는 `Pretendard, "Segoe UI", sans-serif` 인데 Pretendard 는 설치돼 있지 않고, 마지막 `sans-serif` 가 **페이지 언어에 따라 다르게 대체된다**(s-erp `lang="en"` → Noto Sans KR, 송연 `lang="ko"` → 맑은 고딕). 선언을 그대로 베끼면 오히려 글꼴이 달라져서(실측 확인) 실제로 그려지는 글꼴 이름을 적었다 |
| 한글 웹폰트 | PC 마다 달라지지 않도록 Noto Sans KR 을 프로젝트에 넣었다(`frontend/public/fonts/noto-sans-kr`, 124개 조각 3.4MB, SIL OFL). 글자 범위별로 잘려 있어 **화면에 쓰는 조각만**(보통 10~50KB) 내려받고, 인터넷 없이도 뜬다. 표 안에서만 쓰고 다른 화면 글꼴은 그대로 |
| 머리글 높이 | S_ERP 는 선택 체크박스 칸 때문에 머리글이 38px 가 된다. 송연은 체크박스를 쓰지 않아 28px 였는데, 높이만 CSS 로 38px 에 맞췄다(칸은 늘리지 않음) |
| 새로 생긴 기능 | 열 너비 조절, 열 순서·고정·숨기기, 정렬·필터, 키보드 이동, 셀 복사, **줄무늬 행**(`stripeRows`, 기본 켜짐) |
| 자동 테스트 | 화면 테스트 85건 통과(표 선택자를 `table`→`grid` 로 고침) |
| 사용 설명서 | [reference/F1-GRID.md](reference/F1-GRID.md) (s-erp 원본 그대로 복사) |

## 2. 편집 화면(수주등록) 시범 — 2026-09-23

**확인한 동작** — 모두 기존과 같게 동작한다.

| 동작 | 결과 |
|---|:-:|
| 줄 추가 → 칸 입력 → **저장**(번호 받고 잠김) | ✅ |
| **수정**(잠금 풀고 고쳐 다시 저장, PUT) | ✅ |
| **삭제**(저장 전은 바로, 저장된 줄은 확인 후 서버에서) | ✅ |
| 재고생산 체크 → 물류출고일 비우고 잠금 | ✅ |
| 저장된 줄 잠금 · 가져간 줄 '… 가져감 — 수정불가' | ✅ |
| 합계(수주품목수량·총수주량), 엑셀 다운로드 | ✅ |
| 서버 거절 문구 → 고칠 칸(거래처·물류출고일)으로 이동 | ✅ |

**기존과 달라진 조작** — 화면 담당자·현장에 설명이 필요한 부분이다.

| | 기존 화면 | F1-Grid |
|---|---|---|
| 입력 | 칸이 늘 입력칸 | 칸을 **두 번 누르거나 Enter** 로 열어 고친다 |
| 거래처·품목 후보 | 자체 자동완성(부분검색, 그 거래처 품목을 '이 거래처' 로 위에) | **브라우저 기본 목록(datalist)**, 품목은 전체 목록 |
| 없는 거래처 | 칸을 떠날 때 비우고 알림 | **저장할 때** 같은 문구로 알리고 그 칸으로 보냄 |
| 줄 색 | 줄(tr)에 CSS 클래스 | 칸마다 배경색을 지정 |

## 3. 문제점

중요도: 🔴 전체 적용 전에 반드시 해결 · 🟡 결정 필요 · 🟢 알고 넘어가면 됨

| | 문제 | 내용 | 대응 |
|:-:|---|---|---|
| 🔴 | **행 키(id) 필수** | 행마다 고유 번호가 없으면 오류가 나고 **앱 화면 전체가 빈 화면**이 된다(시범 중 실제 발생) | 화면마다 서버 응답에 id 추가, 화면에서도 없으면 순번으로 대체 |
| 🔴 | **표가 목록을 따로 들고 있음** | 고친 값은 표 안에만 있어서 ① 저장할 때 표에서 값을 되받아 와야 하고 ② 줄 잠금·추가·삭제는 **표를 다시 그려야** 반영된다. 다시 그리면 정렬·필터·스크롤 위치가 풀린다 | 화면마다 '다시 그리기 번호'를 두는 방식으로 처리(수주등록에 적용) |
| 🟡 | **자동완성이 브라우저 기본 목록** | F1-Grid 의 자동완성은 `datalist` 다. 기존 화면은 **후보가 1,000개를 넘으면 느려서** 자체 자동완성을 만들어 썼고, 줄마다 다른 후보('이 거래처' 우선)도 datalist 로는 못 준다. 편집기를 바꿔 끼우는 훅(`createEditor`)은 타입에만 있고 동작하지 않아, 원본을 고치지 않으면 교체할 수 없다 | **결정(2026-09-23): 기본 목록을 그대로 쓴다.** 후보가 많은 화면에서 느려지면 그때 다시 본다 |
| 🔴 | **기존 표 동작 재구현** | 로트 펼치기, 배차별 묶음 줄, 줄 안의 입력칸·버튼을 F1-Grid 로 그대로 옮길 수 없다 | 화면마다 방법 설계(펼치기는 트리 방식으로 대체 가능) |
| 🟡 | 빈 표 문구 고정 | 결과가 없으면 항상 '데이터가 없습니다'. 화면별 기존 문구를 못 쓴다 | 통일 / 화면에서 덮어쓰기 / s-erp 팀에 옵션 요청 |
| 🟡 | 줄 단위 표시가 없음 | 줄에 클래스를 달 수 없어 줄 색·강조는 칸마다 지정해야 한다 | 화면에서 칸 스타일 함수로 처리(수주등록에 적용) |
| 🟡 | 편집 기능이 기본으로 켜짐 | 체크박스, 오른쪽 클릭 행 추가·삭제 메뉴가 기본값. 조회 화면마다 꺼야 한다 | 조회용 공통 설정 묶음(래퍼) 만들기 |
| 🟡 | 설정을 빠뜨리면 화면 깨짐 | 표 높이·칸 최소 폭을 제대로 주지 않으면 줄이 덜 그려지거나 좁은 화면에서 칸이 사라진다(4장) | 래퍼에 기본값으로 넣기 |
| 🟡 | 엑셀 라이브러리 2개 | 기존 SheetJS + F1-Grid 용 exceljs(930KB, 보안 경고 보통 수준) | 하나로 통일(기존 파일 모양 유지하려면 SheetJS) |
| 🟡 | 원본 따로 관리 | 복사본이라 원본 수정이 자동으로 안 들어온다. 실제로 s-erp-main 판과 S_ERP 판이 달라 화면 모양이 어긋났다(2026-09-29 S_ERP 판으로 맞춤) | 기준을 S_ERP 로 두고 주기적으로 다시 복사, 장기적으로 공용 패키지화 |
| 🟡 | 사내 코드 사용 확인 | s-erp 코드를 송연 프로젝트(고객사 납품)에 써도 되는지 | 사용 범위 확인 |
| 🟢 | 오른쪽 고정 칸이 옆 칸을 가림 | 칸 너비 합이 화면보다 넓으면 오른쪽 고정(작업 단추) 칸 밑으로 옆 칸 글자가 들어간다 | 칸 너비를 줄여 맞춤 |
| 🟢 | 화면 파일 크기 2배 | 560KB → 1,163KB(압축 149KB → 337KB), 대부분 MUI | 필요하면 화면별 나눠 불러오기 |
| 🟢 | 자동 테스트 수정 | 표 구조가 바뀌어 화면마다 테스트를 고쳐야 한다 | 전환할 때 함께 수정 |

## 4. 화면 깨짐 점검 (생산현황·수주등록으로 확인)

| 상황 | 결과 | 원인 · 대응 |
|---|:-:|---|
| 조회 직후 줄 표시 | ❌ → ✅ | 500줄을 조회해도 **8줄만 그려지고 아래가 빈 채로 남았다**(스크롤해야 나타남). 표 높이를 '최소·최대'로 주면 빈 표일 때 잰 높이로 계속 그린다. → 높이를 **고정값**(`height`)으로 주면 해결 |
| 좁은 화면(폭 390px) | ❌ → ✅ | **거래처 칸이 사라지고 머리글이 한 글자씩 세로로 쪼개졌다.** 늘어나는 칸의 최소 폭이 0 이라서. → 늘어나는 칸마다 최소 폭(`width`) 지정, 좁으면 표 안에서 가로 스크롤 |
| 오른쪽 고정 칸(작업 단추) | ❌ → ✅ | 칸 너비 합이 화면보다 넓어 **'물류출고일' 머리글이 단추 칸 밑으로 잘렸다.** → 칸 너비를 줄여 맞춤 |
| 긴 글자 | ⚠️ | 칸을 넘는 글자는 '…' 로 잘린다(기존 표는 전체가 보였다). 열 너비를 늘려야 다 보인다 |
| 줄 500개 스크롤 | ✅ | 머리글 고정, 보이는 줄만 그려 부드럽다 |
| 머리글 메뉴 · 오른쪽 클릭 메뉴 | ✅ | 정상 표시(행 추가·삭제 메뉴는 끈 상태) |
| 야간모드 · 탭 이동 후 창 크기 변경 | ✅ | 표·메뉴 모두 어둡게 바뀌고, 돌아와도 열 폭이 맞다 |

**화면마다 지켜야 할 설정**(빠뜨리면 위 ❌ 가 다시 생긴다): 표 높이는 고정값, 늘어나는 칸에는 최소 폭, 행 키(id) 필수, 칸 너비 합은 화면 폭 안에. → 공통 설정 묶음(래퍼)에 넣어 두면 화면마다 신경 쓰지 않아도 된다.

## 5. 판단

| 화면 종류 | 이점 | 권장 |
|---|---|---|
| 편집 화면(수주등록·생산확정·출하확정, 앞으로 발주·입고·재고조정) | 여러 줄 편집·일괄 저장, 키보드·셀 복사, 대량 자료 | **적용** — 단, 자동완성 후보가 많은 화면은 속도를 먼저 확인 |
| 조회 화면(생산현황·출하현황 등) | 열 너비·정렬·필터 정도 | 선택 |
