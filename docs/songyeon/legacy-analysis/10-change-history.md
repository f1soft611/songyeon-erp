# 송연 MES 전환 작업 내역

- 대상: 기존 송연 MES(Python Flask + SQLite)를 React + Spring Boot + PostgreSQL 로 전환
- 기간: 2026-09-17 ~ 2026-09-29
- 원칙: 기존 화면의 문구·배치·동작을 그대로 옮기고, 기존과 다르게 만든 부분은 따로 기록한다
- 화면코드: SA 영업관리 · CM 공통관리 · PD 생산관리 · LG 물류관리 (예: SA0001 = 영업관리 > 제품등록)

## 1. 진행 현황 요약

| 업무 | 전환 완료 화면 | 비고 |

| 영업관리(SA) | 제품등록, 단가관리, 견적, 수주등록, 출하등록, 생산가능확인 (6/6) | 서버 연결 완료 |
| 공통관리(CM) | 기초정보(10개 탭), 생산스케줄, 물류스케줄 (3/3) | 현장 TV 화면 2종 포함 |

### 2026-09-23 — F1-Grid 점검과 확대

| 구분 | 작업 내용 |
|---|---|
| 화면 깨짐 점검 | 7가지 상황(좁은 화면·긴 글자·500줄·탭 이동·메뉴·야간모드 등)을 확인해 두 가지를 바로잡았다. ① 조회 직후 줄이 일부만 그려지던 문제 ② 좁은 화면에서 칸이 사라지던 문제 |
| 원재료BOM 탭 적용 | 기초정보 > 원재료BOM 표를 F1-Grid 로 교체. 칸 이름·표시 규칙·줄마다 버튼 4개는 그대로, 버튼 칸은 오른쪽 고정 |
| 설정 정리 | 조회 화면에서는 체크박스·행 추가/삭제 메뉴·줄 높이 조절을 끄고, 칸 사이 세로선을 켜 기존 표와 같게 맞춤 |
| 수주등록 적용 | 편집 화면에서도 되는지 보려고 수주등록 표를 F1-Grid 로 교체. 줄마다 저장·수정·삭제(기존 방식)를 그대로 두고 확인했고 모두 정상 동작한다 |
| 문서 | F1-Grid 사용 설명서를 s-erp 에서 그대로 복사해 `docs/reference/F1-GRID.md` 로 보관 |

**F1-Grid 관련 결정**: 복사해 온 F1-Grid 원본은 고치지 않는다. 그래서 빈 표 문구는 F1-Grid 기본 문구("데이터가 없습니다")를 쓰고(화면마다 다르던 기존 문구는 표시되지 않는다), 수주등록의 거래처·품목 자동완성도 F1-Grid 기본 방식(브라우저 기본 목록)을 그대로 쓴다.

### 2026-09-29 — 실행 방법 정리

| 구분 | 작업 내용 |
|---|---|
| 실행 명령 | 백엔드는 `backend` 에서 `mvn spring-boot:run`, 프런트는 `frontend` 에서 `npm run dev` 로 실행하도록 정리했다(기존 `run.cmd` 도 그대로 쓸 수 있다) |

| 탭 아이콘 | 브라우저 탭에 기본 지구본이 나오던 것을 기존 화면과 같은 아이콘(`static/icon-192.png`)으로 맞춤 |
| F1-Grid 판올림 | 복사해 둔 F1-Grid 가 S_ERP 화면의 것보다 오래된 판이라 모양이 달랐다(줄무늬 행 없음 등). S_ERP 판 41개 파일과 사용 설명서를 다시 복사했다 — 타입검사·화면 테스트 85건 통과 |
| 그리드 모양 맞춤 | 같은 F1-Grid 인데 달라 보이던 글꼴과 머리글 높이를 S_ERP 화면을 직접 띄워 재서 맞췄다(한글 Noto Sans KR, 머리글 38px). 표 안에만 적용하고 다른 화면은 그대로 |
| 한글 웹폰트 | 표 글꼴이 PC 마다 달라지지 않도록 Noto Sans KR 을 프로젝트에 포함(3.4MB, 무료 공개 글꼴). 인터넷 없이도 같은 글꼴로 보인다 |
| 수주등록 줄 색 | 저장된 줄에 깔리던 파란 바탕을 뺐다(표에서 고른 줄처럼 보인다는 지적). 저장 전 줄의 빨간 표시는 그대로 두고, 저장 여부는 줄 끝 단추(저장 / 수정·삭제)로 구분한다 |
| 수주등록 순번 칸 | 거래처 앞에 순번(줄 번호) 칸을 넣었다(s-erp 화면과 같은 구성). 기존 파이썬 화면에는 없던 칸이다 |
| 수주등록 필수 표시 | 거래처 머리글에 빨간 `*` 를 붙였다(s-erp 화면과 같은 표시). 서버가 반드시 요구하는 칸이라서 — 물류출고일은 '재고생산' 에 체크하면 없어도 되는 조건부라 붙이지 않았다 |
| 표 글자색 | 표 안 글자색을 s-erp 테마 값(`#0f172a`, 야간모드 `#e2e8f0`)으로 맞췄다 — 송연 본문 글자색과 미세하게 달랐다 |
| 문서 | 실행 안내(08) 와 두 README 의 실행 명령을 같은 방식으로 맞춤 |

## 4. 기존과 다르게 만든 부분

| 화면 | 내용 | 이유 |
|---|---|---|
| 출하확정 | 실출하량 저장과 확정을 한 번에 처리 | 기존에는 확정이 실패해도 실출하량만 저장되고 실패 사실이 화면에 표시되지 않았음 |
| 라벨출력 | 생산수량 표시 방식 수정 | 기존에는 `1,000kg` 이 `1` 로 잘못 표시되었음 |
| 엑셀 | 엑셀 처리 부품을 최신 판으로 교체 | 기존 판에 알려진 보안 문제가 있었음 |
| 생산현황 · 원재료BOM · 수주등록 | 표를 F1-Grid 로 교체(열 너비 조절·정렬·필터 추가, 표 모양은 s-erp 방식) | F1-Grid 도입 검토를 위한 시범 적용 |
| 위 세 화면 | 결과가 없을 때 문구가 "데이터가 없습니다" 로 바뀜 | F1-Grid 원본을 고치지 않기로 함 |
| 수주등록 | 칸을 두 번 누르거나 Enter 를 눌러야 고칠 수 있다(기존은 칸이 늘 입력칸) | F1-Grid 의 편집 방식 |
| 수주등록 | 거래처·품목 후보가 브라우저 기본 목록으로 바뀌고, 품목은 전체 목록이 나온다(기존은 고른 거래처 품목을 '이 거래처' 로 위에) | F1-Grid 의 자동완성이 브라우저 기본 목록(datalist)이라서 |
| 수주등록 | 거래처BOM 에 없는 거래처는 칸을 떠날 때가 아니라 **저장할 때** 같은 문구로 알린다 | 표 안에서는 칸을 떠나는 시점이 없어서 |

## 5. 결정 필요 사항

| 항목 | 내용 |
|---|---|
| 원재료BOM 목록 정렬 | 현재 코드순으로 변경되어 있고, 기존은 이름순이다. 어느 쪽으로 할지 결정이 필요하다(현재 서버 테스트 1건이 이 차이로 실패) |
| 출하확정 권한 | 기존에는 출하확정 권한만으로는 확정 기능 일부가 막혀 있었다. 새 화면은 출하확정 권한으로 모두 쓸 수 있게 했다. 기존과 같게 제한할지 결정이 필요하다 |
| 운영 자료 이관 | 운영 PC의 실제 자료를 옮기기 전에 테스트 거래처와 테스트 자료를 정리해야 한다 |
| F1-Grid 적용 범위 | 지금은 생산현황·원재료BOM·수주등록 세 화면만 적용했다. 편집 화면 시범(수주등록)까지 마쳤으니 나머지로 넓힐지 결정이 필요하다([12-f1-grid-review.md](12-f1-grid-review.md)) |
