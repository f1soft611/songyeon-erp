# 20261102_001 판매관리 중분류 결과

- 계획 · 사양: `docs/plan/20261102/20261102_001_판매관리_중분류_계획사양서.md`
- DB 변경 이력: `docs/database/20261102/20261102_001_sl_module_categories_change_schema.md`

## 결과

- 판매관리 아래에 판매처리(판매등록) · 판매조회(판매현황 · 토탈집계) 중분류를 두는 스크립트를 만들었다.
- 프론트 폴더 · 화면ID 비교 · 백엔드 패키지 · 매퍼 · API 주소 · 테스트를 메뉴 구조에 맞췄다.
- 업무 로직, 응답 모양, 그리드 `storageKey` 는 바꾸지 않았다.

## 검증

| 항목 | 결과 |
|---|---|
| `npm run build` | 통과 |
| `tests/sl-sales-register.test.ts` · `tests/sl-sales-status-total.test.ts` | 6건 통과 |
| `SalesRegisterServiceImplTest` · `SalesStatusServiceImplTest` | 통과 |
| 프론트 전체 테스트 | 167파일 중 30파일 · 213건 실패. 판매 화면을 참조하는 테스트는 위 2파일뿐이고 실패 목록에 없다. 변경 전 기준 실행은 하지 않아 원인은 확인하지 못했다 |
| 예전 경로 · 주소 · 화면 키 검색 | 남은 곳 없음 |
| 트랜잭션 시험 실행 | 적용 결과 일치, 재적용 동일, 권한 15행 · 역할 권한 15행 그대로, 롤백 시 처음과 같음. 끝에 트랜잭션을 취소해 DB 는 바뀌지 않음 |

## DB 확인 근거

- 이 세션에 DB MCP(`songyeon-erp-postgresql-readonly`)가 없어 쓰지 못했다.
- 대신 사용자 환경변수의 접속 정보로 JDBC 조회를 해 판매관리 메뉴 76~78 의 현재 상태를 확인했고, `20261030_002` 스크립트와 같은 모양으로 작성했다.

## 남은 일

- DB 는 2026-11-02 사용자 요청으로 적용했다. 배포된 예전 화면에서는 판매관리가 열리지 않으므로 war · 프론트를 같이 배포해야 한다.
- 스크린샷이 없다. 화면 확인은 사용자가 한다.
