# 20261102_002 판매등록 표준화 결과

- 계획 · 사양: `docs/plan/20261102/20261102_002_판매등록_표준화_계획사양서.md`

## 결과

- 화면을 표준 구조로 나누고, 판매일자 기간을 상세 조회(⌄)로 옮겼다.
- [직접 등록]과 오른쪽 클릭 [행 추가]가 같은 내장 상세 창을 연다. [적용] 뒤 [저장]으로 넣는다.
- 검색칸은 거래처코드 · 거래처명을 둘 다 찾는다. 서버는 `selectShipped` 의 거래처 조건만 바꿨고 API 는 그대로다. DB 변경은 없다.
- 상세 조회에 품목코드/명을 더했다. 서버에서 받은 목록을 화면에서 거른다(`filterOrderRows`).
- 상세 조회 [조회]도 저장하지 않은 새 줄이 있으면 먼저 묻는다.
- 정리: 직접 등록 변환을 `toManualBody(row)` 하나로 합치고, 프론트의 `pendingCount` 와 기본 기간 중복 계산을 없앴다.

## 상세 창 빈 화면 수정

- 재현: 출하확정 줄의 상세(연필) 단추를 누르면 칸 없는 창이 떴다.
- 원인: `buildGridFormSections` 가 그 줄에서 편집할 수 없는 칸을 뺀다. 출하확정 줄은 모든 칸이 편집 불가다.
- 해결: 사용자 승인으로 `form.readOnly` 를 적은 칸은 편집 불가여도 창에 보여 주게 패치했다. 표 안의 편집 막기는 그대로고, [적용]은 `onBeforeApply` 로 막는다.
- 함께 바뀌는 곳: 결재양식(`DraftFormGrid`)의 양식코드 칸도 `form.readOnly` 라서 창에 읽기 전용으로 나온다.
- 회귀 검증: `tests/sl-sales-register-page.test.tsx`, `tests/f1-grid-form-modal.test.tsx` 통과. `tests/f1-grid.test.tsx` 는 46건 실패로 패치 전 47건보다 늘지 않았다.

## 남은 일

- 실제 브라우저 확인과 스크린샷은 하지 않았다. 등록 창 위에 고르기 팝업이 뜨는지, 실제 저장이 되는지는 사용자가 화면에서 확인한다.
- F1-Grid 를 다시 복사하면 `GridFormModel.ts` 패치를 다시 넣어야 한다.
