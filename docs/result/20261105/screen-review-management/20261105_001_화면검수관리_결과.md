## 결과

- 환경설정 > 시스템 관리 > 메뉴관리 밑에 '화면검수 관리'(화면ID `ST_SCREEN_REVIEWS`)를 만들었다. 보기 전용이다.
- 카드 6개: 전체 화면 · 검수완료 · 검수진행중 · 수정요청 · 미진행(건수 · 비율) · 전체 진행률(막대, `N개 중 M개 완료`, 기준일). 건수는 화면 수이고 검색과 상관없이 전체 기준이다.
- 표: F1-Tree. 모듈 묶음 줄(`기준정보 (11)`, 거른 뒤 건수) 아래 화면 줄. 칸은 No · 메뉴구분(중분류) · 화면명 · 화면코드 · 담당자(개발담당) · 검수일 · 상태(색 칩) · 비고(마지막 의견 한 줄, 마우스를 올리면 전체).
- 검색줄: 화면명 또는 화면코드. 상세 조회(⌄): 구분(모듈) · 상태 · 담당자.
- 서버: `GET /api/v1/system/screen-reviews` 목록. 표시 상태는 서비스(`displayStatus`)가 정한다: 수정요청 · 검수진행중은 현황 그대로, 마지막 이력이 검수완료면 검수완료(현황은 미검수로 돌아가 있음), 나머지 미진행.
- 넣지 않은 것: 오른쪽 화면 상세, 요구반영 · 기능점검 · 현업검수 3단계, 대표이사 보고서(PDF).

## DB 확인 (읽기 전용 조회 · 시험 실행)

- 대상 화면 = 사용 모듈의 사용 메뉴 중 하위 메뉴가 없는 것: 적용 전 61개 + 새 화면 1개 = 62개. 화면에 보인 숫자와 같다.
- 메뉴 스크립트 시험 실행: 새 메뉴 권한 = 메뉴관리 권한(메뉴 권한 5 · 역할 권한 9), 다른 메뉴 그대로, 다시 적용해도 같음, 롤백하면 처음과 같음. 사용자 승인 뒤 적용.

## 알아 둘 것

- No(행 번호)는 F1-Grid 표준 행 번호라 모듈 묶음 줄도 번호를 받는다.
- 쓰시는 8080 서버는 다시 켜야 목록 API 가 생긴다. 그 전에는 메뉴는 보이지만 목록을 못 불러온다는 알림이 뜬다.
