## 1. 목적

모든 화면의 검수 상태를 한 화면에서 본다. 보기 전용이다. 상태는 지금처럼 각 화면의 [화면검수] 패널에서 바꾼다.

## 2. 메뉴

- 환경설정 > 시스템 관리 > 메뉴관리(순서 30) 바로 밑. 화면ID `ST_SCREEN_REVIEWS`, 주소 `/settings/system/screen-reviews`, 이름 `화면검수 관리`, 순서 35(F1 Grid 테스트 40 은 그대로).
- 권한 행(메뉴 권한 · 역할 권한)은 메뉴관리(`ST_MENUS`)를 그대로 복사한다.
- 스크립트 `20261105_001`(SQL · 롤백 · 변경 이력, 두 폴더), `db-schema.md` 변경 이력. 시험 실행 뒤 적용 전 사용자 확인.

## 3. 대상 화면

- `tb_menu` 중 사용(`use_at = 'Y'`)이고 하위 메뉴가 없는 메뉴(실제 화면). 중분류 · 모듈 묶음 메뉴는 뺀다.
- 사용 중인 모듈의 메뉴만. 순서는 모듈 순서 → 중분류 순서 → 화면 순서.

## 4. 화면별 상태 (건수는 화면 수)

| 표시 | 정하는 법 |
|---|---|
| 검수완료 | 마지막 이력이 검수완료(`to_status = 'COMPLETED'`)이고 현황이 미검수 |
| 수정요청 | 현황이 `CHANGE_REQUESTED` |
| 검수진행중 | 현황이 `IN_PROGRESS` |
| 미진행 | 그 밖(이력이 없거나 현황 줄이 없음) |

- 한 화면에 수정요청이 여러 번 쌓여도 그 화면은 수정요청 1건이다.
- 검수완료 뒤 새 수정요청이 들어오면 그 화면은 수정요청이 된다.

## 5. 화면 구성 (이미지 기준, 오른쪽 화면 상세 · 대표이사 보고서 단추 · 3단계 칸 뺌)

- 머리: 제목 `화면검수 관리`, 설명 `메뉴 · 화면별 검수 상태를 한 번에 확인해요`.
- 카드 6개: 전체 화면 N개 · 검수완료 N개(%) · 검수진행중 N개(%) · 수정요청 N개(%) · 미진행 N개(%) · 전체 진행률(검수완료 ÷ 전체, 막대, `N개 중 M개 완료`, `기준일: 조회한 날`).
- 카드 건수는 조회한 그 시점의 현재 상태다. 날짜로 자르지 않는다(지금까지 쌓인 이력 전체로 정한 현재 상태). 기준일은 "이 날 조회한 숫자"라는 표시일 뿐이다.
- 카드 건수는 검색 조건과 상관없이 전체 화면 기준.
- 검색: 화면명 또는 화면코드 글자 · 구분(모듈) · 상태 · 담당자. 화면에서 거른다(전체를 한 번에 받는다).
- 표: F1-Tree, 처음에 모두 펼침. 트리 칸은 메뉴구분: 묶음 줄 = 모듈 `기준정보 (14)`(거른 뒤 건수, 남는 화면이 없으면 묶음 줄도 숨김), 화면 줄 = 중분류 이름.

| 칸 | 값 |
|---|---|
| No | 행 번호(F1-Grid 표준) |
| 메뉴구분 | 중분류 이름 |
| 화면명 | 메뉴 이름 |
| 화면코드 | 화면ID(`menu_code`) |
| 담당자 | 개발담당(`developer_name`) |
| 검수일 | 마지막 검수일(`review_date`) |
| 상태 | 4장 표시, 색 칩(검수완료 초록 · 검수진행중 파랑 · 수정요청 주황 · 미진행 회색) |
| 비고 | 마지막 이력 의견 한 줄(넘치면 말줄임, 마우스를 올리면 전체) |

- 편집 · 행 추가 · 오른쪽 클릭 메뉴 없음. 빈 값은 빈칸.

## 6. API

- `GET /api/v1/system/screen-reviews` (기존 화면검수 컨트롤러에 목록 추가). 로그인 테넌트 기준.
- 응답 `items[]`: `moduleCode` · `moduleName` · `menuId` · `menuCode` · `menuName` · `groupName` · `developerName` · `reviewDate` · `displayStatus`(`COMPLETED`/`IN_PROGRESS`/`CHANGE_REQUESTED`/`NOT_STARTED`) · `lastComment`.
- SQL 한 번: 대상 메뉴 + 현황 LEFT JOIN + 화면별 마지막 이력(LATERAL). 응답에는 `reviewStatus` · `lastToStatus` 도 들어 있다(표시 상태 근거).

## 7. 확인

- 서버: 매퍼 · 서비스 테스트(4장 상태 규칙, 묶음 메뉴 제외, 수정요청 여러 번 = 1건).
- 화면: 카드 건수 · 거르기 · 묶음 건수 테스트. 실제 화면 1280 · 375px.
