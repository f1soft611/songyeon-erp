## 1. 문제 (S_ERP 와 같음)

- 서버를 war 로 배포하면 주소 앞에 배포 경로(context path, 예: `/s-erp-backend`)가 붙는다.
- `AuthenticInterceptor` 는 주소 전체(`getRequestURI()`)가 `/auth/refresh` 로 시작할 때만 토큰 갱신 요청을 통과시켰다. 배포 경로가 붙은 `/…/auth/refresh` 는 이 조건에 맞지 않아 세션 확인으로 넘어가 오류가 났다.
- 화면은 토큰 갱신이 실패하면 로그인 정보를 지우고 로그인 화면으로 보내므로, 쓰는 도중 로그인 화면으로 튕긴다.

## 2. 변경

- 갱신 경로 판단을 배포 경로를 뺀 `getServletPath()` 가 정확히 `/auth/refresh` 인지로 바꿨다. S_ERP 최신 파일과 같다(송연에서 따로 고친 곳이 없던 파일이라 그대로 맞춤).
- 인증 방식 · 토큰 만료 · API · DB 는 바뀌지 않는다.

## 3. 변경 파일

- 서버: `com/cmm/interceptor/AuthenticInterceptor.java`(S_ERP 최신).
- 테스트(새로 · S_ERP): `AuthenticInterceptorTest`(배포 경로가 붙은 갱신 요청이 통과하는지).

## 4. 검증

- 바꾸기 전 `AuthenticInterceptorTest` 가 `ModelAndViewDefiningException` 으로 실패(S_ERP 수정 전과 같음) → 바꾼 뒤 통과.
- 서버 전체 812건 중 기존 실패 `MinioStorageConfigTest` 1건(설정 파일 없음, 이번 변경과 무관)만.
- 화면 변경 없음. 개발 서버는 배포 경로가 `/` 라 전과 같이 동작한다. 운영 반영은 war 재배포 뒤 브라우저 Network 에서 `/…/auth/refresh` 응답이 `resultCode: "200"` 과 새 토큰인지 확인한다.
