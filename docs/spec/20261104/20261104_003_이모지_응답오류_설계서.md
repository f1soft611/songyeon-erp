## 1. 문제

- 서버 응답 JSON 에 이모지(😀 · 👍🏽 · 👩‍💻 처럼 UTF-16 두 칸을 쓰는 글자)가 있으면 `Unmatched first part of surrogate pair` 로 응답을 만들지 못한다.
- 원인: 공통 `HtmlCharacterEscapes.getEscapeSequence` 가 글자를 한 칸(char)씩 잘라 돌려줘 두 칸짜리 글자가 깨진다.
- 송연에는 쪽지가 없지만 같은 변환(`WebMvcConfig.htmlEscapingConverter`)을 공지 · 결재 댓글 등 모든 응답이 쓴다.

## 2. 변경

- `backend/src/main/java/egovframework/com/config/HtmlCharacterEscapes.java` 를 S_ERP 최신본으로: 따로 바꿀 것이 없는 글자는 `null` 을 돌려 Jackson 기본 Unicode 처리를 쓴다. ASCII JSON escape 설정은 그대로.
- S_ERP 의 쪽지 알림 요약 497자 경계 처리(`DirectMessageServiceImpl`)는 송연에 쪽지가 없어 해당 없음.

## 3. 검증

- `HtmlCharacterEscapesTest`(S_ERP 테스트와 같은 확인, 송연은 쪽지 VO 대신 Map): 이모지 · 피부색 · ZWJ · 한글 · 따옴표 · 꺾쇠 · 개행이 실제 converter UTF-8 응답 왕복에서 그대로. 고치기 전 같은 오류로 실패 확인 → 고친 뒤 통과.
- 백엔드 전체 `mvn test`: 710건 중 실패 1건 `MinioStorageConfigTest` — git 제외 파일 `application-prod.properties` 가 로컬에 없어 읽지 못함(이번 변경 무관, S_ERP 도 같음).
