## 1. 동작 (S_ERP 와 같음)

| | 바뀌기 전 송연 | 바뀐 뒤(S_ERP) |
|---|---|---|
| 내 댓글 | ⋮ 수정 · 삭제 | 그대로 |
| 남의 댓글 | ⋮ 보임 → 누르면 서버가 거절(오류) | ⋮ 안 보임 |
| 시스템 메시지 · 삭제된 댓글 · 작성자 모름 | 안 보임 | 안 보임 |

- '내 댓글' = 댓글 작성자 ID(`writerId`, 사번) 가 로그인 정보의 `userId`(로그인아이디 = 사번, `login_code`)와 같을 때. 화면에서 판단한다(S_ERP 와 같음). 서버의 작성자 확인(남의 댓글 수정 · 삭제 거절)은 그대로.

## 2. 변경 파일

- `shared/components/feed/TiptapCommentThread.tsx`: 메뉴 조건을 S_ERP 와 같이 `comment.isEditable === true && !isDeleted && !isSystemEvent`(1단계 때 남겨 둔 예전 조건을 바꿈).
- `pages/groupware/community/notice/data/noticePostAdapter.ts`: S_ERP 와 같이 `isEditable = 삭제 안 됨 && writerId 있음 && writerId === 로그인 userId`(예전: 삭제 안 됨이면 누구나).
- 결재 문서 상세는 이미 S_ERP 와 같이 내 댓글 판단을 넘기고 있었다.
- 테스트: `feed-components` 에 S_ERP 의 '내 댓글에만 메뉴' 확인 추가, S_ERP 와 같이 메뉴를 쓰는 테스트 자료에 `isEditable: true`, `notice-page` 의 댓글 수정 · 삭제 테스트도 S_ERP 와 같이.
