## 1. 범위

- S_ERP 는 문서현황 · 수주현황(`sales/order/status`)에 적용했다. 송연에는 문서현황만 있어 문서현황과 공통 부분을 옮긴다.
- S_ERP 같은 작업의 통합검색 일치어 강조는 송연에 통합검색이 없어 이번에 제외(통합검색 옮길 때 함께).

## 2. 동작 (S_ERP 와 같음)

- 조회가 성공하면 검색 영역과 그리드 사이에 정보 안내를 띄운다.
  - 결과 있음: `조회 결과 총 N건입니다.`(천 단위 쉼표, N 은 `totalRowCount`)
  - 0건: `조회 결과가 없습니다. 조회 기간을 넓히거나 검색 조건을 변경해 주세요.` — 예전 [검색 조건 초기화] 버튼은 없앴다.
- X 로 닫으면 그 결과 동안 숨고, 다시 조회가 끝나면 새 안내가 보인다. 처음 조회 전 · 조회 중 · 오류에는 안 보인다.
- 간격: 안내 위 · 아래 8px(`PageMessageArea` 의 `compact`: 위 `pt: 1`, 아래 `pb: 0`). 오류 메시지 여백은 그대로.

## 3. 변경 파일

## 3-1. 송연 현황 화면에도 적용 (사용자 결정 2026-11-04 "s-erp가 표준")

| 화면 | 안내 조건 | 건수 | 예전 0건 문구 |
|---|---|---|---|
| 생산현황 · 출하현황 | [조회]한 뒤, 조회 중 · 오류 아님 | 받은 줄 수 | 결과 문구는 없앰. [조회] 전 '기간을 정하고 [조회] 를 눌러주세요' 는 그대로(이 두 화면은 [조회]를 눌러야 부른다) |

| 발주현황 | 불러온 뒤, 조회 중 아님 | 받은 발주 수 | 없었음(앞서 사용자가 지움) |

| 재고현황 | 불러온 뒤, 조회 중 아님 | 탭 · 검색어 · 재고 0 제외로 거른 줄 수 | '해당하는 원재료/부자재가 없습니다' 와 `emptyText` 없앰(테스트 2줄도) |

- 안내 자리는 검색 영역 바로 다음(오류 · 저장 메시지가 있으면 그 다음), 표 위.
- 좁은 화면(375px)에서 안내 아래 간격이 12px 이다. 송연 업무 화면의 표 영역 여백이 `p: { xs: 1.5, sm: 1 }`(좁으면 12px)이라서다. S_ERP 는 `p: 1`(8px). 송연 화면 전체에 같은 값이라 이번에는 바꾸지 않았다 → 사용자 결정으로 S_ERP 와 같은 `p: 1` 로 통일([20261104_005](20261104_005_최근사용메뉴_PC유지_여백통일_설계서.md)), 375px 도 8px.

## 4. 결과

- 고치기 전 S_ERP 테스트를 먼저 넣어 실패 확인(공통 컴포넌트 없음, 0건 안내 · 재조회 안내 2건) → 고친 뒤 통과. `document-status-page` 29건 중 1건(`refreshes quietly and keeps the document detail open after a detail action`)은 S_ERP 의 다른 업데이트(20261102_003 종합현황 문서액션 조용한 갱신) 내용이라 그 작업 때 함께 맞춘다.
- 실제 화면(송연 서버, 375 · 768 · 1280px): `조회 결과 총 N건입니다.` 안내, 위 · 아래 8px, 가로 넘침 없음, X 로 닫힘, [조회] 뒤 다시 보임, 화면 오류 0, 저장 요청 0.
- 송연 현황 6개(375 · 1280px): 모두 안내가 뜨고(0건 · N건 문구), X 로 닫히고, [조회] 뒤 다시 보임. 생산현황 · 출하현황은 [조회] 전에는 안내 없음. 1280px 위 · 아래 8px, 375px 위 8px · 아래 12px(위 3-1). 가로 넘침 · 화면 오류 · 저장 요청 0. 타입 검사 · 재고현황 · 발주 · 입고 테스트 통과.
