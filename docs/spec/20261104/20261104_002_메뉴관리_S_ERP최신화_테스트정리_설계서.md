## 1. 테스트 실패 확인 방법

- S_ERP 프론트를 임시 폴더에 복사해 S_ERP 원본 그대로 전체 테스트를 돌리고(S_ERP 폴더는 건드리지 않음), 송연 결과와 테스트 이름 단위로 비교했다.
- S_ERP 원본도 31개 파일 211건이 실패한다. 이 중 F1-Grid 테스트 46건은 S_ERP 테스트 파일의 한글 229줄이 깨져 있는 것이 주원인(33건)이다. 송연은 S_ERP 에서 그대로 받아온 것이라 따로 고치지 않는다.

- 전체를 한꺼번에 돌릴 때 시간 초과로 가끔 실패하는 것(F1-Grid 머리 스크롤 · 공지 댓글 등)은 따로 돌리면 통과한다.

## 3. 메뉴관리 S_ERP 최신화

- `MenuManagementPage.tsx` · `components/MenuManagementPanel.tsx` · `menuManagementPageSession.ts` 를 S_ERP 최신본으로 바꾸고, 송연 권한(2026-10-21)만 다시 얹었다.
  - Panel: `canWrite` · `canDelete` 속성, `readOnlyColumns(columns, canWrite)`, 오른쪽 클릭 루트 추가 = 쓰기, 행 추가 = 쓰기 · 저장 중 아님, 행 삭제 = 삭제 · 저장 중 아님.
  - Page: `canWrite={pageActionPermissions.write}` · `canDelete={pageActionPermissions.delete}`, 조건 저장 키 `songyeon-erp:page:menu-management`.
- S_ERP 최신본에서 새로 들어온 것: 저장 · 새로고침 중 모듈 · 권한 선택 · 검색 · 그리드 조작 잠금, 저장 재시도 때 이미 만든 메뉴를 다시 만들지 않음, 첫 로딩 실패 시 다시 시도, 모듈 · 권한 · 검색어 유지, 저장 안 한 변경이 있을 때 창 닫기 경고.
- 공통 `PermissionGroup.tsx` 를 S_ERP 최신본으로(제목줄 버튼에 `saving` 을 주면 저장 중 표시). `saving` 을 주지 않는 화면은 그대로다.
- 테스트 `menu-management-f1-grid` · `menu-management-required-selection` 은 S_ERP 최신본(저장 키만 송연), `menu-management-permission`(새로) 은 송연 권한 3건.

## 4. 결과

- 메뉴관리 테스트: S_ERP 원본과 같은 결과(S_ERP 에서도 실패하는 23건만 남음). 송연 권한 테스트 3건 통과, S_ERP 원본 Panel 로 바꾸면 2건 실패(테스트가 권한 처리를 잡아냄).
- 실제 화면(송연 서버): 메뉴관리 열림, 권한 고르면 메뉴 목록, 다른 화면에 갔다 와도 모듈 · 권한 · 검색어 유지, 화면 오류 0, 저장 요청 0.
- 전체 프론트 테스트: 194건 실패 중 192건은 S_ERP 원본에서도 실패, 송연에서만 실패는 시간 초과 2건(따로 돌리면 통과)뿐이다(수주현황 테스트 정리 후).
