## 1. 동작 (S_ERP 와 같음)

- 로그인 중이면 화면이 서버 실시간 연결(`GET /api/v1/groupware/realtime`, SSE)을 하나 연다. 끊기면 다시 잇고, 탭이 안 보일 때는 신호를 모았다가 보일 때 한 번에 갱신한다. 로그아웃하면 닫는다.
- 서버는 데이터가 실제로 바뀐 뒤(트랜잭션 커밋 후)에만 그 사람에게 신호를 보낸다.
  - 알림이 새로 쌓임 → 받는 사람 `NOTIFICATION`(쪽지 알림이면 `MESSAGE` 도)
  - 알림 읽음 · 보관 → 본인 `NOTIFICATION`
  - 쪽지 보냄 → 보낸 사람 `MESSAGE`, 받는 사람은 알림 신호로
  - 대화 읽음 · 숨김 → 본인 · 상대 `MESSAGE`
- 신호를 받으면 상단 알림 · 쪽지 숫자, 알림 창 · 알림함, 쪽지함 목록 · 열린 대화가 새로고침 없이 다시 불린다.

## 2. 송연에 맞춘 점

- 사람: S_ERP `Long` → 송연 사번 문자열(`RealtimePublisher.publish(tenantId, String userId, area)`, 연결 주인도 사번). 숫자가 아니어도 되고 빈 값만 막는다.
- 화면 이벤트 이름: `songyeon-erp:realtime`, 로그인 키 `songyeon-erp-auth`(송연 키 규칙).
- `App.tsx`: S_ERP 는 같은 때 라우터 방식도 바꿨지만(다른 작업) 이번에는 `<RealtimeBridge />` 한 줄만 옮겼다.
- 보안 설정은 S_ERP 와 같아(송연 공개 주소만 더 있음) 실시간 주소를 따로 열지 않았다. 로그인 토큰이 있어야 연결된다.

## 3. 변경 파일

- 서버(새로 · S_ERP): `groupware/realtime` 4개(컨트롤러 · 영역 · 게시 · 연결 관리).
- 서버(바꿈): 알림 서비스(S_ERP 와 같은 자리에 신호), 쪽지 서비스(S_ERP 최신본에서 사람만 사번).
- 화면(새로 · S_ERP): `RealtimeBridge`. 화면(바꿈): `App.tsx`(한 줄). `realtimeService` · `useRealtimeRefresh` 는 1단계에서 들어와 있었다.
- 테스트: 실시간 4개(S_ERP, 사번), 알림 · 쪽지 서비스 테스트에 S_ERP 실시간 신호 확인 되살림, `realtime-service.test.ts`(S_ERP, 송연 키).
