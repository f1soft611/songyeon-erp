## 1. 왜 한 번에 했나

- 송연 결재는 S_ERP 10-28(`3df09a85` 문서번호 · 공유) 수준이었다. 그 뒤 S_ERP 결재 변경 세 개가 모두 빠져 있었고, 기안자 최종확인 DB 스크립트가 앞의 참조자 확인(10-29) · 참조 추가(10-30) 제약을 전제로 해서 따로 옮길 수 없었다.
- 그래서 결재 서버 · 화면을 S_ERP 최신으로 맞추고 송연 고유 부분만 다시 넣었다.

## 2. 들어온 기능 (S_ERP 와 같음)

- 참조자 확인: 참조자는 상신 뒤 문서를 열어 '확인'을 누른다. 결재 요약에 '내가 확인할 문서' 건수 · 목록.
- 참조자 추가: 상신 뒤 문서에 참조자를 더한다(사용자 선택 창, 이력 `REFERENCE_ADDED`).
- 기안자 최종확인: 상신 · 재상신 때 서버가 결재선 끝에 기안자 최종확인 줄을 만든다(화면 결재선에는 안 보임). 최종 승인 · 반려 때 대기로 바뀌고, 기안자가 '최종확인'을 누르면 확인 처리된다. 문서 상태는 바뀌지 않는다. 결재 요약에 '내가 최종 확인할 문서'. 예전처럼 최종 승인 때 따로 쌓던 `COMPLETED` 이력은 새 처리에서 만들지 않는다.
- 링크 미리보기 · 공유: 문서 · 공지 공유 링크를 공용 암호 토큰(`groupware/shared/ShareTokenCodec`)으로 만들고, 본문 · 댓글 · 쪽지의 문서 · 공지 · 외부 링크(OG) 미리보기를 보여 준다. 공지 공유 API(`NoticeShareApiController`).
- 문서현황 처리 뒤 조용한 갱신, 편집기 저장 흐름, 첨부 목록 · 파일 보기 · 페이지 번호 등 같은 커밋의 공용 화면 변경.
- 알림 → 문서 바로 열기: 알림을 누르면 `/groupware/doc/write?approvalId=…` 로 가서 그 문서 상세가 열린다. 종합현황 → 공지(`dashboardPostId`)도 같은 방식. 닫으면 주소에서 지운다. (알림함을 옮길 때 대시보드 연결이 빠져 있던 것을 이번에 넣었다.)
- 상단 바 높이: 좁은 화면에서 검색창이 다음 줄로 내려가면 상단 바도 늘어난다(S_ERP `4d6becc1`). 고정 높이였을 때는 375px 에서 검색 단추가 문서 상세의 닫기 단추를 덮었다.

## 3. 송연에 맞춘 점

- 사람은 사번 문자열: 인증 사용자(`authenticatedUserId`) · 댓글 멘션 대상 · 열람 기록 계정 번호를 문자열로 둔다(앞자리 0 유지). Mapper 의 `selectLoginIdByLoginCode` · `selectApprovalCommentRecipientUserIds` 는 송연 쿼리 그대로.
- 화면 멘션 후보 · 멘션 보내기 · 댓글 스레드의 사람 번호도 문자열.
- `pom.xml`: S_ERP 와 같이 `httpclient` 의 test 한정을 풀었다(링크 미리보기 서버가 씀). 웹 푸시 라이브러리는 보류라 넣지 않았다.
- F1-Grid `UserSelectEditor`: 송연 수정이 없던 S_ERP 예전 복사본이라 S_ERP 최신 파일을 그대로 복사했다(`disableCloseOnSelect` 옵션). `F1-GRID.md` 36장에 옵션 설명을 더했다.
- 넣지 않은 것: 품목-거래처 단가(S_ERP 업무 화면), 영업 대시보드 숫자, 종합현황(`OverviewPage`) 개편, 웹 푸시.

- DB: 시험 실행(다시 적용해도 같음, 최종확인 줄 · 참조자 확인 들어감, 같은 문서 최종확인 두 번 · 같은 사람 일반 결재 두 번 막힘, 확인 시각 없는 확인 막힘, 새 줄이 있으면 롤백 멈춤, 롤백하면 처음과 같음) 뒤 승인 받아 적용.
- 서버: 결재 · 공유 · 공지 공유 183건 통과. 전체 865건 중 기존 실패 `MinioStorageConfigTest` 1건만.
