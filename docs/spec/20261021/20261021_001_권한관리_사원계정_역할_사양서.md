# 20261021_001 권한관리: 송연 사원 계정 · 역할 적용 사양서

- 계획서: [20261021_001_권한관리_사원계정_역할_계획서.md](../../plan/20261021/20261021_001_권한관리_사원계정_역할_계획서.md)

## 1. 표 쓰임 (구조 변경 없음)

| 표 | 송연에서 쓰는 방법 |
| --- | --- |
| `tb_login_account` | 계정 있는 직원마다 한 줄. `tenant_id` = SONGYEON, `login_code` = 사번(`employees.id`), `password_hash` = Werkzeug 해시, `use_at` = 'Y'. 사진 · 도장 칸은 쓰지 않는다(그대로 `employees`) |
| `tb_login_account_role` | 계정 ↔ 역할 |
| `tb_role` · `tb_role_menu_permission` · `tb_menu_permission` | S_ERP 와 같다 |
| `employees` | 이름 · 부서 · 퇴사일 · 로그인 아이디(`username`, 계정 있음 표시 겸 `LoginVO.id`). `password_hash` 는 계정 표와 같은 값으로 함께 바꾼다(롤백해도 비밀번호가 맞게) |
| `tb_user` · `tb_department` | 쓰지 않는다 |

- 로그인 아이디: 사번(지금과 같음). `LoginVO.id` = `employees.username`, `LoginVO.uniqId` = 사번(지금과 같음 — 문서함 소유자 등 저장된 값이 묶여 있음)
- 재직: `employees.resign_date` 가 비었거나 오늘보다 뒤

## 2. DB `20261021_001_songyeon_login_account_role` (데이터만)

1. 확인: SONGYEON 테넌트, 역할 ADMIN · DEFAULT_USER 가 없으면 멈춘다.
2. 백업 표 `bak_20261021_001_admin_role_menu_permission`: 적용 전 ADMIN 의 역할 메뉴 권한 줄(롤백용).
3. 계정: `username` 과 `password_hash` 가 있는 직원 → `tb_login_account`(`ON CONFLICT (tenant_id, login_code) DO NOTHING`).
4. 역할: `is_admin` = 1 → ADMIN, 그 밖 → DEFAULT_USER(`ON CONFLICT DO NOTHING`).
5. ADMIN 메뉴 권한: SONGYEON 메뉴의 `tb_menu_permission` 전부 → `tb_role_menu_permission`(`ON CONFLICT DO NOTHING`).
6. 다시 돌려도 같다. 롤백: ADMIN 권한 중 백업에 없는 줄 삭제 → 백업 표 삭제 → SONGYEON 계정 삭제(역할 연결은 FK CASCADE). 적용 전 계정 · 연결은 0줄.

## 3. 로그인 (`EgovLoginUsr_SQL.actionLoginEmployee`)

- `tb_login_account li` JOIN `tb_tenant`(`tenant_code` = 설정값, 사용) JOIN `employees e ON e.id = li.login_code`
- 조건: `li.login_code = 입력 사번`, `li.use_at = 'Y'`
- 비밀번호 = `li.password_hash`(서비스의 Werkzeug 확인은 그대로)
- 역할: S_ERP 와 같은 LATERAL(우선순위 PLATFORM_ADMIN → TENANT_ADMIN → TENANT_USER → 그 밖, 같은 순위면 role_id 큰 것), 사용 중인 역할만. **LEFT JOIN** — 역할 없으면 `roleCode`/`roleId` NULL 로 로그인
- `userSe` · `groupNm`: S_ERP 와 같은 CASE
- 계정 줄이 없는 직원은 로그인 실패(지금 `username` 없는 직원과 같음)

## 4. 권한 판정

- `EgovAccessControlHelper.isTenantAdmin`: `roleCode` NULL → false(송연 예외 삭제). 관리자 = PLATFORM_ADMIN · TENANT_ADMIN · ADMIN(S_ERP 와 같음)
- `SystemMenuServiceImpl.permissionCodesByMenuId`: 역할 0개 → 모든 메뉴 권한 빈 값(화면은 권한 없는 메뉴를 숨김 → 메뉴 0개)
- `EgovSystemMenu_SQL.selectRoleIdsByUserAccount` · `selectRoleCodesByUserAccount`: 넘어오는 `loginCode` 는 `LoginVO.id`(= username). `JOIN employees e ON e.id = la.login_code` 하고 `e.username = #{loginCode}` 로 찾는다

## 5. 권한관리 사용자 매핑 (`EgovSystemRole_SQL`)

- 응답 모양 그대로(`assignedUsers` · `unassignedUsers`), `SystemRoleUserVO` 에 `loginCode`(사번) 추가
  - `userId` · `loginId` = `tb_login_account.login_id`, `userNm` = `e.name`, `departmentNm` = `e.department`(비면 '-'), `emailAddr` = `e.email`, `lastLoginAt` = NULL
- 매핑된 사람: 연결 → 계정(SONGYEON, 사용) → 직원(재직)
- 매핑 안 된 사람: 계정(같은 테넌트, 사용) → 직원(재직), 이 역할 연결 없음. 이름순
- `selectRoleUserMappingId` · `selectLoginIdByUserId` · `selectAssignedUserByLoginId`: `tb_user` 대신 계정 · 직원
- 추가 · 삭제 API 경로 · 본문 그대로(`loginId` 숫자)
- 프론트: `RoleUserRow.loginCode` 추가. '로그인 ID' 칸은 사번(`loginCode`, 없으면 `loginId`)을 보여 준다. 저장 · 키는 지금처럼 `loginId`. 칸 순서 · storageKey 그대로

## 6. 인사관리 계정 (`HrServiceImpl` · `EgovHr_SQL`)

- 계정 저장(`saveAccount`): 지금 검사 그대로 → `employees` 고침(지금과 같음) → 계정 표 upsert(`login_code` = 사번, 비밀번호 = `employees.password_hash`, `use_at` = 'Y')
  - 계정 표 줄이 없던 경우(처음 만듦)만 DEFAULT_USER 역할을 붙인다
- 계정 거두기(`revokeAccount`): 지금 검사 그대로 → `employees` 비움 → 계정 표 줄 삭제(역할 연결 CASCADE)
- 테넌트 코드: 로그인과 같은 설정값 `Globals.songyeon.tenantCode`(기본 SONGYEON)
- 두 표 변경은 한 트랜잭션(`*Impl` 공통 트랜잭션)

## 7. 내 정보 비밀번호 (`EgovLoginUsr_SQL`)

- `selectCurrentPasswordHash`: 계정 표(`login_code` = username 의 사번, 같은 테넌트)
- `updateCurrentPassword`: `employees` 와 계정 표를 같은 해시로(한 문장, CTE)

## 8. 검증 기준

- 단위: 로그인 서비스(역할 없음 로그인), `isTenantAdmin`(NULL → false), 메뉴(역할 0개 → 권한 없음), 인사 계정(처음 만들 때만 역할, 거두면 계정 삭제)
- DB: 트랜잭션 안에서 적용 → 재적용 → 롤백 → ROLLBACK, 개수 비교 후 적용
- API(8080): `0000` 로그인 → 내 메뉴 개수가 적용 전과 같음, 역할 목록 사용자 수, 매핑 목록
- 화면: 권한관리 사용자 매핑(쓰기 막음), 스크린샷
