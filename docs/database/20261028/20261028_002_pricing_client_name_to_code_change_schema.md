# 20261028_002 단가관리 거래처를 거래처코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-28 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(거래처명 → 거래처코드) · 컬럼 이름 변경 · 백업 표 추가(스크립트로 바꿀 때) |
| 대상 표 | `pricing`(`client_name` → `client_code`), 백업 `bak_20261028_002_pricing_client`(새 표) |
| 적용 | songyeon DB 에는 사용자가 직접 같은 변경을 했다(2026-10-28). 이 스크립트는 그 변경의 기록이고, 다른 DB 에 같은 변경을 할 때 쓴다. 이미 바뀐 DB 에서는 아무것도 하지 않는다. 컬럼 설명(COMMENT)은 비어 있어 2026-10-28 Claude 가 스크립트의 COMMENT 문을 따로 적용 |
| 롤백 | `20261028_002_rollback.sql` |

## 내용

- 요청: "단가관리 상세 창에 있는 거래처도 팝업으로 바꿔줘"
- 사용자 결정: 거래처코드로 바꾸기(제품 `20261023_013` 과 같은 방식)
- 바뀐 모양
  - 칸 이름 `client_name` → `client_code`(24번째 자리, text 그대로)
  - 값: 거래처명 `(주)…` → 거래처코드 `000006`. 빈 글자는 NULL
- 지금 DB(개수만): 7건 중 6건이 거래처코드이고 모두 거래처마스터와 이어진다. 1건은 빈 값이다.
- 스크립트로 바꿀 때 거래처명이 거래처마스터와 1:1로 맞지 않으면 멈춘다. 바꾸기 전 값은 `bak_20261028_002_pricing_client` 에 남긴다.
- 시험 실행(트랜잭션, 끝에 ROLLBACK): 이미 바뀐 DB 에서 다시 적용해도 그대로이고, 롤백하면 6건이 거래처명으로 돌아간다.

## 영향 범위

- 단가관리 목록 · 상세(`EgovPricing_SQL`)는 `client_code` 를 읽고 거래처마스터 이름을 붙여 `clientName` 으로 준다. 검색어는 거래처코드 · 거래처명 둘 다 찾는다.
- 단가관리 저장(`PUT /api/v1/sa/pricing/{code}`)은 `clientCode` 를 받는다. 사용 중 거래처만 받고, 지금 값은 그대로 둘 수 있으며, 비우면 비운다.
- 제품등록이 새 단가표를 넣을 때(`insertPricing`) 제품의 거래처코드를 함께 넣는다(예전에는 거래처명 칸이 비어 들어갔다).
- 화면: 단가관리 상세 창의 거래처 칸이 🔍 팝업(제품마스터 거래처 칸과 같은 모양)이 된다.
- 이 변경 전 서버(war)는 `pricing.client_name` 을 읽어서, DB 를 바꾼 뒤에는 단가관리가 오류 난다. 새 war 를 올려야 한다.
- 롤백하면 `client_name`(거래처명)으로 돌아간다. 서버 코드도 함께 돌려야 한다.
