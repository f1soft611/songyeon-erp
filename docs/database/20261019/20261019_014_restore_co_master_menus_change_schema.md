| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경 (스키마 변경 없음) |

| 적용 | 2026-10-19 적용 완료 (트랜잭션 시험 실행 후 적용) |
| 롤백 | `20261019_014_rollback.sql` |

## 내용

- 요청: "테이블 잘못 날렸나봐 tb_menu 테이블 확인 좀"
- 확인
  - 표 3개는 그대로 있었다.
  - 공통관리 분류 '기초정보'(`master`)가 지워져 있었다.
  - 그 아래 화면 메뉴 8개와 권한 행도 없었다. 하위 메뉴(`parent_menu_id` FK)와 권한 행(`menu_id` FK)이 `ON DELETE CASCADE` 라 함께 지워진 것이다.
  - 013 적용 직후에는 화면 8개가 있었다. 그 뒤에 지워진 것이다.
- 복구
  - 분류: `master` '기초정보' `/co/master` 순서 1(권한 행 없음, 원래와 같음)
  - 화면 8개: 포장유형 20 · 공통코드 관리 30 · 창고등록 40 · 제품마스터 50 · 거래처마스터 60 · 거래처별 제품조회 70 · 원재료마스터 80 · 부자재마스터 90
    - 코드 · 이름 · 주소는 원래 스크립트와 같다.
  - 권한 행
    - 생산스케줄(`production`)에서 복사했다(permission_id 10 ~ 14, 메뉴마다 5행).
    - 원래 스크립트는 지운 기초정보(`settings`)에서 복사했다. 두 메뉴의 권한 행은 같다.
  - `menu_id` 는 새로 매겼다. 옛 번호를 가리키는 다른 표는 없다.

## 영향 범위

- 메뉴판: 공통관리 > 기초정보 ▾ 포장유형 · 공통코드 관리 · 창고등록 · 제품마스터 · 거래처마스터 · 거래처별 제품조회 · 원재료마스터 · 부자재마스터
- 분류 메뉴를 지우면 아래 메뉴와 권한 행이 같이 지워진다. 메뉴를 지울 때 주의한다.

## 확인

- 한 트랜잭션 안에서 아래를 했다.
  1. 적용 → 다시 적용(같음)
  2. 롤백 스크립트(원래대로)
  3. ROLLBACK
- ROLLBACK 뒤 DB 는 그대로였다. 그 뒤 적용했다.
- 적용 뒤 내 메뉴 API(`/api/v1/menus/my`)에 새 화면들이 나온다.
