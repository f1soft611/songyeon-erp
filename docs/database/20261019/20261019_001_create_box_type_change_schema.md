## 내용

- 포장유형(공통관리 > 기초정보 > 포장유형, 화면ID BSBoxTypeView)을 옛 `product_types` 대신 이 표에서 관리한다.
  - 칸: 일련번호 PK `box_type_id`, 사업장 · 사업부, 포장유형코드 · 명, 포장단위 수량 · 단위
  - 칸: 고정마진율 · 로스율(%), 인건비 · 포장비 · 물류비 · 마진(원), 부대비용 합계(생성 칸)
  - 칸: 적용기간, 정렬순서, 비고, 사용여부, 감사 칸 4개
  - 유니크: `(factory_code, plant_code, box_type_cd, apply_start_dt)`
  - CHECK: 비율 0~100, 금액 0 이상, 포장단위 수량 > 0, 종료일 ≥ 시작일
  - 인덱스 4개
  - 수정일시 자동 갱신 트리거
- 원본 스크립트와 다른 점(기록 파일만 바꿨고, 표 정의는 같다)
  - 맨 앞 `DROP TABLE IF EXISTS tb_box_type CASCADE` 를 뺐다. 다시 돌리면 자료가 지워지기 때문이다. 표를 지우는 것은 롤백 파일에만 둔다.
  - `CREATE TABLE` · `CREATE INDEX` 를 `IF NOT EXISTS` 로 바꾸고, 트리거는 `DROP TRIGGER IF EXISTS` 뒤에 만든다.
  - 샘플 2건은 같은 번호의 seed 파일로 나누고 `ON CONFLICT DO NOTHING` 을 붙였다. 원본은 트랜잭션 밖이었고 중복되면 오류가 났다.
  - 원본 끝의 '화면 연동 참고 쿼리'는 기록에 넣지 않았다. 실제 쿼리는 매퍼 `BoxType_SQL_postgresql.xml` 에 있다.

## 운영 규칙 (2026-10-19 테이블 설계자 확인)

- 사업장 `F001` · 사업부 `P001` 로 고정한다. 서비스가 넣는다.
- 적용기간(`apply_start_dt` · `apply_end_dt`)은 관리하지 않는다.
  - 처음 넣을 때 기본값(오늘 / 9999-12-31) 그대로 둔다.
  - 수정은 이력 없이 그 줄을 덮어쓴다(`box_type_id` 로).
- 포장유형코드는 화면에 두지 않는다. 새로 등록할 때 서버가 BT001 … 로 매긴다(번호표 `tb_id_sequence`, 키 `BOX_TYPE_CODE` · `F001` · `P001`, 2026-10-19 사용자 결정).
- 아직 정해지지 않아 지금 방식으로 둔 것
  - 삭제: 논리삭제 `use_yn = 'N'`
  - 같은 날 지운 코드를 다시 등록하면 그 줄을 되살린다.
  - 옛 `product_types` 자료(1건): 그대로 둔다(옮기지 않음).

## 영향 범위

- 포장유형 화면, 그리고 포장유형 목록을 쓰는 단가관리 · 견적 · 제품등록이 이 표를 읽는다(API `/api/v1/co/master/box-type`).
- 비율 단위가 0~1(옛 표)에서 0~100(%)로 바뀌었다. 화면의 ×100 변환을 뺐다.
- `factory_code` · `plant_code` 를 쓰는 표는 DB 에서 이 표 하나다.
