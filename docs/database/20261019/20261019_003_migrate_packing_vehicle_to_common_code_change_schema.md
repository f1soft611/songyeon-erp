# 20261019_003 포장방법 · 차량 자료를 공통코드로 옮김 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-19 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경 + 백업 표 추가(`bak_20261019_003_common_code`) |
| 대상 표 | `tb_common_code_group`(1줄 추가), `tb_common_code_item`(5줄 추가), `tb_id_sequence`(2줄) |
| 읽기만 | `packing_methods` · `vehicles` |
| 적용 | 2026-10-19 적용 완료 (트랜잭션 시험 실행 후 적용) |
| 롤백 | `20261019_003_rollback.sql` |

## 내용

- 요청: 기초정보 화면의 포장방법 · 차량정보 탭 삭제 → "관련 파일 다 지워"
- 사용자 선택
  - 백엔드까지 모두 지운다.
  - 출하확정의 목록은 공통코드에서 받는다.
  - 차량은 공통코드 'VEHICLE' 그룹으로 한다.
  - 기존 자료는 공통코드 상세로 옮긴다.
- 공통코드 그룹 '차량'(`VEHICLE`, 순서 2)을 만들었다. 포장방법 그룹 `PACKING_TYPE` 은 20261016_007 에서 만들었다.
- 기존 자료를 상세코드로 옮겼다.
  - `packing_methods` 3건 → `PACKING_TYPE` 상세 001~003
  - `vehicles` 2건 → `VEHICLE` 상세 001~002
  - 원래 id 순서대로 정렬순서를 붙였다. 이름은 같다. 같은 이름이 이미 있으면 넣지 않는다.
- 공통코드 상세 자동 번호 카운터(`tb_id_sequence`, `COMMON_CODE_ITEM_CODE` · 그룹 id)를 넣은 최댓값(3, 2)까지 올렸다. 화면에서 이어 넣으면 004 · 003 부터 매겨진다.
- 이 작업이 넣은 그룹 · 상세 id 는 `bak_20261019_003_common_code` 에 남긴다.
- 옛 표 `packing_methods` · `vehicles` 는 지우지 않았다. 이제 어느 코드도 읽지 않는다.

## 영향 범위

- 출하확정(물류관리)의 포장방법 · 배차 목록이 공통코드 상세에서 온다.
  - 출하확정은 이름(글자)으로 저장하므로, 이미 저장된 값과도 그대로 맞는다.
- 목록을 바꾸려면 공통코드 관리(공통관리 > 기초정보 > 공통코드 관리)에서 `PACKING_TYPE` · `VEHICLE` 상세를 고친다.

## 확인

- 한 트랜잭션 안에서 다음을 차례로 했다.
  1. 적용: 그룹 2개, 상세 3 · 2건. 이름 · 순서가 옛 표와 같고, 번호표 3 · 2, 백업 group 1 · item 5
  2. 다시 적용: 같은 결과
  3. 롤백 스크립트: 상세 0건, VEHICLE 그룹 없어짐
  4. ROLLBACK
- ROLLBACK 후 공통코드 그룹 · 상세 · 번호표 · 백업 표가 시험 전과 같았다.
- 그 뒤 적용했다.
