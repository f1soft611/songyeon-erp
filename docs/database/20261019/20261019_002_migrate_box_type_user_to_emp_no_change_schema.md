# 20261019_002 tb_box_type 등록자 · 수정자를 사번으로 바꿈 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-19 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경 + 백업 표 추가(`bak_20261019_002_box_type_user`) |
| 대상 표 | `tb_box_type.reg_user_id` · `upd_user_id` (읽기: `employees`) |
| 적용 | 2026-10-19 적용 완료 (트랜잭션 시험 실행 후 적용) |
| 롤백 | `20261019_002_rollback.sql` (백업 값으로 되돌리고 백업 표 삭제) |

## 내용

- 요청: "아이디가 0000 으로 저장되고 조회할때 사원테이블이랑 조인해서 관리자를 가져와서 보여주고싶은데"
- `0000` 은 사원 표의 사번(`employees.emp_no`)이다.
  - 사원마다 다르다(유일 인덱스 `idx_employees_emp_no`).
  - '관리자' 는 같은 사원의 로그인 아이디(`employees.username`)다.
- 코드를 바꿨다.
  - 서비스가 로그인한 사원(`LoginVO.uniqId` = `employees.id`)의 사번을 찾아 등록자 · 수정자에 넣는다.
  - 조회는 `employees` 와 사번으로 이어 붙여 이름을 보여준다. 사원 표에 없는 값은 저장된 값 그대로 보여준다.
- 이 SQL 은 이미 로그인 아이디로 들어간 값을 사번으로 바로잡는다.
  - 로그인 아이디와 같은 값(사번이 있는 사원)만 바꾼다. 해당 1줄(`box_type_id` 2 의 수정자)이다.
  - 사원 표에 없는 값(샘플의 등록자 `admin`)은 그대로 둔다.
- 수정일시(`upd_dt`)는 바꾸지 않는다. BEFORE UPDATE 트리거가 `now()` 로 덮기 때문에, 이 작업 동안만 트리거를 끄고 끝나면 다시 켠다.
- 바꾸기 전 값은 `bak_20261019_002_box_type_user`(`box_type_id`, `reg_user_id`, `upd_user_id`, `backed_up_at`)에 남긴다.

## 영향 범위

- 포장유형 그리드의 등록자 · 수정자 칸이 사원 이름으로 보인다.
- 다른 표는 바뀌지 않는다.

## 확인

- 한 트랜잭션 안에서 다음을 차례로 했다.
  1. 적용: 2번 줄 수정자 '아이디' → '사번', 수정일시 10:35:53 그대로, 트리거 다시 켜짐, 백업 1줄
  2. 조회 SQL: 수정자 이름이 사원 이름으로 나옴
  3. `selectEmpNo`: 사번이 나옴
  4. 다시 적용: 같은 결과
  5. 롤백 스크립트: '아이디' 로 되돌아가고 백업 표 없어짐
  6. ROLLBACK
- ROLLBACK 후 DB 가 시험 전과 같았다(표 · 백업 표 · 트리거 상태).
- 그 뒤 적용했다. 개발 모드 8080 API: 2번 줄 수정자 `0000` → 이름 '관리자'
