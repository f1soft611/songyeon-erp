# 20261019_006 기본창고 전체 한 곳 정리 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-19 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 정리 (스키마 변경 없음) |
| 대상 표 | `tb_warehouse.default_yn` (백업 표 `bak_20261019_006_warehouse_default`) |
| 적용 | 적용하지 않음. 확인할 때 DB 는 이미 기본창고가 한 곳(원자재)뿐이라 바꿀 줄이 0줄이었다. 다른 DB 에 같은 규칙을 맞출 때 쓰려고 남긴다 |
| 롤백 | `20261019_006_rollback.sql` |

## 내용

- 요청: "창고코드 화면에서 안 보여야 하는데 기본창고도 하나만 선택되어야 하고"
- 결정(사용자): 원자재 기본창고만 남기고, 기본창고는 전체에서 한 곳으로 둔다. 기본창고 = 입고창고(유형과 상관없이)
- 스크립트
  - 사업장 · 사업부마다 사용 중인 기본창고 가운데 한 곳만 남긴다.
    - 남기는 차례: 원자재 → 정렬순서 → id
  - 나머지는 `default_yn = 'N'` 으로 끈다. 감사 칸은 건드리지 않는다.
  - 끄기 전 값은 백업 표에 남긴다. 다시 돌려도 결과가 같다.
- 표 정의는 바꾸지 않았다.
  - 설계자 표의 `ux_wh_default` 는 유형마다 한 곳까지 허용한다.
  - 전체 한 곳은 서비스(`WarehouseServiceImpl`)와 화면이 지킨다.
  - 표로 막으려면 설계자와 인덱스 변경을 정해야 한다.

## 영향 범위

- 창고등록: 기본창고를 켜면 유형과 상관없이 다른 기본창고를 끈다. 마지막 한 곳은 끄거나 지울 수 없다.
- 입고창고를 읽는 입고 · 재고조정 · 재고 현황 매퍼: `default_yn = 'Y'` 인 사용 중 창고(유형 조건 뺌). 재고조정의 '다른 창고'는 `default_yn = 'N'`.

## 확인

- 한 트랜잭션 안에서 적용 → 다시 적용(같음) → 롤백 스크립트(원래대로) → ROLLBACK 을 했다.
  - 기본창고 1곳 → 1곳. 백업 0줄. 수정일시 그대로
  - 입고창고 쿼리는 한 줄을 돌려줬다.
- ROLLBACK 뒤 DB 는 시험 전과 같았다.
- 같은 날 앞선 확인(005)에서는 기본창고가 7곳(유형마다 하나)이었다.
  - 이번 확인 때는 1곳이었고, 수정일시 · 수정자는 비어 있었다.
  - 창고등록 화면이 아니라 DB 에서 직접 바뀐 것으로 보인다.
