# 20261026_006 출하확정 운행자를 사번으로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(직원 이름 → 사번) · 컬럼 이름 변경 · 백업 표 추가 |
| 대상 표 | `logistics_schedule` · `production_schedule`(`driver_name` → `driver_id`), 백업 `bak_20261026_006_ship_driver`(새 표) |
| 적용 | 2026-10-26 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261026_006_rollback.sql` |

## 내용

- 요청: "driver_name 도 사번으로 들어가야됳거같은데"
- 사용자 결정: 직원만 사번으로 저장(직원이 아닌 운행자는 막는다), 칸 이름도 `driver_id` 로
- 바뀐 모양: 두 표 모두 칸 이름 `driver_name` → `driver_id`(자리 · 형식 text 그대로), 값은 직원 이름 → 사번(`employees.id`)
  - 같은 이름의 직원이 여럿이면 사번이 작은 것(서버 저장 규칙과 같다).
- 직원 목록에 없는 이름이 있으면 멈춘다(적용 때 0건).
- 결과(개수만): 출하등록 1건이 사번으로 바뀌었다(직원 목록과 이어짐). 생산 쪽은 값이 없었다. 나머지 값은 같다. 백업 표 1건.

## 영향 범위

- 출하확정 · 출하현황 매퍼는 사번으로 직원 이름을 붙여 읽는다(`driverName` 그대로).
- 출하확정 저장: 화면은 그대로 직원 이름을 보내고, 서버가 사번으로 바꿔 남긴다. 비우면 비운다.
  - 직원 목록에 없는 이름은 재고를 움직이기 전에 막는다: "직원 목록에 있는 운행자를 골라주세요(용차 기사는 용차정보에 적어주세요)"
- 직원 이름이 바뀌면 저장된 줄의 화면 표시도 따라 바뀐다(사번으로 이어지므로).
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다.
- 롤백하면 `driver_name`(이름)으로 돌아간다. 사번이 그대로인 줄은 백업의 예전 이름, 나머지는 직원 목록 이름이 들어간다. 서버 코드도 함께 돌려야 한다.
