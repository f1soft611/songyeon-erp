## 내용

- 요청: "product_label_versions 테이블에 \"storage\"이것도 코드값으로 들어가야될듯" → 사용자 결정: 공통코드에서만 고르기
- 바뀐 값(칸 이름 · 자리 · 형식 text 그대로)
  - 코드면 그대로, 공통코드 이름과 같으면 그 코드, 아니면 글자에 든 앞말(실온 · 냉장 · 냉동)로 찾은 코드(예: '냉장보관(0℃~10℃)' → 냉장 코드).
  - 빈 값은 그대로. 어느 코드와도 맞지 않는 글자가 있으면 멈춘다.
- 송연 DB 확인(개수만): 처음 확인 때 라벨 버전 1건이 글자였는데, 스크립트를 미리 돌려 볼 때는 이미 코드로 바뀌어 있었다(사용자가 바꾼 것으로 본다). 라벨 요청은 값이 없었다. 그래서 적용하지 않았다(백업 표도 만들지 않았다).
- 시험 실행: 적용 · 다시 적용 결과가 같았다. 롤백은 코드를 공통코드 이름으로 바꾼다.

## 영향 범위

- 라벨등록 창: 보관방법은 공통코드 `STORAGE_METHOD` 목록에서만 고른다(직접 입력 없음). 저장은 코드, 미리보기 · 인쇄에는 공통코드 이름이 찍힌다.
  - 예전 목록 문구('냉장보관(0℃~10℃)')가 아니라 공통코드 이름('냉장(0℃~10℃)')이 찍힌다.
- 서버: 라벨 내용 저장 · 요청 저장 · 요청을 버전으로 옮기기 · v1 자동 생성(제품의 보관방법 이름을 받는다)에서 위 규칙으로 코드로 바꿔 저장한다.
- 사용중 버전을 제품(`products.storage`)으로 베낄 때: 버전의 코드를 그대로 쓴다(맞는 코드가 없으면 제품 값 그대로).
- 롤백하면 글자로 돌아간다. 서버 코드와 화면도 함께 돌려야 한다.
