# 20261026_004 출하등록 거래처 · 품목을 코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL 18) |
| 유형 | 데이터 변환(거래처명 → 거래처코드) · 컬럼 삭제(`product_name`) · 표 다시 만들기(칸 자리 옮김) · 백업 표 추가 |

| 롤백 | `20261026_004_rollback.sql` |

## 내용

- 요청: "logistics_schedule 테이블도 확인"(생산확정 · 수주 20261026_001 ~ 003 이어서)
- 사용자 결정: 똑같이 바꿈, DB 는 Claude 가 스크립트로
- 바뀐 모양
  - 칸 차례: `id` · `schedule_date` · `client_code` · `product_code` · `order_qty` · `note` · …(`product_code` 가 맨 끝에서 4번째로)
  - `client_name`(거래처명) → `client_code`(거래처마스터 거래처코드). 같은 이름이 여럿이면 코드가 작은 것.
  - `product_name`(품명(규격))은 지웠다. 품목은 `product_code` 로만 남는다.
- 표를 새로 만들어 값을 옮겼다.
  - id 시퀀스 `logistics_schedule_id_seq` 를 그대로 이어 쓴다. id 가 그대로라 `shipment_lot_allocation` · `delivery_carryover` · 재고 원장이 가리키는 줄도 그대로다.
  - 기본값(`ship_confirmed` = 0) · NOT NULL · 기본키 · 인덱스(`idx_logistics_schedule_product_code`)를 예전 이름 그대로 다시 만들었다.
  - 이 표를 가리키는 FK · 뷰 · 트리거는 없었다.
- 멈추는 경우: 거래처마스터에 없거나 코드 없는 거래처명, 품목명은 있는데 제품코드가 비었거나 제품마스터에 없는 줄(적용 때 0건)
- 결과(개수만): 4건 모두 거래처코드로 바뀌었고 거래처마스터와 이어진다. 4건 모두 제품코드가 있고, 지우기 전 품목명과 제품마스터 '품명(규격)' 이 같았다. 나머지 값 · 제약 · 인덱스 · 시퀀스는 같다. 백업 표 4건.

## 영향 범위

- 서버 매퍼 6개 파일(출하등록 · 출하확정 · 출하현황 · 판매등록 · 매출매입 · 물류스케줄)은 코드로 거래처명 · 품목명을 붙여 읽는다. 화면에 주고받는 값(`clientName` · `productName`)은 그대로다.
  - 출하현황 품목 · 거래처 검색, 판매등록 거래처 검색도 붙인 이름으로 찾는다.
- 출하등록 저장: 서버가 거래처명 · 품목명을 코드로 바꿔 남긴다. 못 바꾸면 '거래처코드가 있는 거래처를 골라주세요' · '제품마스터에 등록된 품목을 골라주세요' 로 막는다(수주와 같은 규칙).
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다.
- 롤백하면 예전 모양으로 돌아간다. 코드가 그대로인 줄은 백업의 예전 이름, 바뀐 줄 · 새 줄은 거래처마스터 · 제품마스터 이름이 들어간다. 서버 코드도 함께 돌려야 한다.
