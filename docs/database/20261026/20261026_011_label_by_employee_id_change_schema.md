# 20261026_011 라벨 버전 · 라벨 요청 '누가' 칸을 사번으로 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(직원 이름 → 사번) · 백업 표 추가 |
| 대상 표 | `product_label_versions`(`created_by` · `updated_by`), `label_requests`(`updated_by`), 백업 `bak_20261026_011_label_by`(새 표) |
| 적용 | 2026-10-26 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261026_011_rollback.sql` |

## 내용

- 요청: "product_label_versions 여기 테이블에 created_by 값이 안 들어가는거 같아" → 사용자 결정: 사번으로 채우기
- 원인: 라벨 버전을 처음 만들 때(v1 자동 생성 — 라벨 버전 목록을 처음 열 때, 라벨등록에서 처음 저장할 때) `created_by` 를 채우지 않았다. '새 버전' 으로 만들 때만 로그인 이름이 들어갔다.
- 바꾼 값: 세 칸 모두 직원 이름 → 사번(칸 이름 · 자리 그대로). 같은 이름이 여럿이면 사번이 작은 것.
- 결과(개수만): `product_label_versions.updated_by` 1건이 사번으로 바뀌었다. `created_by` 는 비어 있는 1건뿐이라(누가 만들었는지 모름) 그대로 두었다. `label_requests.updated_by` 는 값이 없었다. 백업 1건.

## 영향 범위

- 라벨(`/api/v1/qm/label`) · 라벨등록(`/api/v1/qm/label-register`) 서버가 로그인한 사원의 사번을 넣는다(v1 자동 생성 · 새 버전 · 내용 저장 · 양식 저장 · 요청 저장 · 요청 옮기기).
- 라벨 버전 목록 · 한 버전 · 라벨 요청은 사번으로 직원 이름을 붙여 보여 준다(화면의 '만든 사람' 은 그대로 이름).
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다.
- 롤백하면 이름으로 돌아간다. 서버 코드도 함께 돌려야 한다.
