# 20261026_003 수주 거래처 · 품목을 코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL 18) |
| 유형 | 데이터 변환(거래처명 → 거래처코드) · 컬럼 삭제(`product_name`) · 표 다시 만들기(칸 자리 옮김) · 백업 표 추가 |
| 대상 표 | `sales_order`, 백업 `bak_20261026_003_sales_order`(새 표) |
| 적용 | 2026-10-26 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261026_003_rollback.sql` |

## 내용

- 요청: "sales_order테이블도 확인해줘"(생산확정 20261026_001 · 002 이어서)
- 사용자 결정: 생산확정과 똑같이, DB 는 Claude 가 스크립트로
- 바뀐 모양
  - 칸 차례: `id` · `order_date` · `client_code` · `product_code` · `order_qty` · `note` · …(`product_code` 가 맨 끝에서 4번째로)
  - `client_name`(거래처명) → `client_code`(거래처마스터 거래처코드). 같은 이름이 여럿이면 코드가 작은 것(서버 저장 규칙과 같다).
  - `product_name`(품명(규격))은 지웠다. 품목은 `product_code` 로만 남는다.
- 표를 새로 만들어 값을 옮겼다(PostgreSQL 은 칸 자리를 바로 옮길 수 없다).
  - id 시퀀스 `sales_order_id_seq` 를 그대로 이어 쓴다.
  - 기본값(`imported` · `imported_production` · `imported_shipment` · `is_stock_production` = 0) · NOT NULL · 기본키 · 인덱스(`idx_sales_order_product_code`)를 예전 이름 그대로 다시 만들었다.
  - 이 표를 가리키는 FK · 뷰 · 트리거는 없었다.
- 멈추는 경우: 거래처마스터에 없거나 코드 없는 거래처명, 품목명은 있는데 제품코드가 비었거나 제품마스터에 없는 줄(적용 때 0건)
- 결과(개수만)
  - 7건 모두 거래처코드로 바뀌었고, 7건 모두 거래처마스터와 이어진다.
  - 7건 모두 제품코드가 있고, 지우기 전 품목명과 제품마스터 '품명(규격)' 이 같았다.
  - 거래처 · 품목명을 뺀 나머지 값은 바꾸기 전과 같다. 제약 · 인덱스 · 시퀀스도 같다.
  - 백업 표 7건(바꾸기 전 표 전체).

## 영향 범위

- 서버 매퍼 3개 파일(`sa/order` · `pd/confirm` 수주 가져오기 · `sa/shipment` 수주 가져오기 · 생산예정 수주)은 코드로 거래처명 · 품목명을 붙여 읽는다. 화면에 주고받는 값(`clientName` · `productName`)은 그대로다.
- 수주 저장: 화면은 그대로 거래처명 · 품목명을 보내고, 서버가 코드로 바꿔 남긴다.
  - 코드 없는 거래처는 '거래처코드가 있는 거래처를 골라주세요' 로 막는다.
  - 제품마스터에 없거나 '이름(규격)' 이 같은 제품이 둘이라 하나로 정해지지 않는 품목명은 '제품마스터에 등록된 품목을 골라주세요' 로 막는다(예전에는 코드 없이 이름만 저장했다). 지금 제품마스터에는 '이름(규격)' 이 겹치는 제품이 없다.
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다.
- 롤백하면 예전 모양으로 돌아간다. 코드가 그대로인 줄은 백업의 예전 이름, 바뀐 줄 · 새 줄은 거래처마스터 · 제품마스터 이름이 들어간다. 서버 코드도 함께 돌려야 한다.
