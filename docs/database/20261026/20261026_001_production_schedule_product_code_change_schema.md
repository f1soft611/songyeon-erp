# 20261026_001 생산확정 품목명 칸 삭제 · 제품코드 자리 옮김 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL 18) |
| 유형 | 컬럼 삭제(사용자 직접) · 표 다시 만들기(칸 자리 옮김) · 백업 표 추가 |
| 대상 표 | `production_schedule`(`product_name` 삭제, `product_code` 자리 이동), 백업 `bak_20261026_001_production_schedule`(새 표) |
| 적용 | 2026-10-26 적용 완료. `product_name` 삭제는 사용자가 직접 했고, 스크립트는 다른 DB 에 똑같이 하기 위한 기록이다. 자리 옮김은 트랜잭션 시험 실행(다시 적용해도 같음, 롤백 확인) 뒤 적용 |
| 롤백 | `20261026_001_rollback.sql` |

## 내용

- 요청: "production_schedule 테이블에서 product_name컬럼을 지웠어 이제 product_code로 product_name찾게 해주고 컬럼 위치도 client_name 뒤였으면 좋겠어"
- 사용자 결정: DB 작업은 Claude 가 스크립트로
- 스크립트(적용 순서)
  1. `20261026_001_drop_production_schedule_product_name.sql`(기록용): `product_name` 을 지운다. 제품코드가 비었거나 제품마스터에 없는 줄이 있으면 멈춘다.
  2. `20261026_001_reorder_production_schedule_product_code.sql`: 표를 새로 만들어 `product_code` 를 `client_name` 바로 뒤(4번째)로 옮긴다.
- 자리 옮김 방법: PostgreSQL 은 칸 자리를 바로 옮길 수 없다. 새 표 → 값 옮김 → 예전 표 지움 → 이름 바꿈 순으로 했다.
  - id 시퀀스 `production_schedule_id_seq` 를 그대로 이어 쓴다(새 번호가 처음부터 시작하지 않는다).
  - 칸 형식 · 기본값(`ship_confirmed`, `is_stock_production` = 0) · NOT NULL · 기본키 · 인덱스 4개는 예전 이름 그대로 다시 만들었다.
  - 이 표를 가리키는 FK · 뷰 · 트리거는 없었다.
- 결과(개수만)
  - 5건 모두 옮겼다. 값 해시 · 칸 정의 · 제약 · 인덱스 · 시퀀스가 바꾸기 전과 같다(자리만 다르다).
  - 5건 모두 `product_code` 가 제품마스터와 이어진다.
  - 백업 표 5건.
- 시험 실행 중 새 줄 넣기를 해 본 탓에 시퀀스가 1 올라갔다(번호 하나 건너뜀, 동작 영향 없음).

## 영향 범위

- 서버 매퍼 13개 파일: 품목명은 `products` 에서 '품명(규격)'(규격이 없으면 품명)으로 붙인다. 수주 · 출하등록에 적힌 이름과 같은 모양이다.
  - 생산확정 · 생산입고 · 생산현황 · 라벨출력 · 재료치환 · 출하등록 · 출하확정 · 출하현황 · 제품재고 · 판매등록 · 판매현황 · 매출매입 · 생산/물류 스케줄
  - 제품마스터 · 거래처품목의 '마지막 생산일' 은 제품코드로 찾는다.
- 생산확정 저장
  - 화면은 그대로 품목명을 보내고, 서버가 제품코드로 바꿔 남긴다.
  - 제품마스터에 없는 품목명은 '제품마스터에 등록된 품목을 골라주세요' 로 막는다(지우면 품목이 사라지므로).
  - 로트번호 회차는 같은 날 · 같은 제품코드 안에서 센다.
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다(예전 표를 가리키던 연결 · 예전 매퍼).
- 롤백하면 `product_name` 을 4번째 자리에 되살리고 제품마스터 이름으로 채운다. 지울 때 따로 남긴 값이 없어 예전 글자와 다를 수 있다. 서버 코드도 함께 돌려야 한다.
