## 내용

- 요청: "sales_record 테이블의 client_name,product_name,created_by 이것도 코드값으로"
- 사용자 결정: 마스터에 있는 것만 저장(직접 추가 판매도 거래처마스터 · 제품마스터에 없으면 막는다). `created_by` 는 칸 이름 그대로 값만 사번
- 바뀐 모양(칸 자리 · 형식 text 그대로, 이름만 바꿈)
  - `client_name` → `client_code`: 거래처명 → 거래처코드(같은 이름이 여럿이면 코드가 작은 것)
  - `product_name` → `product_code`: '품명(규격)' · '품명 (규격)' · 품명 → 제품코드(여럿이면 코드가 작은 것)
  - `created_by`: 등록자 이름 → 사번(`employees.id`)
- 마스터 · 직원 목록에 없는 값이 있으면 멈춘다(적용 때 0건).
- 결과(개수만): 2건 모두 거래처코드 · 제품코드 · 사번으로 바뀌었고 모두 마스터 · 직원과 이어진다. 나머지 값은 같다. 백업 표 2건.

## 영향 범위

- 판매현황 · 토탈집계(`sl/status` 매퍼 `selectRecords`)는 코드로 거래처명 · 품목명 · 등록자 이름을 붙여 읽는다(`clientName` · `productName` · `createdBy` 그대로). 거래처 · 품목 검색과 정렬도 붙인 이름으로.
- 판매등록
  - 출하에서 끌어오기: 출하 줄의 거래처코드 · 제품코드를 그대로 저장한다.
  - 직접 추가: 화면이 보낸 이름을 코드로 바꾼다. 없으면 '거래처마스터에 있는 거래처를 적어주세요' · '제품마스터에 있는 품목을 적어주세요'.
  - 등록자는 로그인한 사원의 사번(`LoginEmployeeResolver`). 예전에는 로그인 이름이었다.
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다.
- 롤백하면 이름으로 돌아간다. 값이 그대로인 줄은 백업의 예전 값, 새 줄은 마스터 · 직원 이름이 들어간다. 서버 코드도 함께 돌려야 한다.
