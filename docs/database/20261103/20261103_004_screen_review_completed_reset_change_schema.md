# 20261103_004 화면검수 검수완료 후 미검수 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-03 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 바꾸기(표 구조 그대로) |
| 대상 표 | `tb_screen_review` |
| 적용 | 2026-11-03 적용 완료(시험 실행 통과: 검수완료 1줄 → 미검수 · 요청일 비움, 이력 8줄 그대로, 다시 적용해도 같음, 롤백하면 처음과 같음) |
| 롤백 | `20261103_004_rollback.sql` |

## 내용

- 요청: 검수완료로 한 바퀴(수정요청 → 검수진행중 → 검수완료)가 끝나면 화면 상태는 미검수로 돌아간다.
- 설계: [20261103_004_화면검수_완료후_미검수_설계서.md](../../spec/20261103/20261103_004_화면검수_완료후_미검수_설계서.md)
- 서버가 검수완료 저장 때 현황을 미검수 · 요청일 · 개발담당 · 개발완료일 비움으로 저장한다(이력에는 검수완료 줄이 남는다). 적용 때 남아 있던 검수완료 1줄은 개발담당 · 개발완료일이 원래 비어 있어 스크립트는 상태 · 요청일만 바꿨다. 이 스크립트는 이미 검수완료로 남아 있는 현황을 같은 모양으로 맞춘다.
- 롤백: 마지막 이력이 검수완료인 미검수 현황을 검수완료로, 요청일은 마지막으로 수정요청으로 바꾼 날(수정요청 추가 제외)로 되돌린다.

## 같이 바뀐 코드

| 영역 | 위치 |
|---|---|
| 백엔드 | `ScreenReviewServiceImpl.save`(검수완료면 현황 `NOT_STARTED` · 요청일 `NULL` · `resetCycle`), 매퍼 `ScreenReview_SQL_postgresql.xml` `updateReview`(요청일 `jdbcType=VARCHAR`, `resetCycle`이면 개발담당 · 개발완료일 `NULL`) |
| 프론트 | 바뀌지 않음 |

## 영향 범위

- `tb_screen_review` 상태 · 요청일만 바뀐다. 배포: war 와 함께 올린다(예전 war 는 다음 검수완료를 다시 검수완료로 남긴다).
