# 20261105_003 제품 식품유형을 공통코드(FOOD_TYPE) 코드로 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-05 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(이름 → 코드, 맞지 않는 글자는 비움) + 백업 표 추가 + 컬럼 설명 |
| 대상 표 | `products.food_type`, 백업 `bak_20261105_003_product_food_type`(새 표) |
| 적용 | 미적용 (시험 실행 후 사용자 승인 대기) |
| 롤백 | `20261105_003_rollback.sql` |

## 내용

- 요청: "제품등록 화면에서 식품유형 추가해야겠다". 저장 방식은 사용자 결정 "코드로 저장"(보관방법 `20261023_012` 와 같은 방식).
- 공통코드(SONGYEON, 사용자가 만든 것): 그룹 `FOOD_TYPE`(식품유형) — 001 복합조미식품 · 002 소스(살균제품) · 003 향신료조제품
- `products.food_type`: 코드면 그대로, 공통코드 이름과 똑같은 글자면 그 코드, 어느 것과도 맞지 않는 글자는 비운다(사용자 결정 2026-11-05 "지워버려"). 빈 값은 그대로.
- 적용 전 상태: 값이 있는 제품 1건(`조미식품`)은 공통코드에 없어 비워진다(백업 1건).
- 라벨 표의 식품유형은 `20261105_004` 에서 바꾼다.
- 계획 · 사양: [20261105_006](../../plan/20261105/20261105_006_제품등록_식품유형_공통코드_계획사양서.md), [20261105_007](../../plan/20261105/20261105_007_제품마스터_라벨_식품유형_공통코드_계획사양서.md)

## 영향 범위

- 제품등록 · 제품마스터 창은 식품유형을 코드로 저장한다(서버가 공통코드 사용 중 코드만 받는다, 비워 둘 수 있다).
- 라벨(예전 방식 `selectProductLabel`)은 `foodType` 을 이름으로 돌려준다(코드가 아니면 글자 그대로).
- 라벨 버전 확정(`copyVersionToProducts`)은 라벨 값이 FOOD_TYPE 코드 · 이름과 같으면 그 코드를, 아니면 제품 값을 그대로 둔다.
- 롤백하면 백업된 제품이 원래 글자로 돌아간다. 적용 뒤 새로 저장한 제품은 백업에 없어 코드로 남는다. 서버 · 화면 코드도 함께 돌려야 한다.
