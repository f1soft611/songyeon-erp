# 20260915_002 커뮤니티 네이밍 기준 문서

## 1. 목적

그룹웨어 하위의 커뮤니티 기능은 공지사항, 게시판, 자료실을 하나의 구조로 통합 관리하기 위해 일관된 명칭 기준을 적용한다.

이 문서는 메뉴명, 코드명, 게시판 타입, 권한명, URL 경로의 네이밍 규칙을 정의한다.

---

## 2. 기본 구조

### 2-1. 모듈 구조

- 모듈: `GROUPWARE`
- 중메뉴: `커뮤니티`
- 하위 메뉴: `공지사항`, `게시판`, `자료실`

예시 트리:

```text
그룹웨어
└── 커뮤니티
    ├── 공지사항
    ├── 게시판
    └── 자료실
```

---

## 3. 명칭 기준

### 3-1. 메뉴명

메뉴명은 사용자에게 노출되는 표준 명칭을 사용한다.

| 구분      | 표준 명칭 | 비고                          |
| --------- | --------- | ----------------------------- |
| 모듈      | 그룹웨어  | 기존 프로젝트 기본 구조 유지  |
| 중메뉴    | 커뮤니티  | 통합 공지/게시/자료 관리 영역 |
| 하위 메뉴 | 공지사항  | 공지 전용                     |
| 하위 메뉴 | 게시판    | 일반 커뮤니케이션             |
| 하위 메뉴 | 자료실    | 파일/문서 공유                |

권장 원칙:

- 사용자용 명칭은 한글 우선
- 설명 문구는 보조적으로 영어/코드로 붙임
- 내부 코드와 화면 텍스트를 혼용하지 않음

### 3-2. 코드명

코드는 내부 시스템 식별용으로 사용하며, 다음 규칙을 따른다.

| 항목        | 코드 규칙              | 예시                                  |
| ----------- | ---------------------- | ------------------------------------- |
| 모듈 코드   | 대문자 + 언더스코어    | `GROUPWARE`                           |
| 중메뉴 코드 | `GW_` 접두 + 의미 단어 | `GW_COMMUNITY`                        |
| 게시판 코드 | `GW_` 접두 + 의미 단어 | `GW_NOTICE`, `GW_BOARD`, `GW_ARCHIVE` |
| 권한 코드   | 대문자 + 언더스코어    | `BOARD_VIEW`, `BOARD_WRITE`           |

권장 규칙:

- 영문은 축약형보다 의미 기반 네이밍 우선
- 코드명은 사용자에게 직접 노출하지 않음
- 동일 기능은 중복 코드 사용 금지

### 3-3. URL 경로

URL은 기능 경로를 의미 있게 구성한다.

| 메뉴          | URL 예시                       |
| ------------- | ------------------------------ |
| 그룹웨어 루트 | `/groupware`                   |
| 커뮤니티      | `/groupware/community`         |
| 공지사항      | `/groupware/community/notice`  |
| 게시판        | `/groupware/community/board`   |
| 자료실        | `/groupware/community/archive` |

권장 규칙:

- 경로는 소문자로 통일
- 단어 구분은 `-` 또는 `/` 구조로 유지
- `community`는 전반적으로 `info-center`보다 더 자연스럽고 기능 중심적임

### 3-4. 게시판 타입

DB에서 게시판 유형은 내부 식별값으로 사용한다.

| 게시판 타입 | 의미     |
| ----------- | -------- |
| `NOTICE`    | 공지사항 |
| `BOARD`     | 게시판   |
| `ARCHIVE`   | 자료실   |

권장 규칙:

- 게시판 타입은 표시명과 별개로 영문 상수로 관리
- `board_kind` 값은 `notice`, `board`, `archive`를 사용

---

## 4. 권한 네이밍

권한 코드는 기능 단위로 작성한다.

| 권한 코드      | 의미        |
| -------------- | ----------- |
| `BOARD_VIEW`   | 조회 권한   |
| `BOARD_WRITE`  | 등록 권한   |
| `BOARD_DELETE` | 삭제 권한   |
| `BOARD_UPLOAD` | 업로드 권한 |

권장 규칙:

- 기능 단위로 분리해서 관리
- 게시판 유형별로 공통 권한을 재사용
- 권한명은 `조회`, `등록`, `삭제`, `업로드`와 같이 기능 중심으로 작성

---

## 5. 네이밍 우선순위

다음 우선순위를 따른다.

1. 기존 시스템 구조와 일치: `GROUPWARE` 유지
2. 사용자 친화적 명칭: `커뮤니티` 우선
3. 기능 의미 명확화: `공지사항`, `게시판`, `자료실`
4. 내부 코드 통일성: `GW_` + 의미 단어 유지
5. 확장성: 추후 FAQ, Q&A, 이벤트 등 추가 가능

---

## 6. 최종 권장 표기

### 최종 예시

- 모듈: `GROUPWARE`
- 중메뉴: `커뮤니티`
- 코드: `GW_COMMUNITY`
- 하위 메뉴:
  - `GW_NOTICE` → 공지사항
  - `GW_BOARD` → 게시판
  - `GW_ARCHIVE` → 자료실

### 경로 예시

```text
/groupware/community
/groupware/community/notice
/groupware/community/board
/groupware/community/archive
```

---

## 7. 적용 원칙

- 사용자에게 보여지는 텍스트는 `커뮤니티`를 우선 사용한다.
- 내부 코드와 상수는 `GW_COMMUNITY`/`GW_NOTICE` 형식으로 유지한다.
- 기능이 추가되더라도 커뮤니티 하위 구조를 유지한다.
- “정보센터”라는 표현은 사용하지 않는다.

---

## 8. 결론

기존 구조와 사용자 이해를 모두 고려하면, “정보센터”보다 “커뮤니티”가 더 적합하다.

최종 표준은 다음과 같다.

```text
그룹웨어 > 커뮤니티 > 공지사항 / 게시판 / 자료실
```
