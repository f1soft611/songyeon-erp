# 20261021_001 권한관리: 송연 사원 계정 · 역할 적용 작업지시서

## 요청 (2026-10-21)

- "S_ERP 랑 동일하게 권한관리 들어갈 거고, 여기서는 employees 테이블 보면 될 것 같은데"
- "송연에 따로 테이블을 내가 새로 만들고 싶지는 않고 최대한 S_ERP 랑 동일한 구조로 가고 싶어"
- S_ERP 는 업체가 업체 계정으로 쓰고, 송연은 업체의 직원이 쓰는 프로그램이다.

## 사용자 결정

| 항목 | 결정 |
| --- | --- |
| 적용 범위 | S_ERP 처럼 실제 적용. 로그인 사원의 역할로 메뉴 · 단추 권한을 준다 |
| 표 구조 | 새 표를 만들지 않는다. S_ERP 표(`tb_login_account` · `tb_login_account_role` · `tb_role` · `tb_role_menu_permission`)를 그대로 쓴다 |
| 계정 | 안 "가": 직원마다 `tb_login_account` 한 줄(`login_code` = 사번). 로그인 · 비밀번호 · 역할은 계정 표, 이름 · 부서는 `employees`. `tb_user` 는 쓰지 않는다 |
| 사용자 매핑 그리드 | 퇴사자는 뺀다. 최근 로그인 칸은 빈 값 |
| 역할이 없는 사원 | 로그인은 되지만 메뉴는 없다 |
| 인사관리에서 계정을 처음 만들 때 | '일반 사용자(DEFAULT_USER)' 역할을 자동으로 붙인다 |

## 완료 조건

1. 지금 계정이 있는 직원(`0000`)이 같은 사번 · 비밀번호로 로그인되고, 지금과 같은 메뉴 · 단추가 보인다(시스템 관리자 역할).
2. 권한관리 > 권한별 사용자 매핑에 재직 중이고 계정이 있는 직원이 나오고, 매핑 여부를 켜고 끈 뒤 [저장]하면 `tb_login_account_role` 에 반영된다.
3. 역할이 없는 계정은 로그인되지만 메뉴가 보이지 않고, 관리자 API 를 쓸 수 없다.
4. 인사관리에서 계정을 만들면 계정 표에 한 줄과 일반 사용자 역할이 생기고, 계정을 거두면 계정 표 줄과 역할 연결이 지워진다.
5. 내 정보에서 비밀번호를 바꾸면 계정 표의 비밀번호로 로그인된다.
6. DB 변경은 날짜별 SQL · 변경 이력 · 롤백을 `docs/database/20261021` 과 `backend/DATABASE/20261021` 에 같이 남기고, 시험 실행 후 적용한다.
7. 결과 문서와 스크린샷을 `docs/result/20261021/settings-role-employee` 에 남긴다.

## 하지 않는 것

- `tb_user` · `tb_department` 채우기, 로그인 화면 모양 · 문구 변경
- `employees.is_admin` · `employees.permissions` 칸 정리(그대로 둔다)
- 서버 쪽 로그인 잠금(지금도 없음)
- S_ERP 수정
