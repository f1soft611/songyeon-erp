## 지금 상태

- 메뉴 권한은 내 메뉴 응답(`permissions { read, create, update, delete, excel }`)으로 화면에 `selectedMenuPermissions` 로 들어온다.
- 메뉴관리 기본기능 칸: 읽기(READ) · 쓰기(CREATE + UPDATE) · 삭제(DELETE) · 엑셀(EXCEL).
- 제목줄 단추는 대부분 이미 권한을 본다. 안 보는 것
  - 그리드 오른쪽 클릭 [행 추가] · [루트 추가] · [행 삭제](공통코드 · 포장유형 · 창고 · 모듈): 항상 켜짐
  - 셀 편집 · 체크 칸: 항상 됨
  - 화면 안 단추: 제품 · 원재료 · 부자재 줄 [수정] 등, 원재료 · 부자재 [엑셀 다운로드], 거래처 [엑셀 양식 내려받기] · [엑셀 올리기], 거래처 창 [저장] · [삭제]
  - 포장유형 · 창고 · 거래처 제목줄 [엑셀 다운로드]: 엑셀 또는 읽기

## 구현 단위

1. 공통 도우미 `shared/utils/menuPermission.ts`
   - `screenPermissionsOf(menuPermission)` → `{ read, write, delete, excel }`
   - `readOnlyColumns(columns, canWrite)`: 쓰기가 없으면 모든 칸 `editable: false`(체크 칸 포함, 순번 칸 제외)
2. 기초정보 패널 공통 props(`BasicInfoTabPanelProps`)에 `canWrite` · `canDelete` 추가(기본 true — 다른 곳 · 기존 테스트는 그대로)
3. 화면마다 연결(사양서 표)
4. 테스트: 도우미 단위 테스트, 화면별 권한 없음 / 있음 렌더 테스트
5. 화면 확인: 권한을 일부만 준 시험 토큰으로 화면 열기(쓰기 막음) · 스크린샷

## 영향 범위

- 프론트 11개 화면, 공통 도우미 1개. 백엔드 · DB 없음.
- 시스템 관리자(모든 권한)의 화면은 그대로다.
