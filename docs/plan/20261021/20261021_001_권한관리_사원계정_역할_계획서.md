## 지금 상태 (읽기 전용 확인, 2026-10-21)

- 로그인: `employees` 에서 사번(`id`)으로 찾고 `employees.password_hash`(Werkzeug)로 확인한다. 역할은 비운다(`roleCode`/`roleId` NULL).
- 역할 없음 = 모든 메뉴 · 단추 허용(`SystemMenuServiceImpl.permissionCodesByMenuId`), 관리자 API 도 허용(`EgovAccessControlHelper.isTenantAdmin`).
- S_ERP 표는 있으나 비어 있다: `tb_login_account` 0, `tb_user` 0, `tb_login_account_role` 0.
- 역할 4개(SONGYEON): PLATFORM_ADMIN · ADMIN(시스템 관리자) · ROLE_INFO_MANAGER · DEFAULT_USER(일반 사용자).
- 역할별 메뉴 권한 `tb_role_menu_permission` 19줄뿐(ADMIN 3, PLATFORM_ADMIN 16). 메뉴 권한 정의 `tb_menu_permission` 은 메뉴 53개 × 5가지(READ · CREATE · UPDATE · DELETE · EXCEL) = 265줄.
- 직원 1명(`0000`, `is_admin` = 1, 계정 있음).
- 권한관리 화면(프론트)은 S_ERP 와 같다. 사용자 목록 쿼리는 `tb_user` 를 본다.

## 구현 단위

1. DB(데이터만, 표 구조 그대로): `20261021_001`
   - 계정 있는 직원마다 `tb_login_account` 한 줄(`login_code` = 사번, 비밀번호 해시 복사)
   - 역할 연결: `is_admin` = 1 → ADMIN, 그 밖 → DEFAULT_USER
   - ADMIN 에 메뉴 권한 전체(`tb_menu_permission` 그대로) — 지금과 같은 메뉴 · 단추가 보이게
2. 로그인(`EgovLoginUsr_SQL`): 계정 표에서 찾고 비밀번호를 확인하고 역할을 읽는다(역할 없으면 NULL 로 로그인).
3. 권한 판정
   - `isTenantAdmin`: 역할 없음 = 관리자 아님
   - 내 메뉴: 역할 없음 = 권한 없음(메뉴 0개)
   - 사용자 역할 찾기(`EgovSystemMenu_SQL` 2개): 로그인 아이디(`username`) → 사번 → 계정
4. 권한관리 사용자 매핑(`EgovSystemRole_SQL`): `tb_user` 대신 `employees`. 퇴사자 제외. 화면 '로그인 ID' 칸에 사번
5. 인사관리 계정 발급 · 회수(`EgovHr_SQL` · `HrServiceImpl`): 계정 표 같이 만들기 · 지우기, 처음 만들 때 일반 사용자 역할
6. 내 정보 비밀번호(`EgovLoginUsr_SQL`): 계정 표에서 확인 · 바꾸기
7. 검증: 단위 테스트 → 백엔드 전체 · 프론트 전체 → DB 시험 실행 → 적용 → 8080 API 확인 → 화면(쓰기 막고) 스크린샷
8. 결과 문서 · 메모리 갱신(권한 개념 생김)

## 영향 범위

- 백엔드: 로그인, JWT 의 역할 값, 내 메뉴, 관리자 API 7곳(`isTenantAdmin`), 권한관리, 인사관리 계정, 내 정보 비밀번호
- 프론트: 권한관리 사용자 그리드 '로그인 ID' 표시(그리드 자체는 손대지 않음)
- 역할이 바뀌면 다음 로그인부터 적용(토큰에 역할이 들어감, S_ERP 와 같음)
- 앞으로 메뉴를 더하는 SQL 은 ADMIN 역할 권한 줄도 함께 넣어야 관리자에게 보인다
