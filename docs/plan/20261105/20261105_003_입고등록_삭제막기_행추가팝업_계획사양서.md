## 1. 확인한 것 (바꾸기 전)

- 입고 삭제를 막는 규칙이 어디에도 없었다: 화면, 서버 `ReceivingServiceImpl.cancel`, 송연 원본 `app.py cancel_receiving` 모두 '없는 줄'만 거절했다. 지우면 재고에서 수량을 빼고 서류도 지운다.
- 빈틈: 반품 줄은 원래 입고 번호(`return_of_id`)를 들고 있는데 그 입고를 지워도 막지 않았다. 재고가 이미 쓰였으면 지울 때 재고가 마이너스가 될 수 있었다. Delete 키는 F1-Grid 가 권한 · 오른쪽 클릭 메뉴 설정과 상관없이 고른 줄을 뺐다.

## 2. 바꾼 것

| 규칙 | 서버(저장) | 화면 |
|---|---|---|
| 반품이 걸린 입고 | `반품이 등록된 입고는 지울 수 없어요. 반품등록에서 반품을 먼저 지워주세요` | 같은 문구(+원재료명) |
| 지우면 재고가 마이너스 | 입고 수량 > 지금 재고면 `재고가 모자라 지울 수 없어요(현재 재고 N, 입고 수량 M)`. 반품 줄(수량 마이너스)은 해당 없음 | 같은 원재료를 함께 지우면(이미 표에서 빼 둔 줄 포함) 수량을 더해 견준다 |
| 삭제 권한 없음 | (저장 단추가 없음) | Delete 키로도 못 뺀다 |

- 화면에서 막는 곳: 오른쪽 클릭 [행 삭제](막힌 줄을 고르면 꺼짐), Delete 키(빼지 않고 이유 알림), 제목줄 [삭제](이유 알림). 규칙은 `utils/receiving.ts receivingDeleteBlockReason` 하나.
- 화면이 미리 보려고 입고 목록 조회에 `stockQty`(원재료 지금 재고)를 더했다(`selectReceivings`). 서버 취소도 `selectForCancel` 에서 재고를 같이 읽는다.
- 오른쪽 클릭 [행 추가]: 표에 빈 줄을 넣지 않고 입고 등록 창을 연다(제목줄 [입고 등록]과 같음, 등록 권한이 있을 때만). 견적 화면과 같은 방식(`treeContextMenu`).
- 반품등록 화면은 같은 삭제 훅을 쓰지만 규칙을 넘기지 않아 그대로다. 서버 규칙은 반품 줄에는 걸리지 않는다.
