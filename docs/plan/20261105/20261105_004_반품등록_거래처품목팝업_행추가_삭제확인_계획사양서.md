## 1. 반품 삭제 확인

- 서버 `ReceivingServiceImpl.cancel`: 반품 줄도 같은 취소를 쓴다. '없는 줄'만 거절한다.
- 2026-11-05 입고 삭제 막기 규칙은 반품 줄에 걸리지 않는다: 반품 줄을 참조하는 줄이 없고(`returnedQty` 0), 수량이 마이너스라 지우면 재고가 다시 늘어난다(재고 규칙은 수량이 양수일 때만).
- 그래서 반품 줄은 막을 데이터 규칙이 없다. 남은 빈틈은 Delete 키가 삭제 권한과 상관없이 줄을 빼는 것 하나라 이것만 막았다.

## 2. 바꾼 것

- 반품 등록 창(`ReturnDialog`): 거래처 · 품목 자동완성 칸 → 읽기 전용 칸 + 🔍 → `MasterPickerDialog`(거래처 · 원재료). 거래처를 안 고르고 추가하면 `거래처를 먼저 선택해주세요`. 입고내역에서 가져오기 · 단가 · 사유 · 확정은 그대로.
- `PickerField` 를 `receiving-register/components/PickerField.tsx` 로 빼서 입고 등록 · 반품 등록 창이 같이 쓴다(발주등록 창 파일은 건드리지 않음).
- 반품내역 표(`ReceivingReturnGrid`): 오른쪽 클릭 [행 추가] → 표에 줄을 넣지 않고 반품 등록 창(등록 권한이 있을 때만). 삭제 권한이 없으면 Delete 키도 막는다.
