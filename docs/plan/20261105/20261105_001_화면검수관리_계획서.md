# 화면검수 관리 화면 구현 계획서

> 실행: 이 세션에서 직접(인라인). 단계마다 실패 테스트 → 구현 → 통과.

**목표:** 환경설정 > 시스템 관리 > 메뉴관리 밑에 모든 화면의 검수 상태를 모아 보는 보기 전용 화면을 만든다.

**구조:** 서버가 화면 목록 + 현황 + 마지막 이력을 한 번에 내려주고 화면별 표시 상태를 정한다. 화면은 카드 6개 · 검색 · F1-Tree(모듈 묶음)로 보여 준다.

**설계서:** [20261105_001_화면검수관리_설계서](../../spec/20261105/20261105_001_화면검수관리_설계서.md)

## 지킬 것

- S_ERP 는 건드리지 않는다. F1-Grid 본체는 고치지 않는다(쓰기만).
- 표 첫 칸은 행 번호(`type: 'rownumber'`, 머리 `No`). 빈 값은 빈칸.
- 저장 키는 `songyeon-erp:` 로 시작.
- DB 는 데이터 스크립트 `20261105_001`, 시험 실행 → 사용자 승인 → 적용. 자격 증명 · 개인 정보 출력 금지.
- 커밋하지 않는다.

## 주의해서 볼 것

- 검수완료 뒤 새 수정요청: 현황이 `CHANGE_REQUESTED` 이므로 마지막 이력과 상관없이 수정요청.
- 하위 메뉴가 모두 미사용인 중분류: 하위가 "있으면" 묶음으로 보고 뺀다(설계 3장 "하위 메뉴가 없는 메뉴").
- 미사용 모듈의 메뉴는 뺀다.
- 거른 뒤 화면이 없는 모듈 묶음 줄은 숨긴다.
- 비고 의견에 줄바꿈이 있으면 한 줄로 보인다.
