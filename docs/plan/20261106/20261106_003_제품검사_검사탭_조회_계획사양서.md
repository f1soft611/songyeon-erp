## 원본 조회

- 생산 로트(`production_schedule`) 하나가 한 줄. 기본은 생산이 끝난 것(실생산량이 들어온 줄)만, `생산예정도 보기` 를 켜면 전부
- 기간은 시작일 · 종료일이 둘 다 있을 때만 건다. 날짜 기준 `제조일` = 생산일(`schedule_date`), `출고일` = 그 로트의 출하줄(`logistics_schedule.lot_id`) 날짜나 생산줄의 물류출고일(`logistics_date`) 중 하나라도 기간 안
- 정렬: 제조일 최근 것 먼저, 같은 날은 나중 줄 먼저. 최대 300줄
- 생산량: 실생산량, 없으면 주문량에 `(예정)`
- 출고일: 확정된 출하줄 날짜(` / ` 로 이음) → `확정`. 없으면 확정 안 된 출하줄 날짜, 그것도 없으면 물류출고일 → `예정`. 둘 다 없으면 `미정`(재고생산이면 `재고생산`)
- 소비기한: `제조일로부터 {개월수}{단위(없으면 개월)}까지`, 보관방법이 있으면 뒤에 ` [보관방법]`. 개월수가 없으면 비움
- 상태 고르기(전체 · 아직 안 쓴 것 · 검토 기다리는 것 · 반려된 것 · 승인된 것)는 받아온 줄을 화면에서 거른다. 원본은 상태 · 생산예정도를 바꾸면 다시 부른다 → ERP 는 생산예정도만 다시 부르고, 상태는 화면에서 거르기만 한다(같은 결과, 서버를 다시 부를 일이 없다)
- 요약: `로트 N건 · 아직 검사 안 한 것 N건 · 검토 기다리는 것 N건`(거르기 전 전체)
- 거른 줄이 없고 생산예정도를 안 켰으면: `생산이 끝난 것(실생산량이 들어온 줄)만 보고 있습니다 — '생산예정도 보기'를 켜보세요.`
- 제품 검사 창 위쪽: 제품명 · 내용량 · 제조일자 · 생산량 · 출고일 · 소비기한(로트 줄의 값)

## ERP 에서

- 성적서 표(송연 `qdoc_record`)가 ERP DB 에 아직 없다 → 모든 로트의 성적서는 `아직 안 함`, 인쇄 단추 없음. 상태 고르기는 받아온 줄을 그대로 화면에서 거르므로 `아직 안 쓴 것` 은 전체, 나머지는 0줄
- 생산줄은 제품코드(`product_code`)로 제품과 이어진다(원본처럼 이름으로 코드를 찾는 일은 없다). 품목 칸은 제품명(제품이 없으면 제품코드)
- 식품유형은 공통코드 `FOOD_TYPE` 이름(코드가 아닌 예전 글자는 그대로), 없으면 `유형 없음`
- 검사 창 아래쪽 검사항목 표 · 임시저장 · 결재 올리기는 그대로 비활성(식품유형별 검사항목을 어디서 정할지 아직 모름)

## API

`GET /api/v1/qm/inspection/product-inspection/lots?start=&end=&dateBy=&planned=`

| 파라미터 | 내용 |
| --- | --- |
| `start` · `end` | `YYYY-MM-DD`. 둘 다 있을 때만 기간을 건다 |
| `dateBy` | `made`(기본) · `ship`. 다른 값이면 입력 오류 `날짜 기준이 올바르지 않습니다` |
| `planned` | `true` 면 생산예정 줄도 |

| 응답 `resultList[]` | 내용 |
| --- | --- |
| `lotId` · `lotNo` · `madeOn` | 생산줄 번호 · 로트번호 · 제조일 |
| `productCode` · `productName` | 제품코드 · 제품명 |
| `foodType` · `foodTypeNm` | 식품유형 코드 · 공통코드 이름 |
| `netWeight` · `shelfLife` | 내용량 · 소비기한 문구 |
| `qty` · `qtyIsActual` | 생산량 · 실생산량인가 |
| `shippedOn` · `shipState` | 출고일 · `확정` · `예정` · `미정` · `재고생산` |
| `recordId` · `recordStatus` | 지금은 늘 비어 있음(성적서 표 없음) |
