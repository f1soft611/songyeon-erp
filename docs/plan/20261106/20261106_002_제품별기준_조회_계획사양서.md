## 원본 조회

- 사용안함(`discontinued`) 제품은 빼고, 제품명 · 제품코드에 검색어가 들어간 것
- 정렬: 식품유형 있는 것 먼저, 그다음 제품명. 최대 500줄
- 보기: `유형있음` · `유형없음` · `규격있음`(기준 넣은 것) · `규격없음`
- 요약: 제품 N개 · 식품유형 정한 것 N개 · 규격 넣은 것 N개(검색과 관계없이 전체)
- 기준 칸: 제품별 기준 표(`qdoc_product_spec`)에 넣은 값. 유형이 없으면 비움, 유형은 있는데 넣은 기준이 없으면 `안 넣음`

## ERP 에서

- **제품별 기준 표(`qdoc_product_spec`)가 ERP DB 에 아직 없다.** 이번에는 표를 만들지 않는다(조회까지만)
  - 그래서 모든 제품의 기준은 '넣은 것 없음': 기준 칸은 유형 있는 제품 `안 넣음`, `규격있음` 은 0줄, `규격없음` 은 전체, 요약의 '규격 넣은 것' 은 0
- 식품유형은 코드(공통코드 `FOOD_TYPE`)로 저장된다 → 화면에는 공통코드 이름. 코드가 아닌 예전 글자가 남아 있으면 그 글자를 그대로 보인다
- 화면 문구: 유형 없는 줄은 `유형 없음` 만(사용자 결정: `제품BOM에서 정하세요` 안내를 뺀다)

## API

`GET /api/v1/qm/inspection/product-inspection/product-specs?q=&only=`

| 응답 | 내용 |
| --- | --- |
| `resultList[]` | `code` · `name` · `spec` · `foodType`(코드) · `foodTypeNm`(공통코드 이름, 없으면 저장값) |
| `stats` | `total` · `typed` · `withSpec`(지금은 0) |

- `only` 가 위 네 값 · 빈 값이 아니면 입력 오류(`보기 조건이 올바르지 않습니다`)
