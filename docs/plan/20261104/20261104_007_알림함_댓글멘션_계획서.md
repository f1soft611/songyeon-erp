## 1. 순서 조정

S_ERP 알림은 '결재 댓글 멘션' · '쪽지 받음' 두 종류만 만들어진다. 알림함만 먼저 넣으면 받을 알림이 없으므로 순서를 바꿨다.

1. 알림함 + 결재 댓글 멘션(이 계획)
2. 쪽지함(쪽지 받음 알림 포함)
3. 실시간 갱신(RealtimePublisher · 화면 자동 갱신)
4. 댓글 수정 · 삭제 메뉴 권한(`isEditable`)
5. (선택) 웹푸시

## 2. 송연에 맞출 점

- 사람: S_ERP 는 `tb_user.user_id`(숫자), 송연은 사번(`employees.id`, 20261103_003). 알림 받는 사람 · 멘션 대상 · API 의 사람 ID 를 모두 사번 문자열로.
- 알림함은 메뉴가 아니라 상단 바 알림 아이콘으로 여는 고정 화면 `/groupware/notifications`(S_ERP 와 같음, 메뉴 DB 작업 없음).
- 실시간 · 웹푸시 호출은 3 · 5단계에서 넣는다(1단계 서버에서는 뺀다).

## 3. 구현 단위

1. DB `20261104_001` 알림 표(사용자 확인 후 적용).
2. 서버 `groupware/notification`: 컨트롤러 · 서비스 · DAO · 매퍼(S_ERP 와 같은 API `/api/v1/groupware/notifications` · summary · 목록 · 읽음 · 보관 · 읽은 것 보관).
3. 서버 결재 댓글: 등록 때 `mentionedUserIds`(사번) · `mentionAll` 을 받아 문서 기안자 · 결재선 사람에게 알림, 멘션 후보 API `/comments/mention-users`.
4. 화면: 상단 바 알림 아이콘(NotificationCenter) · 알림함 화면 · 알림 누르면 그 문서로, 댓글 입력 `@` 멘션(commentMentions · TiptapCommentThread) · 문서 상세 연결.
5. 테스트: S_ERP 테스트(알림 서비스 · 화면 · 멘션)를 송연 사번 · 키에 맞춰 먼저 넣고 실패 확인 → 구현.
6. 실제 확인: 결재 댓글에서 다른 사람 멘션 → 그 사람 알림 수 · 목록 · 문서 이동(시험용 댓글은 확인 뒤 지움, 사용자 확인 후).
