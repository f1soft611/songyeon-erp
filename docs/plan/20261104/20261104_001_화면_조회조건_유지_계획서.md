## 1. 기준 (S_ERP)

- S_ERP 는 공통 `usePageSessionState`(sessionStorage)로 마지막에 [조회]한 검색어 · 상세 조건을 저장하고, 화면을 다시 열면 그 조건으로 다시 조회한다(거래처 · 품목 · 수주현황 · 기안양식 등).
- 그리드 자체를 보관하지 않고 같은 조건으로 다시 부른다. 탭을 닫으면 사라진다.
- 송연에는 공통 훅이 이미 있다(S_ERP 와 같은 파일). 공통코드 · 자료실 · 문서현황만 쓰고 있다.

## 2. 범위

메뉴 순서 영업관리 ~ 구매관리 중 검색 영역(`PageSearchArea`)이 있는 화면 24개.

| 모듈 | 화면 |
|---|---|
| 영업관리 | 견적 · 수주등록 · 생산가능확인 · 단가관리 · 출하등록 |
| 생산관리 | 생산확정 · 생산입고 · 라벨출력 · 생산현황 |
| 물류관리 | 출하확정 · 출하현황 · 제품재고관리 |
| 판매관리 | 판매등록 · 판매현황 · 토탈집계 |
| 구매관리 | 발주등록 · 발주현황 · 입고등록 · 입고현황 · 서류등록 · 반품등록 · 재료 치환등록 · 수불대장 · 재고현황 |

- 제외: 제품등록(입력 화면), 문서함 · 재고조정(검색 영역 없음), 기준정보 · 그룹웨어 · 환경설정.

## 3. 구현 단위

1. 공통 도우미 `shared/utils/searchSession.ts`: 기존 `read/writePageSessionState` 를 감싸 키(`songyeon-erp:page:<화면>`) · 버전 · 모양 검사를 한 곳에 둔다. 테스트 먼저.
2. 화면별 훅/페이지: 처음 조건을 세션 값으로 시작하고, 서버에 부를 때 그 조건을 저장한다. 화면에서 거르는 조건(탭 · 검색어 · 체크)은 바뀔 때 저장한다.
3. 상세 조회 칩: 돌아온 화면에서 저장한 조건을 칩으로 다시 보인다.

## 4. 검증

- `tests/search-session.test.ts`(실패 먼저 확인), 타입 검사, 관련 테스트.
