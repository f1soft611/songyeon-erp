# 20261102_002 판매등록 표준화 계획 · 사양서

- 요청
  - "판매등록 화면 먼저 표준맞춰줘"
  - "날짜는 상세조회로 넣어주고"
  - "마우스로 행추가 가능하게 해주고 그럼 직접등록 버튼이랑 동일하게 동작하면 돼"
- 화면: 판매관리 > 판매처리 > 판매등록(`ENSalesRegisterView`)
- 같은 방식: 거래처마스터(`rowFormPlugin` 내장 상세 창), 출하현황(상세 조회)

## 바꿀 것

- 구조: 화면(`SalesRegisterManagementPage`) · 조회/저장(`hooks/useSalesRegisterManagement`) · 그리드(`components/SalesRegisterGrid`)로 나눈다.
- 제목줄: `출하확정 불러오기` 를 `조회` 로 바꾸고 `저장` 을 더한다.
- 그리드: 첫 칸은 `No`, 칸 이름 `출고일` 은 `판매일자` 로 바꾼다.
- 조회: 판매일자 기간을 상세 조회(⌄)로 옮긴다. 서버 필수 조건이라 필수 칸으로 두고 이번 달 1일~오늘로 시작한다. 검색칸은 거래처코드 · 거래처명을 둘 다 찾는다(서버 `selectShipped`). 상세 조회에 품목코드/명을 더하고 받은 목록을 화면에서 거른다.
- 직접 등록
  - [직접 등록]과 오른쪽 클릭 [행 추가]는 같은 내장 상세 창을 연다. `ManualSaleDialog` 는 없앤다.
  - 거래처 · 품목은 고르기 팝업(`MasterPickerDialog`)으로 고른다. 서버가 마스터에 없는 이름을 막기 때문이다.
  - [적용]하면 표에 새 줄이 생기고 [저장]하면 기존 `POST .../manual` 로 한 줄씩 넣는다.
  - 저장 뒤 목록을 다시 받는다. 직접 등록 건은 출하 건이 아니어서 이 표에 남지 않고 판매현황에서 본다.
- 출하확정에서 온 줄은 고칠 수 없다. 줄의 상세 단추는 값을 읽기 전용으로 보여 주고 [적용]은 막는다.
  - F1-Grid 창은 편집할 수 없는 칸을 숨겨서 빈 창이 떴다. 사용자 승인으로 `GridFormModel.ts` 를 패치해 `form.readOnly` 를 적은 칸은 보여 준다.
- 저장하지 않은 새 줄이 있으면 [조회] · 상세 조회 전에 묻고, [선택 항목 판매등록]은 막는다.

DB 는 바꾸지 않는다. 서버는 조회 쿼리의 거래처 조건만 바꾼다.

## 검증 기준

- 타입 검사 · 빌드, 판매등록 테스트 통과
- 두 진입 경로가 같은 창을 여는지 화면 테스트로 확인
