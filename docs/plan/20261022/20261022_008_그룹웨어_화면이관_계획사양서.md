## 3. 결재 사용자(사용자 결정: "로그인을 S_ERP처럼")

### 문제

- S_ERP 결재 코드는 로그인 `uniqId` 를 `tb_user.user_id`(숫자)로 쓴다. `Long.valueOf(uniqId)` 로 바꾸고, 결재선 참여자 ID 와 글자로 비교한다.
- 송연 로그인 `uniqId` 는 사번(8자리, 앞자리 0, 예: 00000001)이다. 숫자로 바꾸면 1 이 돼서 글자 비교가 맞지 않는다.

### 결정

로그인 `uniqId` 를 S_ERP 와 같이 `tb_user.user_id` 로 한다.

- DB `20261022_006`: 로그인 계정마다 `tb_user` 를 만든다.
  - `login_id` 연결, `user_nm` = 사원 이름
  - `email_addr` = 사원 이메일(다른 사용자와 겹치면 비움)
  - `use_at`: 퇴사일이 있으면 N
  - `department_id` · `level_id` 는 비운다(S_ERP DB 도 부서 0건, 직급 비어 있음).
- 로그인 매퍼 `actionLoginEmployee`: `tb_user` 를 이어 `uniqId = tb_user.user_id`. 사용자 줄이 없으면 예전처럼 사번을 쓴다.
- 사번이 필요한 송연 화면 5곳은 공통 도우미 `LoginEmployeeResolver` 로 사번을 찾는다.
  - 포장유형 · 창고 · 문서함 · 레시피 · 레시피공유. 등록자 · 수정자 · 문서함 잠금 해제에 쓴다.
  - 로그아웃 문서함 잠금 정리도 같은 도우미를 쓴다.
  - `uniqId` 가 0 으로 시작하거나 숫자가 아니면 사번으로 본다(바꾸기 전에 받은 토큰). 그 밖이면 `tb_user → tb_login_account.login_code` 로 사번을 찾는다.
- 로그인 `id` 도 S_ERP 와 같이 계정 `login_code`(사번)로 한다(2026-10-22 화면 확인 중 추가)
  - 그룹웨어 코드는 `id` 로 계정을 찾고(`selectLoginIdByLoginCode`) 작성자를 남긴다. 예전 값(사원 이름 username)으로는 공지 로그인 팝업에서 "인증된 로그인 계정을 찾을 수 없습니다" 오류가 났다.
  - username 으로 사람을 찾던 송연 쿼리 7곳을 사번으로 바꾼다. 메뉴 권한 2곳과 내 정보 · 비밀번호 · 이메일 · 이미지 5곳이다.
- 내 정보 API 에 `employeeId` = `tb_user.user_id` 를 더한다(S_ERP 와 같음).
  - 문서작성 화면이 이 값으로 로그인 사용자를 찾는다. 없으면 "로그인 사용자의 사원 ID를 확인할 수 없습니다" 가 뜬다.
- 바꾸기 전에 받은 로그인 토큰에는 예전 값이 들어 있다. 그래서 한 번 로그아웃한 뒤 다시 로그인해야 한다.
- 인사관리 연동(작업지시서 4단계 '가')
  - 사원 등록 · 계정 만들기: 계정을 만들거나 고친 뒤 `tb_user` 가 없으면 만든다.
  - 사원 수정: 같은 사원의 `tb_user` 이름 · 사용 여부(퇴사일)를 맞춘다.
  - 계정 거두기: 계정 줄이 지워지면 `tb_user.login_id` 는 FK 로 비워진다. 결재 이력 이름은 남는다.

## 4. 결재 준비 데이터 (DB `20261022_007`)

- 기안양식관리 메뉴: S_ERP `CO_WORKFLOW`(전자결재 관리) > `CO_WF_FORM`(기안양식관리, `/co/workflow/form`)를 송연 기준정보(`CO`) 모듈 아래에 넣는다.

  - 역할 권한은 S_ERP 처럼 플랫폼 관리자 READ · CREATE · UPDATE 로 하고, ADMIN 은 송연 규칙대로 모두 준다.
- 공지사항 구분(`NOTICE_GUBUN`) `ALL` · `IMPORTANT` 를 S_ERP 처럼 사용안함으로 한다.
  - 새 공지 화면은 사용 중인 코드만 분류로 보여서, 그대로 두면 '전체' · '중요 공지' 가 분류로 나온다.
- 공통코드 `WF_FORM_CATEGORY` · `WF_FORM_CYCLE` · `WF_ARCHIVE_CATEGORY` 는 이미 S_ERP 와 같다.
- 표 구조: 그룹웨어 매퍼가 쓰는 표 15개의 컬럼 · 제약 · 인덱스가 S_ERP 와 같다(검사 제약 표기만 다르고 뜻은 같다). 그래서 스키마 변경은 없다.
