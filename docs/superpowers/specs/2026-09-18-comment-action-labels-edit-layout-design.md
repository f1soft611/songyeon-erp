# 댓글 액션 명칭 및 수정 입력창 레이아웃 설계

## 목적

공지사항 댓글과 답글의 더보기 메뉴 명칭을 간결하게 정리하고, 수정 입력창의 액션을 한 줄에 배치한다.

## 범위

- 대상 컴포넌트: `frontend/src/shared/components/feed/TiptapCommentThread.tsx`
- 관련 테스트: 댓글 공통 컴포넌트 및 공지사항 댓글 CRUD 테스트
- 백엔드 API, 댓글 데이터 구조, 권한 조건은 변경하지 않는다.

## 동작 설계

1. 댓글과 답글의 더보기 메뉴 항목은 작성자 이름이나 접두어 없이 `수정`, `삭제`로 표시한다.
2. 메뉴의 접근성 명칭도 화면에 표시되는 명칭과 일치시킨다.
3. 수정 입력창 하단 액션은 한 줄 flex 영역에서 `첨부파일 아이콘`, `수정`, `취소` 순서로 표시한다.
4. 첨부파일 선택, 수정 제출, 취소, API 실패 시 입력 내용 보존 동작은 기존 계약을 유지한다.
5. 답글 등록과 일반 댓글 등록의 입력창 동작은 변경하지 않는다.

## 검증 기준

- 댓글 더보기 메뉴에서 `수정`, `삭제`가 표시되고 이전의 작성자 포함 명칭은 표시되지 않는다.
- `수정` 선택 후 수정 입력창이 렌더링되고 `수정` 버튼으로 제출할 수 있다.
- 수정 입력창의 첨부파일 버튼, 수정 완료 버튼, 취소 버튼이 동일한 액션 행에 존재한다.
- 관련 Vitest 테스트와 `npm run build`가 통과한다.
