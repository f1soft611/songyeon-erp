# 대시보드 프로필 API 및 최근 사용 UI 개선 설계

## 목표

로그인 사용자의 프로필 정보를 기존 인증/내 메뉴 API로 대시보드에 전달하고, 첨부 시안에 가까운 프로필 팝오버와 사이드바 하단 최근 사용 메뉴 UI를 제공한다.

## 범위

- 기존 `GET /api/v1/menus/my` 응답의 `user` 정보 확장
- 로그인 시 생성되는 JWT에 프로필 표시용 최소 정보 포함
- JWT 인증 필터에서 해당 정보를 `LoginVO`로 복원
- 대시보드 AppBar의 프로필 팝오버를 동적 사용자 정보 기반으로 표시
- 사이드바 하단 최근 사용 메뉴의 시각적 계층과 항목 가독성 개선
- 기존 라우팅, sessionStorage 최근 메뉴 저장, 모듈 순서 유지

## 제외 범위

- 신규 프로필 전용 API 추가
- 사용자 프로필 수정 기능
- DB 스키마 및 데이터 변경
- F1-Grid 변경
- 전체 페이지 상태 복원

## API 계약

`GET /api/v1/menus/my`의 `result.user`를 다음 형태로 확장한다.

```json
{
  "userId": "admin",
  "name": "홍길동",
  "email": "user@example.com",
  "profileImage": "/api/v1/files/profile/...",
  "groupName": "플랫폼관리자",
  "roleName": "PLATFORM_ADMIN",
  "roles": ["PLATFORM_ADMIN"]
}
```

`profileImage`가 비어 있거나 이미지 로드에 실패하면 사용자 이름의 첫 글자를 Avatar 대체값으로 사용한다. API 요청 실패가 메뉴 조회 전체를 실패시키지 않도록 기존 메뉴 응답 안에서 함께 처리한다.

## 프로필 팝오버

- AppBar 우측 끝의 Avatar를 클릭하면 우측 정렬 팝오버를 연다.
- 팝오버 상단에는 동적 프로필 이미지 또는 첫 글자 Avatar, 사용자명, 역할/그룹명, 이메일을 표시한다.
- 상단 정보와 액션 목록 사이에 구분선을 둔다.
- 액션은 아이콘과 함께 `내 정보 관리`, `보안 설정`, `로그아웃` 순서로 표시한다.
- `내 정보 관리`와 `보안 설정`은 기존 라우팅 정책을 유지하고, `로그아웃`은 기존 `handleLogout`을 호출한다.
- 좁은 화면에서는 팝오버 폭을 제한하고 화면 밖으로 넘치지 않게 한다.

## 최근 사용 영역

- `DashboardMenuTree` 하단 영역에 최근 사용 제목과 현재 항목 수를 표시한다.
- 항목은 메뉴명과 모듈명을 두 줄 계층으로 표시하고, 좌측에 일관된 메뉴 아이콘 또는 상태 표시를 둔다.
- 각 항목은 고정된 최소 높이와 말줄임 처리를 사용해 사이드바 폭에서 줄바꿈으로 레이아웃이 흔들리지 않게 한다.
- hover와 keyboard focus 상태를 구분하고, 선택된 최근 항목은 현재 테마의 강조 색으로 표시한다.
- 기존 최대 5개, 중복 제거, 최신 방문 순서, sessionStorage 저장 규칙은 유지한다.
- 최근 항목이 없을 때는 기존 안내 문구를 유지하되 빈 영역이 과도하게 커지지 않게 한다.

## 데이터 흐름

1. 로그인 서비스가 조회한 `LoginVO`를 사용해 access/refresh JWT에 필요한 표시 필드를 넣는다.
2. `JwtAuthenticationFilter`가 JWT 클레임을 `LoginVO` principal로 복원한다.
3. `MyMenuApiController`가 기존 서비스 응답 생성 흐름에 principal의 표시 정보를 전달한다.
4. 프론트 `menuService`가 확장된 `user` 타입을 보존하고 `DashboardPage`가 프로필 상태로 전달한다.
5. 대시보드 UI는 데이터가 없을 때 `userId`, 역할 코드, 첫 글자 Avatar로 안전하게 대체한다.

## 오류 및 보안

- 프로필 이미지 URL, 이메일 등은 인증된 내 메뉴 응답으로만 전달한다.
- JWT에 포함하는 값은 화면 표시용 최소 정보로 제한하고 비밀번호·민감 식별자는 포함하지 않는다.
- 오래된 JWT에는 새 클레임이 없을 수 있으므로 모든 새 필드는 nullable로 처리한다.
- 프로필 표시 실패는 메뉴 화면을 차단하지 않고 fallback UI로 처리한다.

## 검증 기준

- 백엔드 테스트에서 확장된 내 메뉴 응답의 사용자 필드가 생성되는지 확인한다.
- 프론트 테스트에서 동적 사용자명/역할/이메일과 프로필 팝오버 액션을 확인한다.
- 최근 사용 메뉴가 모듈명과 메뉴명을 함께 표시하고 클릭 이동을 유지하는지 확인한다.
- `npm run build`와 관련 Vitest를 실행한다.
- `mvn test` 또는 변경 범위에 맞는 백엔드 테스트를 실행한다.
- 375px, 768px, 1280px 기준에서 AppBar 팝오버와 사이드바 최근 영역의 overflow를 브라우저로 확인한다.
