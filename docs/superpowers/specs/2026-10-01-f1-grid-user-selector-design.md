# F1-Grid 사용자 선택 컬럼 설계

## 목적

ERP 화면에서 반복해서 사용하는 사용자 선택을 F1-Grid의 전용 컬럼 타입으로 제공한다. 단일 선택과 다중 선택을 지원하고, 같은 선택 UI를 그리드 셀 편집과 F1-Grid 행 폼 모달에서 사용한다. 첫 적용 화면은 전자결재 기안양식관리다.

## 현재 구조와 확인 근거

- `F1GridEditorType`은 `grid.types.ts`에서 선언하고 셀 편집기는 `CellEditor`에서 타입별 컴포넌트를 선택한다.
- 행 폼 모달은 `GridFormField`에서 컬럼 타입별 입력을 렌더링한다. 두 경로는 동일한 컬럼 설정을 공유하지만 현재 `select`의 다중 선택 폼과 셀 편집 동작은 별도로 제한되어 있다.
- 기안양식관리에는 검토자/승인자 단일 ID와 담당자 ID 배열이 있으며 현재 사용자 목록 API는 이름과 부서만 반환한다.
- 읽기 전용 PostgreSQL MCP에서 확인한 기존 스키마에는 `tb_login_account.profile_image`, `tb_user.level_id`, `tb_department.department_nm`가 있다. `level_id`는 `tb_common_code_item.common_code_item_id`를 참조하고 `LEVEL` 그룹 항목을 사용한다. DB 스키마 변경은 필요하지 않다.
- 기존 사용자 조회 API는 인증 사용자의 tenant ID, 활성 사용자 및 활성 로그인 계정 조건을 사용한다. 이 범위 제한은 유지한다.

## 대안과 선택

### 대안 A: 기존 select 확장

기존 select 편집기에 사용자 사진과 행 렌더링을 추가한다. 변경은 작지만 사용자 선택이 일반 코드 선택과 계속 결합되고, 폼 모달과 그리드 UI를 일치시키기 어렵다.

### 대안 B: 페이지 전용 사용자 선택기

기안양식관리에서만 사용자 선택 컴포넌트를 만든다. 이미지 표현을 빠르게 맞출 수 있지만 다른 F1-Grid 화면에서 재사용할 수 없고, 그리드 코어의 신규 타입 요구를 충족하지 못한다.

### 대안 C: F1-Grid 전용 user 타입과 공용 선택기

전용 옵션 메타데이터를 가진 `user` 타입을 추가하고, 하나의 공용 선택 컴포넌트를 셀 편집과 행 폼 모달에서 사용한다. 구현 범위는 늘지만 사용자 선택 경험과 값 계약을 한 곳에서 유지할 수 있어 채택한다.

## 승인 설계

### 컬럼 계약

- `F1GridEditorType`에 `user`를 추가한다.
- 컬럼의 `userOptions`에 사용자 옵션 목록을 지정한다. 각 옵션은 `value: string | number`, `label`과 선택적 `avatarUrl`, `positionName`, `departmentName`을 가진다.
- `form.multiple`로 단일/다중 모드를 정한다. 기본은 단일 선택이다.
- 단일 값은 기존 도메인 ID 타입을 그대로 사용하고 미선택 값은 `null`로 표현한다. 다중 값은 기존 도메인 ID 타입을 담은 배열로 유지하며 미선택은 빈 배열이다.
- `onValueChange`는 선택 결과를 페이지 도메인 형식으로 변환할 수 있으며, 사용자 선택기는 표시용 메타데이터를 저장값에 섞지 않는다.
- 일반 셀 표시에서는 이름을 표시하고, 편집 상태에서는 검색 입력과 사용자 목록을 제공한다. 다중 선택은 선택 칩으로 나타낸다.

### 공용 선택 UI

- 그리드 셀 편집과 행 폼 모달에서 같은 사용자 선택 컴포넌트를 사용한다.
- 목록 항목은 아바타(없으면 이름 이니셜), 이름, 직급, 부서를 표시한다. 검색은 이름·직급·부서에 적용한다.
- 다중 선택 목록은 선택 후에도 열려 있어 연속 선택할 수 있으며 선택 칩을 제거해 값을 해제할 수 있다. 단일 선택은 항목을 고르면 완료한다.
- 좁은 그리드/화면에서도 팝업이 뷰포트를 넘지 않고 목록 내부에서 스크롤되도록 한다.
- 필수, 읽기 전용, 검증 오류, 키보드 접근성은 기존 GridFormField 상태와 일치시킨다.

### 기안양식관리 적용

- `/api/v1/co/workflow/forms/users` 응답에 `profileImage`와 `levelNm`을 추가한다. 기존 `userId`, `loginId`, `userNm`, `departmentNm` 필드는 유지한다.
- 사용자 조회 SQL은 기존 tenant/활성 사용자 조건을 유지하고, `tb_login_account.profile_image`와 활성 `LEVEL` 공통코드 항목명을 조인한다. 사진이나 직급이 없어도 사용자 항목 자체는 목록에 남긴다.
- 검토자와 승인자는 기존 `loginId` 단일 값 및 미선택 `null` 계약을 사용한다. 담당자는 기존 `userId` 문자열 배열 계약을 사용한다.
- 현재 담당자 컬럼을 막고 있는 페이지 편집 제한은 사용자 컬럼 편집 허용에 맞게 조정한다.
- API 계약과 F1-Grid 사용 문서를 갱신한다. DB DDL, 데이터 마이그레이션, 전자결재 payload 변경은 포함하지 않는다.

## 검증 기준

- 셀 편집에서 단일 선택은 ID 한 개, 다중 선택은 ID 배열을 커밋하고 기존 값에 변경이 없으면 dirty로 만들지 않는다.
- form modal 생성/수정에서 단일·다중 선택, 재진입 시 선택값 복원, 미선택, 읽기 전용, 필수/오류 상태가 동작한다.
- 선택 UI가 프로필 이미지·직급·부서를 표시하고 이름·직급·부서로 검색되며, 누락된 사진/직급 정보도 안전하게 표시한다.
- 사용자 API 테스트는 현재 tenant의 활성 사용자 제한과 응답 필드를 검증한다. 사용자 개인정보 행 데이터를 테스트 출력이나 문서에 남기지 않는다.
- 기존 F1-Grid 회귀 테스트와 기안양식관리 테스트를 실행하고 프론트엔드 빌드 및 백엔드 관련 테스트를 통과시킨다.
- 브라우저에서 375px, 768px, 1280px 화면의 그리드 셀 편집 및 행 폼 모달 팝업을 확인하고 결과 스크린샷을 저장한다.

## 범위 제외

- 사용자/부서/직급 스키마 변경 및 새 DB 코드 그룹 생성
- 기안양식의 저장 ID 계약 변경
- 다른 화면의 사용자 선택 적용
- 사용자를 서버 검색/페이지네이션하는 API 변경
