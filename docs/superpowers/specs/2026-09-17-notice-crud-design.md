# 공지사항 통합 조회 및 댓글 기능 개선 설계

## 목표

공지사항 최초 조회에서 게시글·첨부·댓글 구조를 한 번에 받고, 공지/댓글 CRUD 이후 불필요한 전체 재조회를 제거한다. 댓글과 답글은 에디터 및 첨부파일을 지원하며 기본 3건만 표시하고 이전 댓글을 별도 조회한다.

## 범위

- 공지 상세 응답에 첨부파일과 댓글/답글을 포함한다.
- 댓글 조회에 최근 3건 및 이전 댓글 조회 파라미터를 추가한다.
- 공지와 댓글/답글 생성·수정·삭제 후 해당 상태만 프론트에서 갱신한다.
- 댓글/답글 본문은 기존 `content` 컬럼에 에디터 HTML을 저장한다.
- 댓글/답글 첨부파일은 `ownerType=NOTICE_COMMENT`, `ownerId=commentId`로 저장한다.
- 피드 및 공지 수정 화면에서 게시글 첨부파일을 표시한다.
- 게시글·댓글·답글 액션은 더보기 메뉴에서 노출한다.

## 현재 원인

- 프론트 `hydrateNoticePost`가 게시글 목록마다 상세 API와 댓글 API를 각각 호출한다.
- 백엔드 공지 상세 응답은 게시글과 첨부만 조합하고 댓글은 포함하지 않는다.
- 댓글 UI는 단순 input을 사용하며 에디터 HTML/첨부를 전달하지 않는다.
- 댓글 추가 시 프론트가 임시 ID를 먼저 만들고 서버 응답을 상태에 반영하지 않는다.
- 게시글 수정/저장 후 전체 목록을 다시 조회한다.

## API 설계

### 공지 상세

`GET /api/v1/groupware/boards/notice/posts/{postId}`

응답 `item`에 다음을 포함한다.

- `attachments`: 게시글 첨부 목록
- `comments`: 댓글/답글 목록
- `commentCount`: 전체 댓글 수

댓글은 기본 최근 3건을 반환하되, 부모 댓글과 답글의 트리 구조를 유지한다. 이전 댓글 조회는 공지 상세 응답에 포함된 페이징 메타 또는 공통 댓글 조회 API의 페이지 파라미터를 사용한다.

### 댓글

- 생성/수정 응답은 저장된 댓글의 서버 ID, 작성자, 시간, 본문, 첨부 목록을 반환한다.
- 삭제는 삭제 대상 ID만 반환하거나 성공 상태를 보장한다.
- 댓글 본문은 현재 `content` TEXT에 에디터 HTML을 저장한다.
- 댓글 첨부는 공통 파일 API에서 `NOTICE_COMMENT`와 댓글 ID를 소유 키로 사용한다.

### 부분 갱신 원칙

- 공지 생성: 생성 응답을 목록에 추가하고 업로드 완료 첨부를 해당 항목에 반영한다.
- 공지 수정: 수정 응답과 첨부 변경 결과만 해당 항목에 반영한다.
- 공지 삭제: 해당 ID를 목록에서 제거한다.
- 댓글/답글 생성: 서버 응답을 부모 댓글 또는 루트 목록에 삽입한다.
- 댓글 수정: 해당 ID의 본문과 첨부만 교체한다.
- 댓글 삭제: 해당 ID만 제거하고 자식 답글 구조는 API 계약에 맞춰 유지한다.

## 프론트 구조

- `noticeBoardService.ts`: 통합 상세 응답 타입과 댓글 조회 파라미터를 정의한다.
- `commonContentApi.ts`: 댓글 첨부 조회/업로드 API와 페이지 파라미터를 추가한다.
- `CommunityNoticePage.tsx`: 상세 응답을 그대로 변환하고 CRUD 응답으로 로컬 상태를 갱신한다.
- `NoticeFeedList.tsx`: 최근 댓글 3건, 이전 댓글 버튼, 더보기 메뉴, 게시글 첨부 표시를 담당한다.
- `CommentThread.tsx`: 댓글/답글 입력과 수정을 Tiptap 에디터 기반으로 변경하고 첨부 UI를 연결한다.
- 공지 작성 에디터와 동일한 Tiptap 설정을 재사용하되 댓글 입력 높이는 축소한다.

## 오류 처리

- API 실패 시 해당 작업의 로컬 낙관적 변경을 되돌리거나 서버 응답을 받은 뒤에만 반영한다.
- 댓글 저장 실패 시 댓글 목록 전체를 재조회하지 않고 입력 내용을 유지하며 오류를 표시한다.
- 첨부 업로드 실패 시 본문 저장 성공 여부와 파일 업로드 실패를 분리해 표시한다.
- 댓글 삭제 시 서버 실패하면 로컬 댓글을 제거하지 않는다.

## 검증

- 백엔드 단위/컨트롤러 테스트: 통합 상세 응답, 댓글 페이지 파라미터, NOTICE_COMMENT 첨부 계약.
- 프론트 테스트: 공지 최초 조회 호출 수, 댓글 생성/수정/삭제 부분 갱신, 이전 댓글 조회, 액션 메뉴, 첨부 표시.
- `npm run build`, 관련 Vitest 실행, `mvn test` 또는 최소 `mvn -q -DskipTests compile` 실행.
- 결과 문서는 `docs/result/20260917/notice-crud-comments/`에 기록한다.

## DB 영향

현재 댓글 본문은 `content` TEXT를 사용하므로 본문 저장에는 스키마 변경이 없다. `NOTICE_COMMENT`는 공통 파일의 문자열 소유 타입으로 사용하며, 기존 `owner_type` 길이와 파일 API 계약을 확인한다. 컬럼 변경이 필요해질 경우 날짜별 SQL과 `db-schema.md`를 함께 갱신한다.
