## 내용

- 요청: 그룹웨어 전자결재 이관(작업지시서 `20261022_007` 4단계 '가', 계획 · 사양서 `20261022_008` 3절)
  - 사용자 결정: "로그인을 S_ERP처럼"
- S_ERP 결재 코드는 로그인 `uniqId` 를 `tb_user.user_id` 로 쓴다. 그래서 송연 로그인 계정마다 `tb_user` 줄을 만들었다(적용 시점 계정 2개 → 2줄).
  - `login_id`: 계정 연결
  - `user_nm`: 사원 이름
  - `email_addr`: 사원 이메일(비었거나 겹치면 NULL)
  - `use_at`: 퇴사일이 있으면 N
  - 부서 · 직급은 비웠다(S_ERP DB 도 부서 0건, 직급 비어 있음).
- 이후 새 사원은 인사관리 등록 · 계정 만들기 때 서버가 같은 규칙으로 만들고(`HrDAO.insertUserIfMissing`), 사원을 고치면 이름 · 사용 여부를 맞춘다(`syncUserFromEmployee`).

## 영향 범위

- 로그인 응답(`actionLoginEmployee`)
  - `uniqId` = `tb_user.user_id`. 사번이 필요한 송연 화면 5곳은 `LoginEmployeeResolver` 로 사번을 찾는다.
  - `id` = 계정 `login_code`(사번)
- 바꾸기 전에 받은 로그인 토큰은 다시 로그인해야 그룹웨어가 제대로 동작한다.
