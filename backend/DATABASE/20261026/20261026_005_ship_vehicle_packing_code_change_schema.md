# 20261026_005 출하확정 배차 · 포장방법을 공통코드 코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(공통코드 이름 → 코드) · 백업 표 추가 |
| 대상 표 | `logistics_schedule`(`vehicle`, `packing_method`), `production_schedule`(`ship_vehicle`, `ship_packing_method`), 백업 `bak_20261026_005_ship_vehicle_packing`(새 표) |
| 적용 | 송연 DB 에는 적용하지 않음(바꿀 값 0건). 기록 · 다른 DB 용 스크립트. 트랜잭션 시험 실행은 했다 |
| 롤백 | `20261026_005_rollback.sql` |

## 내용

- 요청: "이 테이블은 vehicle 컬럼도 확인해야겠다"
- 사용자 결정: 배차와 포장방법 모두 코드로
- 바뀐 모양: 칸 이름 · 형식(text)은 그대로, 값이 공통코드 이름 → 코드(`item_code`)
  - 배차: 공통코드 `VEHICLE_INFO`(차량정보)
  - 포장방법: 공통코드 `PACKING_TYPE`
  - 같은 이름이 여럿이면 사용 중 → 정렬순서 → 코드 순으로 하나(서버 저장 규칙과 같다).
- 공통코드에 없는 이름이 있으면 멈춘다. 이미 코드인 값 · 빈 값은 건너뛴다.
- 송연 DB 확인(개수만)
  - 처음 확인 때 `logistics_schedule.vehicle` 1건이 이름이었다. 스크립트를 미리 돌려 볼 때는 이미 코드로 바뀌어 있었다(사용자가 바꾼 것으로 본다).
  - 포장방법 두 칸과 `production_schedule.ship_vehicle` 은 값이 없다.
  - 그래서 적용하면 바뀌는 줄이 0건이라 적용하지 않았다(백업 표도 만들지 않았다).
- 시험 실행: 적용 · 다시 적용 결과가 같았다. 롤백은 코드를 공통코드 이름으로 바꾼다(지금 코드로 된 1건은 이름으로 돌아간다).

## 영향 범위

- 출하확정 · 출하현황 매퍼는 코드로 공통코드 이름을 붙여 읽는다. 예전에 이름으로 적힌 값은 그대로 보인다.
- 출하확정 저장: 화면은 그대로 이름을 보내고, 서버가 코드로 바꿔 남긴다. 비우면 비운다. 공통코드에 없는 이름은 재고를 움직이기 전에 막는다.
  - "공통코드 '차량정보'(VEHICLE_INFO)에 없는 배차입니다"
  - "공통코드 'PACKING_TYPE' 에 없는 포장방법입니다"
- 공통코드 이름을 바꾸면 저장된 줄의 화면 표시도 따라 바뀐다(코드로 이어지므로).
- 롤백하면 이름으로 돌아간다. 서버 코드도 함께 돌려야 한다.
