# 20261026_002 생산확정 거래처를 거래처코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL 18) |
| 유형 | 데이터 변환(거래처명 → 거래처코드) · 컬럼 이름 변경 · 백업 표 추가 |
| 대상 표 | `production_schedule`(`client_name` → `client_code`), 백업 `bak_20261026_002_production_schedule_client`(새 표) |
| 적용 | 2026-10-26 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261026_002_rollback.sql` |

## 내용

- 요청: "client_name 도 client_code로 바꿔줘"(20261026_001 이어서)
- 바뀐 모양
  - 칸 이름 `client_name` → `client_code`(3번째 자리, text 그대로). 바로 뒤가 `product_code` 다.
  - 값: 거래처명 → 거래처마스터(`clients`) 거래처코드(6자리). 같은 이름이 여럿이면 코드가 작은 것(서버 저장 규칙과 같다).
- 거래처마스터에 없는 이름이나 거래처코드가 빈 거래처가 있으면 멈춘다(적용 때 0건).
- 결과(개수만): 5건 모두 이름이 있었고 모두 코드로 바뀌었다. 5건 모두 거래처마스터와 이어진다. 백업 표 5건.

## 영향 범위

- 서버 매퍼 12개 파일: 거래처명은 거래처마스터에서 코드로 붙여 보여 준다(`clientName` 그대로).
  - 거래처 검색(출하현황 · 생산현황 · 판매등록 · 판매현황)도 거래처마스터 이름으로 찾는다.
  - 출하현황 · 판매등록은 생산 쪽 · 출하등록 쪽 검색 조건을 갈래마다 둔다(출하등록 `logistics_schedule` 은 그대로 이름).
- 생산확정 저장: 화면은 그대로 거래처명을 보내고, 서버가 거래처코드로 바꿔 남긴다. 코드 없는 거래처는 '거래처코드가 있는 거래처를 골라주세요' 로 막는다.
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다.
- 롤백하면 `client_name` 으로 돌아간다. 백업과 코드가 같은 줄은 예전 이름, 나머지는 거래처마스터 이름이 들어간다. 서버 코드도 함께 돌려야 한다.
