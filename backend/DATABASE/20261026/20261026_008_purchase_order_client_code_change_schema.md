# 20261026_008 발주 거래처를 거래처코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(거래처명 → 거래처코드) · 컬럼 이름 변경 |
| 대상 표 | `material_purchase_order`(`client_name` → `client_code`) |
| 적용 | 2026-10-26 사용자가 직접 적용. 이 스크립트는 기록 · 다른 DB 용(송연 DB 에 다시 돌리면 건너뛴다) |
| 롤백 | `20261026_008_rollback.sql` |

## 내용

- 요청: "material_purchase_order테이블에서 client_name을 client_code로 변경했어 저장도 코드로 할 수있게 해줘"
- 송연 DB 확인(개수만): 칸 이름이 `client_code`(7번째 자리 그대로)이고, 2건 모두 거래처코드로 바뀌어 거래처마스터와 이어진다.
- 스크립트: 거래처명 → 거래처코드(같은 이름이 여럿이면 코드가 작은 것), 칸 이름 변경. 거래처마스터에 없는 이름이 있으면 멈춘다.
- 확인: 트랜잭션 안에서 적용(이미 바뀌어 건너뜀) → 롤백(이름으로 돌아감, 2건 모두 거래처마스터 이름) → 롤백 다시(같음) → 다시 적용(지금 DB 와 같음) → 되돌림.
- 백업 표는 없다. 사용자가 바꿀 때 예전 이름을 따로 남기지 않아, 롤백은 거래처마스터 이름을 넣는다(예전 글자와 다를 수 있다).

## 영향 범위

- 발주관리 매퍼: 발주내역 · 발주현황은 코드로 거래처마스터 이름을 붙여 보여 준다(`clientName` 그대로, `clientCode` 더함). 거래처 검색도 붙인 이름으로.
- 발주 저장(발주 등록 창 · 수불대장 발주): 화면은 그대로 거래처명을 보내고, 서버가 사용 중인 매입 거래처의 코드로 바꿔 저장한다. 없으면 막는다(20261026 '등록된 거래처 · 품목만' 작업과 같은 기준).
- 입고(`material_receiving`)는 자기 표에 거래처명을 따로 적어서 이번 변경과 상관없다.
- 이 표를 쓰던 서버(8080)는 다시 띄워야 한다.
