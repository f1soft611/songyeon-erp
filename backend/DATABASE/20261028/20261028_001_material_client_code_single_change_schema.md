## 내용

- 요청: "materials 테이블에 client_code 컬럼 배열로 들어가는것도 수정해주고"
- 사용자 결정: 원재료마스터 · 부자재마스터 납품업체는 팝업에서 한 곳만 고른다
- 바뀐 모양
  - 값: 거래처코드 배열 `["000003"]` → 거래처코드 한 곳 `000003`. 빈 배열 `[]` → NULL
  - 칸 이름 · 형식(text) · 자리는 그대로
- 시험 결과(개수만)
  - 66건 중 28건이 한 곳짜리 배열이었고 모두 코드 한 곳이 된다. 28건 모두 거래처마스터와 이어진다.
  - 빈 값 38건은 그대로다. 두 곳 이상 든 배열은 0건이다.
- 두 곳 이상 든 배열이 있으면 멈춘다(어느 곳을 남길지 사람이 정한다).
- 바꾸기 전 값은 `bak_20261028_001_material_client_code` 에 남긴다.

## 영향 범위

- 서버 저장(`MaterialMasterServiceImpl.saveMaterialInfo`)은 거래처코드 한 곳을 넣는다. 두 곳 이상 보내면 "납품업체는 한 곳만 고를 수 있어요"로 막는다.
- 읽는 쿼리(원재료마스터 · 부자재마스터 목록, 수불대장)는 한 곳 · 예전 배열을 모두 읽는다. 그래서 이 스크립트를 서버 배포 전에 돌려도, 배포 후에 돌려도 화면이 깨지지 않는다.
- 화면 · API 모양(`supplierCodes`, `suppliers[]`)은 그대로다(한 칸 배열).
- 예전 서버(이 변경 전 war)는 한 곳 값을 거래처코드로 알아보지 못해 업체명 칸에 코드가 보인다. 그래서 적용 뒤에는 새 war 를 올린다.
- 롤백하면 거래처코드 배열로 돌아간다. 적용 뒤 새로 고친 원재료는 코드 한 곳을 배열로 바꿔 넣는다. 서버 저장 코드도 함께 돌려야 한다.

- 새 서버 코드로 조회 API 를 불러 개수만 봤다.
  - 원재료마스터 `GET /api/v1/co/master/material-master`: 납품업체 있는 줄 28, 모두 거래처코드 · 업체명이 붙음, 두 곳 이상 0
  - 부자재마스터 `GET /api/v1/co/master/sub-material-master`: 납품업체 있는 줄 2, 모두 거래처코드 · 업체명이 붙음
