# 20261020_001 포장유형 자동 코드 번호표 초기화 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-20 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경 (스키마 변경 없음) |
| 대상 표 | `tb_id_sequence` (키 `BOX_TYPE_CODE` · `F001` · `P001`) |
| 적용 | 2026-10-20 적용 완료 (트랜잭션 시험 실행 후 적용) |
| 롤백 | `20261020_001_rollback.sql` (바꾸기 전 값 3 으로) |

## 내용

- 요청: "PACK-001 로 시작할 수 있게 해주고"
- 번호표 마지막 값 3 → 0
  - 포장유형 코드를 비우고 저장하면 `PACK-001` 부터 매긴다.
- 함께 바꾼 서버 규칙(`BoxTypeServiceImpl`, 매퍼 `countAnyCode`)
  - 자동 번호를 뽑을 때 이미 있는 코드는 사용안함 줄까지 건너뛴다.
    - 표 유니크 `uq_box_type`(사업장 · 사업부 · 코드 · 적용시작일)은 사용여부를 보지 않는다.
    - 그래서 같은 날 사용안함으로 둔 코드를 다시 넣으면 걸렸다.
  - 직접 적은 코드가 그 유니크에 걸리면 서버 오류 대신 "이미 쓴 적 있는 포장유형코드입니다(사용안함 포함)" 로 알린다.

## 영향 범위

- 포장유형 화면에서 새로 등록하는 줄의 자동 코드만 달라진다.
- 적용할 때 표에는 `PACK-POUCH` 1줄만 있었다. 그래서 다음 자동 코드는 `PACK-001` 이다.

## 확인

- 한 트랜잭션 안에서 아래를 했다.
  1. 적용(0) → 다시 적용(0)
  2. 롤백 스크립트(되돌림)
  3. ROLLBACK
- ROLLBACK 뒤 원래 값 그대로였다. 그 뒤 적용했다(0).
