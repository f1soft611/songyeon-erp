# 20261020_003 자동 코드: 번호표 대신 '가장 큰 번호 + 1' 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-20 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경(1줄) + 서버 규칙 변경 (스키마 변경 없음) |
| 대상 표 | `tb_warehouse.warehouse_cd` (WH-002 → WH-001) |
| 적용 | 2026-10-20 적용 완료 (트랜잭션 시험 실행 후 적용) |
| 롤백 | `20261020_003_rollback.sql` (WH-001 → WH-002) + 코드 되돌리기 |

## 내용

- 요청: "지금 또 지우고 등록했는데 001 로 안 나오고 002 로 나와. 다시 확인해"
- 원인
  - 자동 코드는 번호표(`tb_id_sequence`)에서 받았다. 번호표는 한 번 쓴 번호를 기억한다.
  - 그래서 줄을 지우고 다시 등록해도 다음 번호(`WH-002`)가 나왔다. `20261020_002` 에서 번호표만 1로 돌린 것으로는 다시 지우면 또 어긋난다.
- 바꾼 서버 규칙(창고등록 · 포장유형 둘 다)
  - 자동 코드 = 표에 있는 자동 코드 가운데 가장 큰 번호 + 1
    - 창고 `WH-숫자`(표 전체, 사용안함 줄 포함)
    - 포장유형 `PACK-숫자`(사업장 · 사업부, 사용안함 줄 포함)
  - 매퍼 `selectMaxAutoCodeNo`(창고 · 포장유형)
  - `WarehouseServiceImpl` · `BoxTypeServiceImpl` 은 번호표를 더 쓰지 않는다.
  - 자료를 다 지우면 다시 `WH-001` · `PACK-001` 부터 나온다.
  - 직접 적은 코드(`WH-WEIGH` 등 숫자가 아닌 것)는 번호에 세지 않는다.
  - 이미 있는 코드면 다음 번호로 넘어간다.
  - 화면의 삭제는 줄을 지우지 않고 사용안함으로 둔다. 그래서 그 번호는 남는다. 표에서 줄을 없애야 그 번호를 다시 쓴다.
- 번호표의 `WAREHOUSE_CODE` · `BOX_TYPE_CODE` 줄은 더 쓰지 않지만 지우지 않았다.
- 데이터: 방금 자동으로 받은 `WH-002` → `WH-001`(가리키는 곳 없음). 다음 자동 코드는 `WH-002`.

## 영향 범위

- 포장유형: 지금 `PACK-003`(사용안함) 1줄이 있어 다음 자동 코드는 `PACK-004` 다.

## 확인

- 한 트랜잭션 안에서 아래를 했다.
  1. 적용 → 다시 적용(같음)
  2. 롤백 스크립트(원래대로)
  3. ROLLBACK
- ROLLBACK 뒤 그대로였다. 그 뒤 적용했다.
- 적용 뒤 창고 자동 번호 최대값 1 → 다음 `WH-002`
