# 20261023_011 프로필 · 도장 이미지를 계정 표로 옮김 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 이관(값 복사) + 백업 표 추가 |
| 대상 표 | `tb_login_account`(profile_image · stamp_image), 백업 `bak_20261023_011_login_images`(새 표), 읽기만 `employees` |
| 적용 | 2026-10-23 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261023_011_rollback.sql` |

## 내용

- 증상: 전자결재에서 승인했는데 결재선에 도장이 안 보였다. 내 정보 관리에는 도장이 등록돼 있었다.
- 원인
  - 송연 내 정보 관리는 프로필 · 도장 이미지를 `employees.profile_image` · `stamp_image` 에 저장했다.
  - 전자결재 결재선 · 기안자, 공지, 댓글, 기안양식 사용자 목록(S_ERP 그대로 옮긴 쿼리)은 `tb_login_account` 의 이미지를 읽는다.
  - 두 곳이 달라서, 계정 표에는 이미지가 하나도 없었다.
- 정한 것: S_ERP 와 같이 이미지는 계정 표(`tb_login_account`)에 둔다.
  - 서버의 내 정보 저장 · 조회와 로그인 쿼리도 계정 표를 쓰게 같이 바꿨다(`EgovLoginUsr_SQL_postgresql.xml`).
- 이 스크립트
  - `employees` 에 있는 이미지(프로필 1건 · 도장 1건)를 같은 사번 계정(`login_code = employees.id`)으로 복사했다.
  - 계정에 이미 이미지가 있으면 덮어쓰지 않는다.
  - 바꾸기 전 계정 값은 `bak_20261023_011_login_images` 에 남겼다(롤백용).
  - `employees` 의 이미지 칸은 지우지 않았다. 서버는 더는 읽고 쓰지 않는다.

## 영향 범위

- 결재선 도장(승인 단계 · 승인/반려/반송한 칸), 결재 · 공지 · 댓글 · 기안양식 사용자 목록의 사진이 나온다.
- 내 정보 관리에서 이미지를 바꾸면 계정 표가 바뀐다.
- 롤백하면 계정 이미지가 처음 값(비어 있음)으로 돌아간다. 서버 쿼리도 함께 돌려야 한다.
