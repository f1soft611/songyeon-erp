# 20261023_013 제품 거래처를 거래처코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 컬럼 삭제 · 데이터 변환(이름 → 코드) · 컬럼 이름 변경 |
| 대상 표 | `products`(`client_code` 삭제, `client_name` → `client_code`) |
| 적용 | 2026-10-23 **사용자가 직접 적용**. 이 스크립트는 기록 · 다른 DB 재현용이다(이미 바뀐 DB 에서는 건너뛴다) |
| 롤백 | `20261023_013_rollback.sql` |

## 내용

- 요청: "client_code 컬럼 지우고 client_name 컬럼을 _code로 바꿔줘 그리고 저장될때 거래처명이 아니라 코드가 저장되게 해주고"
  - 처음 요청은 손으로 더한 `client_code`(맨 끝 칸)를 `client_name` 앞으로 옮기는 것이었다. PostgreSQL 은 칸 순서를 바꾸지 못해 이 방법으로 바꿨다.
- 바뀐 모양
  - 맨 끝에 있던 `client_code`(사용자가 손으로 더한 칸, 기록 없음)가 없어졌다. 값은 거래처마스터 코드와 같았다.
  - `client_name`(5번째)의 거래처명이 `clients.client_code`(6자리)로 바뀌었고, 칸 이름이 `client_code` 가 됐다. 형식은 `text` 그대로다.
- 적용 경과
  - 제가 스크립트를 시험 실행(되돌림)하는 사이에 사용자가 DB 에 직접 같은 변경을 했다. 제 스크립트는 적용하지 않았다(백업 표도 없다).
  - 지금 DB 자료 해시는 이 스크립트를 시험 실행했을 때의 결과와 같다.
- 확인(개수만)
  - 바꾸기 전: 제품 6건의 거래처명이 모두 거래처마스터와 1:1로 맞았다. 손으로 넣은 `client_code` 6건도 거래처마스터 코드와 같았다.
  - 지금: 6건의 `client_code` 가 모두 거래처마스터에 있다.
- 롤백(트랜잭션 안에서 확인 후 되돌림)
  - 거래처마스터에서 코드로 이름을 찾아 `client_name` 으로 돌리고, 맨 끝 `client_code` 를 다시 만든다.
  - 돌린 자료가 바꾸기 전 해시와 같았다. 다시 적용하면 지금 상태와 같았다.
  - 거래처마스터에서 이름을 바꾼 뒤 롤백하면 바뀐 이름이 들어간다.

## 영향 범위(서버, 같은 날 함께 고침)

- 제품에 거래처를 저장하는 곳(제품등록 · 제품마스터 창)은 거래처 이름을 받아 코드로 저장한다.
- 제품을 읽는 곳은 거래처마스터에서 이름을 붙여 `clientName` 으로 돌려준다.
  - 제품마스터 · 거래처별 제품조회 · 수주 제품 후보 · 제품재고(거래처 검색 포함)
- 수주 · 생산계획 · 출하 · 매출 등 다른 표의 `client_name`(거래처명 글자)은 바꾸지 않았다.
