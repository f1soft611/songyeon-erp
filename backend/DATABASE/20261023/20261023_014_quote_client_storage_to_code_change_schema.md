# 20261023_014 견적 거래처 · 보관방법을 코드로 저장 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(이름 → 코드) · 컬럼 이름 변경 |
| 대상 표 | `quotes`(`client_name` → `client_code`, `storage` 이름 → 코드) |
| 적용 | 2026-10-23 **사용자가 직접 적용**. 이 스크립트는 기록 · 다른 DB 재현용이다(이미 바뀐 DB 에서는 아무것도 하지 않는다) |
| 롤백 | `20261023_014_rollback.sql` |

## 내용

- 요청: "견적도 코드값으로 변환할게"
  - 사용자 답: "변경직접 작업 했고 보관방법도 코드값으로 변경했으니까 확인해줘"
- 바뀐 모양(확인, 개수만)
  - `client_name`(6번째)이 `client_code`(text)가 됐다. 1건이 거래처마스터에 있는 코드다.
  - `storage` 1건이 공통코드 STORAGE_METHOD 코드(`003`)다.
  - 맨 끝 `product_code`(text, 비어 있음) 칸이 있다. 이 변경과 따로이고 서버가 쓰지 않는다. 손대지 않았다.
- 스크립트 확인(트랜잭션 안에서, 끝나고 되돌림)
  - 롤백하면 `client_name` 으로 돌아가고, 값이 이름(거래처 · 보관방법)이 된다.
  - 다시 적용하면 지금 상태와 같다. 두 번 적용해도 같다.
  - 끝난 뒤 DB 는 처음 그대로다.
- 롤백은 백업 표 없이 거래처마스터 · 공통코드에서 이름을 찾는다. 그 사이 이름을 바꿨다면 바뀐 이름이 들어간다.

## 영향 범위(서버 · 화면, 같은 날 함께 고침)

- 견적 저장(작성 · 수정)은 `clientCode` · 보관방법 코드를 받아 그대로 저장한다(사용 중 거래처 · 공통코드만).
- 견적 조회는 `clientCode` · `clientName`(거래처마스터 이름) · `storage` · `storageNm` 을 돌려준다.
- 레시피 → 견적(`EgovRecipeShare.insertQuote`)은 레시피의 거래처 이름으로 거래처코드를 찾아 넣는다(없으면 비움).
