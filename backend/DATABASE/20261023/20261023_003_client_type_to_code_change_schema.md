# 20261023_003 거래처 분류를 공통코드 값으로 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경(스키마 변경 없음) |
| 대상 표 | `clients`(`client_type`) |
| 참조 | 공통코드 `CUSTOMER_CATEGORY`(SONGYEON, 사용자가 만든 것): 001 매입거래처 · 002 매출거래처 · 003 매입+매출 거래처 |
| 적용 | 2026-10-23 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261023_003_rollback.sql` |

## 내용

- 요청: "지금 화면의 분류를 다 코드값으로 바꿔줘 … 테이블에 저장은 코드로"(계획 · 사양서 `docs/plan/20261023/20261023_006_거래처분류코드_사용중거래처만선택_계획사양서.md`)
- `clients.client_type` 의 예전 글자를 코드로 바꿨다.
  - 매입 → 001(13건)
  - 매출 → 002(5건)
  - 매입+매출 → 003(1건)
- 스크립트는 먼저 공통코드에 001 · 002 · 003 이 다 있는지 보고, 없으면 멈춘다.

## 영향 범위

- 거래처마스터
  - 목록 · 창 · 조회 조건은 공통코드와 이어 이름으로 보여 준다. 저장은 코드다.
  - 엑셀 올리기는 이름 · 코드 · 예전 글자를 받아 코드로 바꾼다.
- 분류로 거르던 쿼리(`LIKE '%매입%'` · `'%매출%'`)는 공통코드 이름으로 거르게 바꿨다. 같은 날 코드와 함께 바꿨다.
  - 원재료 · 부자재 납품업체
  - 수주 거래처 · 수주 저장 검사
  - 매출 · 매입관리 매입처
- 시험 실행으로 확인한 것
  - 바꾸기 전 글자 거르기와 바꾼 뒤 코드 + 이름 거르기의 거래처 수가 같다(매입처 14 · 매출처 6).
  - 모든 거래처에 분류 이름이 붙는다.
- 이 DB 를 쓰는 다른 프로그램(예전 송연 파이썬)이 분류 글자를 직접 본다면 그쪽도 코드로 맞춰야 한다.
