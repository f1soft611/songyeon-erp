# 20261023_006 부자재 분류를 공통코드 값으로 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경(스키마 변경 없음) |
| 대상 표 | `materials`(`sub_category`) |
| 참조 | 공통코드 `SUB_MATERIAL_CATEGORY`(SONGYEON, 사용자가 만든 것): 001 필름 · 002 파우치 · 003 박스(이름에 설명이 붙어 있음, 예: '필름 — M로 입고 · 생산입고 때 빠짐') |
| 적용 | 2026-10-23 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261023_006_rollback.sql` |

## 내용

- 요청: "그것도 공통코드에서 SUB_MATERIAL_CATEGORY 로 수정해줘"
  - 사용자 결정: "코드로 저장(거래처와 같게)"
- `materials.sub_category` 의 글자를 코드로 바꿨다.
  - 파우치 → 002(2건)
  - 박스 → 003(1건)
  - 필름은 0건이었다.
  - 원재료(빈 값) 50건은 그대로다.
- 스크립트는 먼저 공통코드에 001 · 002 · 003 이 다 있는지 보고, 없으면 멈춘다.

## 영향 범위

- 분류 이름은 공통코드 이름의 ' — ' 앞부분이다(예: 필름). 서버는 `sub_category_nm` 으로, 화면은 `subCategoryShortName` 으로 같은 규칙을 쓴다.
- 분류를 읽는 쿼리는 모두 이름(`sub_category_nm`)을 함께 준다.
  - 제품마스터 원재료 고르기
  - 원재료 · 부자재마스터
  - 수불대장 · 재고현황
- 제품 창 부자재 칸 검사(필름 · 파우치 · 박스로 등록된 것만)는 이름으로 견준다.
- 부자재 저장은 공통코드 사용 중 코드만 받는다.
- 생산입고 · 출하확정의 필름 · 파우치 · 박스 차감은 제품에 적힌 부자재 코드로 하므로 분류 값과 무관하다.
- 이 DB 를 쓰는 다른 프로그램(예전 송연 파이썬)이 `sub_category` 글자를 직접 본다면 그쪽도 코드로 맞춰야 한다.
