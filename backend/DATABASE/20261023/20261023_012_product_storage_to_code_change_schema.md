# 20261023_012 제품 보관방법을 공통코드(STORAGE_METHOD) 코드로 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변환(이름 → 코드) + 백업 표 추가 + 컬럼 설명 |
| 대상 표 | `products.storage`, 백업 `bak_20261023_012_product_storage`(새 표) |
| 적용 | 2026-10-23 적용 완료 (트랜잭션 시험 실행: 다시 적용해도 같음, 롤백하면 처음과 같음 확인 후 적용) |
| 롤백 | `20261023_012_rollback.sql` |
| 같은 번호 추가 스크립트 | `20261023_012_backfill_backup.sql`(롤백용 백업 채우기, 아래 참고) |

## 내용

- 요청: "제품등록 화면에서 보관방법을 공통코드 STORAGE_METHOD 로 적용시켜줘". 저장 방식은 사용자 결정 "코드로 저장".
- 공통코드(SONGYEON): 001 실온(1℃~35℃) · 002 냉장(0℃~10℃) · 003 냉동(-18℃이하)
- `products.storage` 의 이름 글자를 코드로 바꾼다. 공통코드 이름과 똑같은 글자만 바꾸고, 맞지 않는 글자 · 빈 값은 그대로 둔다.
- 결과: 6건 모두 코드가 됐다(001 3 · 002 1 · 003 2).
- 견적(`quotes.storage`)과 라벨 표(`label_requests` · `product_label_versions`)의 보관방법은 바꾸지 않았다(인쇄 글자 · 견적 기록).

## 적용 때 있었던 일(백업 채우기)

- 시험 실행(되돌림) 때는 6건이 이름이었다(해시 `e559…`).
- 적용하기 직전에 다시 보니 6건이 이미 코드로 바뀌어 있었다. 이 스크립트 밖에서 바뀐 것이다(백업 표 · 컬럼 설명은 없었다).
- 그래서 이 스크립트의 백업이 0건이 되어, 롤백이 이름으로 돌리지 못하는 상태였다.
- `20261023_012_backfill_backup.sql` 로 백업을 공통코드 이름으로 채웠다.
  - 채우기 전 확인: 지금 코드를 이름으로 바꾼 값의 해시가 시험 실행 때 원래 값의 해시(`e559…`)와 같았다.
  - 채운 뒤 롤백 스크립트를 트랜잭션 안에서 돌리면 원래 해시와 같았다(되돌림).

## 영향 범위

- 제품등록 · 제품마스터 창은 코드로 저장한다(서버가 공통코드 사용 중 코드만 받는다).
- 제품마스터 · 거래처별 제품조회 목록은 `storage`(코드)와 `storageNm`(이름)을 돌려준다.
- 출하확정 · 출하현황 · 라벨(예전 방식 `selectProductLabel`)은 `storage` 를 이름으로 돌려준다.
- 라벨 버전 확정(`copyVersionToProducts`)은 라벨 글자에 실온 · 냉장 · 냉동이 들어 있으면 그 코드를, 없으면 제품 값을 그대로 둔다.
- 롤백하면 6건이 이름으로 돌아간다. 적용 뒤 새로 등록 · 수정한 제품은 백업에 없어 코드로 남는다. 서버 · 화면 코드도 함께 돌려야 한다.
