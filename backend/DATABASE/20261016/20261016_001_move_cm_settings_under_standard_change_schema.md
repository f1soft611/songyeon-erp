# 20261016_001 공통관리 > 기준정보 분류 추가, 기초정보를 그 아래로 옮김 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-16 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경 (스키마 변경 없음) |
| 대상 표 | `tb_menu` (SONGYEON 테넌트, 공통관리 모듈 `CM`) |
| 적용 | 2026-10-16 적용 완료 (트랜잭션 시험 실행 후 적용) |
| 롤백 | `20261016_001_rollback.sql` |

## 내용

- S_ERP 처럼 공통관리 메뉴를 분류 아래 화면 구조로 바꿨다.
  - 전: 공통관리 > 기초정보(화면)
  - 후: 공통관리[모듈] > 기준정보[분류] > 기초정보[화면]
- 추가: 분류 `standard` '기준정보', 주소 `/cm/standard`, 순서 1
  - 환경설정의 '시스템 관리'(`ST_SYSTEM`)와 같은 모양이다. 주소는 있고, 권한 행은 두지 않는다(자식 화면이 보이면 분류도 보인다).
- 변경: 기초정보(`settings`)
  - 부모를 '기준정보' 로
  - 주소 `/cm/settings` → `/cm/standard/settings` (환경설정의 `/settings/system/...` 과 같은 규칙)
  - 순서 1 → 10
- 그대로 둔 것
  - 기초정보의 `menu_id` · 이름 · 설명 · 권한 행(`tb_menu_permission` 5행)
  - 생산스케줄 · 물류스케줄(공통관리 바로 아래, 순서 2 · 3)

## 영향 범위

- 메뉴판: 공통관리에서 '기준정보' 를 펼치면 '기초정보' 가 나온다.
- 경로 줄: 공통관리 > 기준정보 > 기초정보
- 화면 연결: 화면 키는 주소의 마지막 칸(`settings`)이라 바뀌지 않는다.
- 옛 주소 `/cm/settings` 는 메뉴에 없는 주소라 '페이지를 찾을 수 없습니다' 가 된다.
  - 코드 안의 링크 두 곳(세금계산서 · 온도모니터링의 서버관리 안내)은 새 주소로 바꿨다.
  - 브라우저 즐겨찾기나 '최근 사용' 에 남은 옛 주소는 새로 눌러 들어가면 된다.
- 권한: 바뀌지 않는다.

## 주의

- `tb_menu.parent_menu_id` 는 `ON DELETE CASCADE` 다. 분류를 지우면 기초정보와 그 권한 행도 같이 지워진다.
- 그래서 롤백은 기초정보를 먼저 원래 자리로 떼어낸 뒤, 자식이 없을 때만 분류를 지운다.

## 확인

- 한 트랜잭션 안에서 적용 → 확인 → 다시 적용(같은 결과) → 롤백 스크립트(원래대로) → ROLLBACK 을 했다.
- ROLLBACK 후 `tb_menu` · `tb_menu_permission` · `tb_role_menu_permission` 전체가 시험 전과 같았다.
- 그 뒤 적용했다. 적용 후 공통관리: 기준정보 #1 · 생산스케줄 #2 · 물류스케줄 #3 · 기준정보 > 기초정보 #10
