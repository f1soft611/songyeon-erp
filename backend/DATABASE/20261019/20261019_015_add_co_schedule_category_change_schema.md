# 20261019_015 공통관리 > 스케줄관리 분류 추가 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-19 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경 (스키마 변경 없음) |
| 대상 표 | `tb_menu` (SONGYEON 테넌트) |
| 적용 | 2026-10-19 적용 완료 (트랜잭션 시험 실행 후 적용) |
| 롤백 | `20261019_015_rollback.sql` |

## 내용

- 요청: "생산스케줄 · 물류스케줄 둘은 뭐로 묶어야 할까? 스케줄관리?" → "co/schedule 로 스케쥴관리라는 분류 만들고 그 밑으로 화면 두 개 넣어줘"
  - 이름은 화면 이름(생산스케줄 · 물류스케줄)에 맞춰 '스케줄관리'로 적었다.
- 분류: `schedule` '스케줄관리' `/co/schedule`, 순서 2(기초정보 1 다음), 권한 행 없음(기초정보 분류와 같음)
- 옮긴 화면(메뉴 번호 · 권한 행은 그대로)

| 화면 | 주소 | 순서 |
|---|---|---|
| 생산스케줄 (`production`) | `/co/production` → `/co/schedule/production` | 2 → 10 |
| 물류스케줄 (`logistics`) | `/co/logistics` → `/co/schedule/logistics` | 3 → 20 |

## 영향 범위

- 메뉴판: 공통관리 ▾ 기초정보 · 스케줄관리(생산스케줄 · 물류스케줄)
- 화면 키(주소 마지막 칸)는 그대로라 화면 코드는 바꾸지 않았다.
- 옛 주소를 즐겨찾기 해 둔 경우에는 새 주소로 들어가야 한다.
- 롤백은 화면을 먼저 밖으로 뺀 뒤 분류를 지운다. 하위 메뉴는 parent FK `ON DELETE CASCADE` 라 순서를 바꾸면 화면 메뉴도 지워진다(014 참고).

## 확인

- 한 트랜잭션 안에서 아래를 했다.
  1. 적용 → 다시 적용(같음)
  2. 롤백 스크립트(원래대로)
  3. ROLLBACK
- ROLLBACK 뒤 DB 는 그대로였다. 그 뒤 적용했다.
- 화면(Edge, 조회만)
  - `/co/schedule/production` · `/co/schedule/logistics` 가 열린다.
  - 경로 표시: 공통관리 > 스케줄관리 > 생산스케줄
