# 20261019_005 창고마스터 tb_warehouse 새 모양 기록 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-19 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 스키마 기록 (표는 테이블 설계자가 DB 에 직접 만듦, 이 작업에서 바꾼 표 정의 없음) |
| 대상 | `tb_warehouse` (번호표 `tb_id_sequence` 키 `WAREHOUSE_CODE` 를 새로 씀) |
| 적용 | 표는 이미 DB 에 있다. 기록 파일은 다시 돌려도 아무것도 바꾸지 않는다(`IF NOT EXISTS`) |
| 롤백 | `20261019_005_rollback.sql` (번호표 줄만 지움. 표 삭제는 설계자 판단, 주석으로만 둠) |

## 내용

- 요청: "테이블도 tb_warehouse 로 변경됐어"
- 창고등록(공통관리 > 기초정보 > 창고등록, 화면ID BSWarehouseView)이 옛 송연 `warehouses` 대신 이 표를 쓴다.
- 이 표는 `20260909_001` 의 옛 S_ERP 모양(`tenant_id` · `use_at` · `created_by` …)을 설계자가 새 모양으로 바꾼 것이다.
  - 칸 36개
    - 사업장 · 사업부, 창고코드(표 전체에서 하나) · 창고명, 상위창고코드, 창고유형 · 창고구분 · 온도대
    - 온도 · 습도 범위, Y/N 표시 7개, 거래처 · 담당자 · 주소 · 면적, 정렬순서, 비고, 사용여부, 감사 칸 4개
  - CHECK
    - 유형 8가지, 구분 2가지, 온도대 5가지, Y/N
    - 범위(상한 ≥ 하한)
    - 보류와 가용재고를 함께 Y 로 둘 수 없음
    - 외부 창고는 거래처 필수, 냉장 · 냉동은 온도 범위 필수
  - 기본창고는 사업장 · 사업부 · 유형마다 사용 중인 것 한 곳(`ux_wh_default`)
  - `tb_warehouse_location` 이 이 표를 참조한다(`fk_wh_loc_wh`).
  - 트리거는 없다. 수정일시는 서비스가 `NOW()` 로 넣는다.
- 자료
  - 설계자가 넣은 10줄(모두 F001/P001, 사용 중)
    - 유형: 원자재 3, 완제품 2, 부자재 · 재공 · 반품 · 보류 · 폐기 1
    - 기본창고 7곳 가운데 원자재 1곳
  - 이 기록에는 자료를 넣지 않았다.
  - 옛 `warehouses` 6줄은 옮기지 않았다(사용자 결정). 옛 표는 지우지 않았고, 이제 읽는 코드가 없다.

## 운영 규칙 (2026-10-19 사용자 결정)

- 사업장 `F001` · 사업부 `P001` 고정. 목록 · 이름 중복 검사는 사용 중(`use_yn = 'Y'`)인 줄만 본다.
- 창고코드는 화면에서 받지 않는다. 새로 등록할 때 서버가 `WH001` … 로 매긴다.
  - 번호표: `tb_id_sequence`, 키 `WAREHOUSE_CODE` · `F001` · `P001`
  - 이미 있는 코드면 다음 번호로 넘어간다.
- 입고창고 = 사용 중인 원자재 기본창고(`warehouse_type = '원자재' AND default_yn = 'Y'`)
  - 들여온 원재료가 들어가는 창고다. 입고 · 재고조정 · 재고 현황도 이렇게 읽는다.
- 기본창고를 켜면 같은 유형의 다른 기본창고를 끈다.
  - 마지막 원자재 기본창고는 끄거나, 유형을 바꾸거나, 지울 수 없다.
- 원재료 · 재고 · 입고 표는 창고를 이름으로 들고 있다. 그래서:
  - 창고명은 사용 중인 줄 가운데 하나뿐이어야 한다.
  - 이름을 바꾸면 쓰던 곳도 같이 바꾼다.
  - 쓰는 곳이 있으면 지울 수 없다.
- 삭제는 지우지 않고 `use_yn = 'N'` · `default_yn = 'N'` 으로 둔다.
- 화면에서 받지 않는 칸(구분 · 온도대 · 온습도 · Y/N 표시 · 거래처 · 주소 등)은 표 기본값을 쓴다.

## 영향 범위

- 창고등록 화면 · API `/api/v1/co/master/warehouse` (매퍼 `Warehouse_SQL_postgresql.xml`)
- 창고 목록 · 입고창고를 읽는 곳(매퍼만 바꿈, 화면 그대로)

  - 재고조정 `EgovStockAdjust_SQL_postgresql.xml`
  - 재고 현황 `EgovMaterialStockSnapshot_SQL_postgresql.xml`
- 남은 일: 옛 S_ERP 창고관리 코드(`system/warehouses`)는 옛 칸(`tenant_id` · `use_at`)을 읽어 이 표와 맞지 않는다.
  - 메뉴는 `20261002_004` 에서 이미 뺐다(화면으로는 열 수 없음).
  - 이번에는 건드리지 않았다.

## 확인

- DB 카탈로그로 칸 · 제약 · 인덱스 · 설명을 읽었다.
- 한 트랜잭션 안에서 기록 파일을 지금 DB 에 적용 → 다시 적용(바뀐 것 없음) → 롤백 스크립트(번호표 줄만 지움, 표는 남음) → ROLLBACK 을 했다.
- 다른 트랜잭션에서 임시 스키마에 기록 파일로 표를 새로 만들어 지금 표와 비교했다.
  - 칸 · 기본값 · 설명 · 제약 · 인덱스가 같았다(스키마 이름만 다름).
  - 그 뒤 ROLLBACK 했다.
- 시험 뒤 DB 는 시험 전과 같았다.
