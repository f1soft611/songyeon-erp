# 20261021_001 송연 직원 계정 · 역할(권한관리 적용) 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-21 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 데이터 변경 + 서버 규칙 변경 (스키마 변경 없음) |
| 대상 표 | `tb_login_account`, `tb_login_account_role`, `tb_role_menu_permission`(ADMIN), 백업 표 `bak_20261021_001_admin_role_menu_permission` |

| 롤백 | `20261021_001_rollback.sql` + 코드 되돌리기 |

## 내용

- 요청: "S_ERP 랑 동일하게 권한관리 들어갈 거고 … 따로 테이블을 새로 만들고 싶지는 않고 최대한 S_ERP 랑 동일한 구조로"
- 송연 직원 한 명 = S_ERP 계정 한 개
  - `tb_login_account.login_code` = 사번(`employees.id`). 비밀번호 해시는 계정 표에서 확인한다.
  - 이름 · 부서 · 퇴사일은 `employees` 에서 읽는다. `tb_user` 는 쓰지 않는다.
- 데이터
  - 계정 있는 직원(`username` · `password_hash` 있음)마다 계정 한 줄. 지금은 1명(`0000`)이다.
  - 역할 연결: `is_admin` = 1 → ADMIN(시스템 관리자), 그 밖 → DEFAULT_USER(일반 사용자)
  - ADMIN 에 SONGYEON 메뉴 권한 정의(`tb_menu_permission`)를 전부 준다(지금과 같은 메뉴 · 단추).
- 서버 규칙(코드)
  - 로그인: 계정 표에서 사번으로 찾고 역할을 읽는다. 역할이 없으면 로그인은 되지만 메뉴가 없다.
  - 역할이 없으면 관리자 API 도 쓸 수 없다(`isTenantAdmin` 송연 예외 삭제).
  - 인사관리 계정 발급: 계정 표에 한 줄을 만들고, 처음 만들 때 DEFAULT_USER 를 붙인다. 계정을 거두면 계정 줄 · 역할 연결을 지운다.
  - 비밀번호 변경(인사관리 · 내 정보)은 `employees.password_hash` 와 계정 표를 같은 값으로 바꾼다.

## 영향 범위

- 로그인, 내 메뉴, 환경설정 관리자 API, 권한관리 사용자 매핑, 인사관리 계정, 내 정보 비밀번호
- 역할을 바꾸면 다음 로그인부터 적용된다(토큰에 역할이 들어감).
- 앞으로 메뉴를 더하는 SQL 은 ADMIN 역할 메뉴 권한 줄도 함께 넣어야 관리자에게 보인다.
