# 20261105_001 화면검수 관리 메뉴 추가 변경 이력

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-05 |
| 대상 DB | songyeon (PostgreSQL) |
| 유형 | 메뉴 데이터 추가(화면 1행, 권한 행 복사). 테이블 · 칸 변경 없음 |
| 대상 표 | `tb_menu`(추가 1행), `tb_menu_permission` · `tb_role_menu_permission`(새 화면 행 추가) |
| 적용 | 2026-11-05 적용 완료(트랜잭션 시험 실행 통과: 새 메뉴 권한 = 메뉴관리 권한, 다른 메뉴 그대로, 다시 적용해도 같음, 롤백하면 처음과 같음) |
| 롤백 | `20261105_001_rollback.sql` |

## 내용

- 요청: 화면 이미지 '프로젝트 화면검수 관리' — "환경설정에 메뉴관리 밑에 만들거고".
- 설계: [20261105_001_화면검수관리_설계서.md](../../spec/20261105/20261105_001_화면검수관리_설계서.md)

| 순서 | 화면ID · 주소 | 이름 | 바뀐 것 |
|---|---|---|---|
| 35 | `ST_SCREEN_REVIEWS` · `/settings/system/screen-reviews` | 화면검수 관리 | 새 행(`메뉴 · 화면별 검수 상태를 한 번에 확인해요`), 부모 `ST_SYSTEM`(시스템 관리) |

- 권한은 메뉴관리(`ST_MENUS`)의 메뉴 권한 · 역할 권한을 그대로 복사했다. 메뉴관리를 보는 사람이 같은 권한으로 본다.
- 기존 메뉴 · 권한 행은 바뀌지 않는다(메뉴관리 30, F1 Grid 테스트 40 그대로).

## 같이 바뀐 코드

- 화면: `frontend/src/pages/settings/system/screen-reviews`, `DashboardContent`(`screen-reviews`).
- 서버: `GET /api/v1/system/screen-reviews`(화면검수 컨트롤러에 목록 추가).

## 영향 범위

- 스크립트만 적용하면 메뉴는 보이지만 예전 프론트에서는 빈 화면이 열린다. 프론트 · 서버와 함께 올린다.
- 프론트만 올리면 메뉴가 없어 화면에 들어갈 수 없다(다른 화면 영향 없음).
- 롤백하면 메뉴를 지운다(권한 행은 FK CASCADE, 이 화면의 화면검수 기록은 먼저 지움).
